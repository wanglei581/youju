# 全国覆盖清单说明（数据覆盖第一阶段，2026-11-05）

目标：有据收录**国家、省、市、县四级**所有和企业政策有关的政府部门发布的文件（创始人 11/5："要做就做好，不要做一半"）。这个目录是第一阶段的成果：从官方导航自动生成的全国清单、集约化平台盘点、两个试点省的接入结果和覆盖看板设计。

## 文件

| 文件 | 内容 | 怎么来的 |
|---|---|---|
| `行政区划.csv` | 31 省、333 地级、2847 县级行政区（应接入的分母） | 民政部国家地名信息库公开接口，`youju coverage-divisions` |
| `门户网站/<省>.csv` | 每个行政区一行：门户网址、**在哪个官方页面上找到的**（导航来源页、导航文字）、状态和原因、网站标识码、平台特征 | `youju coverage-inventory` |
| `部门栏目/<省>.csv` | 每个"行政区 × 目标部门"一行：部门全称、部门网址（独立网站 / 门户频道 / 门户本身）、导航来源页、通知公告 / 政策文件 / 公示公告三类栏目的名称和网址、平台特征 | 同上 |
| `栏目清单/<省>.csv` | 试点省每个栏目一行，**前 14 列和 `全国来源清单_P0_v1.csv` 完全相同**，可以直接 `youju import-sources`；后 6 列是追溯信息 | `youju coverage-verify`（用正式抓取程序的列表识别试读一遍） |
| `栏目抽样试读/<省>.csv` | 每省每级抽 8 个栏目试读，平台盘点用 | `youju coverage-verify --sample-per-level 8` |
| `集约化平台盘点_数据.md` | 每省平台分布、可读比例、防护情况（程序生成） | `youju coverage-survey` |

| `覆盖看板设计.md` | 看板的数据模型、状态规则、后台页面 | — |
| `第二阶段计划.md` | 全国铺开的分批计划和时间表 | — |

## 和全国来源清单的列对应

`栏目清单/<省>.csv` 前 14 列 = `全国来源清单_P0_v1.csv` 的 12 列，加上地市清单已有的"城市""区县"：

| 列 | 写法 |
|---|---|
| 层级 | 国家级 / 省级 / 市级 / 区县级 |
| 省份、城市、区县 | 和 sources 表一致：省份简称；地级市去掉"市"、自治州等写全称；直辖市的区县城市填直辖市简称；省直辖县级单位（仙桃、文昌、石河子等）城市填它自己的简称 |
| 部门 | 政府办、发改委、工信、科技、商务、财政、人社、市场监管、农业农村、文旅、生态环境、数据局、开发区 |
| 验证状态 | 开头的词决定导入后的抓取方式，**新来源一律不启用**：`试跑可读`（static，不启用）、`需浏览器渲染或接口`（browser）、`已访问…需人工确认`（manual）、`网站防护拦截…不绕过` / `robots 禁止抓取`（blocked）、`本机无法访问`（manual） |
| 页面日期数、最新日期样例 | 试读时识别出的带日期条目数、最新一条的日期 |
| 后 6 列 | 栏目类型、网站URL、导航来源页、栏目来源页、平台、区划代码 |

`部门栏目/<省>.csv` 是宽表（一行一个部门，三类栏目各占两列），给人看和做看板用；导入用 `栏目清单`。

## 怎么生成（可重跑）

在 `backend/` 下：

```bash
uv run youju coverage-divisions
```

```bash
uv run youju coverage-inventory --log
```

```bash
uv run youju coverage-verify --state ~/.cache/youju-coverage/state-全国.json --province 浙江 --province 山西
```

```bash
uv run youju coverage-survey --state ~/.cache/youju-coverage/state-全国.json --checks ~/.cache/youju-coverage/checks-抽样-全国.json
```

- 页面缓存在 `~/.cache/youju-coverage`（成功的页面 14 天、失败的 2 天内不重抓），重跑同一天的命令几乎不联网；`--offline` 只用缓存。
- 全国走一遍约 2–3 小时（同一网站两次请求至少间隔 3 秒，不同网站并行，每省同时最多 6 个行政区）。

## 怎么找的（每一步都在官方页面上）

1. 中国政府网"地方政府网站"导航页 → 31 个省级门户；"国务院部门网站"导航页 → 部委。
2. 每个门户：首页、首页上的导航页（"市县政府网站""部门网站""网站导航""政府机构""政府信息公开"等）、拼页脚的本站脚本、**政府网站年度报表目录**（国办要求每个政府网站每年发布年报，门户的年报目录就是本地政府网站的官方名录；年报里有"首页网址"，PDF 版也读）。
3. 下级政府门户：在上面这些页面里按国家地名信息库的名称（全称、简称、"恩施州"这类写法）认，同名的不认。
4. 部门：按机构名称认 13 类目标部门，县级合并部门同时算几类；别处的部门（上级、兄弟地区）按名称前缀排除。
5. 栏目：部门页面上按链接文字认通知公告、政策文件/规范性文件、公示公告（标题旁边"更多"的也认），没有就沿"信息公开"再进一层；只认本网站上的栏目。
6. 每个页面记平台特征：网站标识码（meta SiteIDCode）、页脚"技术支持"、平台标记、文章网址形状。

找不到的不猜：导航里没有就记"导航未找到"，打不开记原因，防护拦截、验证码、要登录、robots 禁止记"不能抓"，都不绕过。

## 规矩

- 只访问公开页面；遵守 robots.txt；同一网站两次请求至少间隔 3 秒；透明标识（YoujuBot）；不换标识、不绕过任何防护。
- 不写生产数据库、不部署、不在线上启用新来源。试点只在本机测试库里抓一轮。
- 清单里的网址都来自官方导航；人工补的导航入口（如果有）也必须是官方页面，并在文件里写明。
