# 覆盖看板设计（数据覆盖第一阶段，2026-11-05）

目的：回答一个问题——**有据现在覆盖了哪些政府部门、还差哪些、差在哪儿**。按国家、省、市、县四级，每一级都能逐格查到"这个地方的这个部门收没收、为什么没收、上次成功是什么时候"，按级验收。

第一阶段只做设计和离线统计（`youju coverage-board`，读本机数据库）；数据表、后台页面在第二阶段第 1 周开发（要一个迁移号，向协调会话申请，不自己占号）。

## 一、统计单位：格

**一格 = 一个行政区 × 一个目标部门。**

- 行政区：国家（1）+ 31 省 + 333 地级 + 2847 县级（国家地名信息库 2026-11-05 版，见 `行政区划.csv`）。
- 目标部门（各级相同）：
  - **标准部门 11 个，每个行政区都应该有**：政府办（门户的政府文件、通知公告）、发改委、工信（经信）、科技、商务、财政、人社、市场监管（含知识产权）、农业农村、文旅、生态环境；
  - **有就收 2 类**：数据局（各地设立进度不一）、开发区和高新区管委会（国家级、省级开发区，一个行政区可能有几个）。
- 县级常把几个部门合成一个（"科学技术和工业信息化局"）：合并部门的网站同时算科技、工信两格，栏目只接一次。
- 应接入格数 = 3,212 个行政区 × 11 + 实际找到的数据局、开发区格数（约 35,300 + α）。

一格下面挂 0–3 个**来源**（sources 表一行 = 一个栏目：通知公告、政策文件/规范性文件、公示公告）。一个来源也可能同时服务几格（合并部门）。

## 二、五种状态（创始人 11/5 定）和判定规则

每格每天按下面顺序判定一次（`youju/govsites/board.py` 的 `cell_for`，第二阶段搬进每天的抓取轮次之后）：

| 顺序 | 状态 | 判定 | 原因写什么 |
|---|---|---|---|
| 1 | **需人工** | 官方导航里没找到这个部门的网站或频道 | "官方导航里没找到这个部门的网站或频道" |
| 2 | **不能抓** | 部门网站或全部栏目要登录、有验证码、防护拦截（412/521、瑞数、加速乐等），或 robots.txt 禁止 | 具体哪种（"瑞数防护""robots.txt 禁止"）+ 替代来源（如省级政策文件库） |
| 3 | **抓取失败** | 部门网站或栏目打不开（超时、连接断开、5xx、robots.txt 取不到），或已接入的栏目连续失败 | 最后一次错误 |
| 4 | **网站无此栏目** | 部门网站能打开，首页和"信息公开"页都没有通知公告、政策文件、公示公告 | "首页和信息公开页都没有……（待人工确认）"；人工确认后去掉"待确认" |
| 5 | **已收录** | 至少一个栏目抓取成功并读出条目 | "2/3 个栏目已收录"；同时显示**最后成功时间**（各栏目里最新的） |
| 6 | 需人工 | 栏目找到了，但读不出条目（脚本渲染、要接口、通用规则认不出） | 试读结论 |
| — | 待启用（过渡） | 栏目试读可读，已导入但没启用、没抓过 | 只在分批接入期间出现，接完应为 0 |

人工可以改的只有三件事（都留审计记录，和来源页现有做法一样）：确认"网站无此栏目"、把"需人工"改成指定来源、给"不能抓"填替代来源。其余状态全部由程序按数据算，不能手填"已收录"。

"已收录"的时效：最后成功时间超过 3 天（每天检查 1–4 次）自动掉成"抓取失败"，原因写"连续 N 天没有成功"。

## 三、数据表（第二阶段第 1 周，一个迁移）

```
coverage_divisions                      行政区（来自 行政区划.csv，盘点后补门户字段）
  code            char(6)   PK          行政区划代码；国家级用 000000
  name, kind, level, province, city, district, parent_code
  portal_url      varchar(512)          门户首页（导航里找到的）
  portal_status   varchar(16)           已找到 / 导航未找到 / 打不开 / 不能抓
  portal_nav_source varchar(512)        在哪个官方页面上找到的（可追溯）
  site_id_code    varchar(20)           网站标识码（页面 meta SiteIDCode）
  platform        varchar(64)           集约化平台特征（如"大汉|art_日期_编号"）
  inventoried_at  datetime(6)

coverage_cells                          一格 = 行政区 × 部门
  id              bigint PK
  division_code   char(6)  FK → coverage_divisions
  dept            varchar(16)           政府办 / 发改委 / 工信 / ……（和 sources.dept 同写法）
  seq             tinyint               同一行政区同一部门的第几个（开发区可有多个），其余为 0
  required        bool                  标准部门 true；数据局、开发区 false
  dept_full_name  varchar(128)
  site_url        varchar(512)          部门网站或门户里的部门频道
  site_type       varchar(8)            独立网站 / 门户频道 / 门户本身
  nav_source      varchar(512)          官方导航来源页
  state           varchar(8)            五种状态 + 待启用
  reason          varchar(300)
  last_success_at datetime(6)           由关联来源算出
  confirmed_by, confirmed_at            人工确认"网站无此栏目"/指定来源/替代来源
  alt_source      varchar(512)          "不能抓"时的替代来源
  state_changed_at datetime(6)
  unique (division_code, dept, seq); index (state), index (dept)

coverage_cell_sources                   格 ↔ 来源（多对多）
  cell_id   FK → coverage_cells (cascade)
  source_id FK → sources (restrict：来源只停用不删除)
  kind      varchar(8)                  通知公告 / 政策文件 / 公示公告
  primary key (cell_id, source_id)
```

不改 sources 表：来源的健康、最后成功时间、最后错误都已有（`health`、`last_success_at`、`last_error`）。看板的"已收录"只看已启用来源的成功时间（试点期间在本机库里看抓过的）。

填表：`youju coverage-import --state <盘点结果>`（第二阶段写）把盘点结果写进前两张表，按栏目网址关联已有来源（网址相同的就是同一个来源，现有 93 个全国来源、36 个地市来源会自动挂上）；重复导入只更新盘点字段，不动人工确认的内容。

## 四、按级汇总

每级（国家、省、市、县）和每省、每市都算这一组数：

- **应接入** N：格数；
- **已收录** M、**抓取失败** F、**网站无此栏目** E、**需人工** H、**不能抓** B（加过渡的待启用 P）；
- **覆盖率** = M ÷ (N − E − B)：没有栏目、明确不让抓的不算缺口，但单独列出、各自要有替代来源说明；
- **触达率** = (M + E + B) ÷ N：每格都有结论的比例。

按级验收标准（第二阶段每批接完用这组数验收）：

| 层级 | 覆盖率 | 触达率 | 不能抓 | 其他 |
|---|---|---|---|---|
| 国家级 | ≥ 95% | 100% | 每个都有替代来源 | 13 个目标部委全部有结论 |
| 省级 | ≥ 95% | 100% | 每个都有替代来源 | 每省 11 个标准部门都有结论 |
| 市级 | ≥ 90% | ≥ 98% | 有替代来源或写明暂无 | 333 个地级门户都找到或标明原因 |
| 县级 | ≥ 85% | ≥ 95% | 同上 | 2847 个县级门户都找到或标明原因 |

## 五、后台页面（/admin/coverage，只给管理员）

和现有 /admin/sources 同一套样式（同一份配色、字号、卡片），不另起风格。

1. **顶部四个层级页签**：国家级 / 省级 / 市级 / 区县级。每个页签一行数字：应接入、已收录、抓取失败、网站无此栏目、需人工、不能抓、覆盖率（数字可点，点了下面列表按这个状态筛）。
2. **省份表**（默认视图）：一行一个省，列是该级的覆盖率条（已收录绿、失败红、需人工橙、无此栏目灰、不能抓深灰，按格数比例分段），右侧是数字；按覆盖率从低到高排，最需要处理的在上面。
3. **点进一个省**：行是行政区（省本级、各市、各县，按区划代码排），列是 13 类部门，每格一个色块。鼠标移上去显示部门全称和状态原因；点开右侧抽屉：
   - 部门全称、部门网址、**导航来源页**（点开就是当初在哪个官方页面找到的）；
   - 栏目列表：栏目名、网址、对应来源编号、健康、最后成功时间、最后错误；
   - 操作：试跑（复用 /api/admin/sources/trial）、确认网站无此栏目、指定来源、填替代来源、备注；每次操作写审计。
4. **筛选**：状态、部门、平台（集约化平台特征）、"最后成功超过 N 天"。
5. **导出 CSV**：当前筛选结果，列和 `试点覆盖/<省>.csv` 一样。

接口（都在 /api/admin/ 下，沿用现有管理员登录和限频）：

- `GET /api/admin/coverage/summary?level=省级` → 各省各状态格数、覆盖率；
- `GET /api/admin/coverage/cells?province=浙江&city=&state=&dept=` → 格列表（分页）；
- `POST /api/admin/coverage/cells/{id}` → 人工确认、替代来源、备注（写审计）。

## 六、什么时候更新

- 每天抓取轮次结束后重算一次全部格的状态（只读 sources 表，几秒）；状态变化写 `state_changed_at`。
- 每周重跑一次盘点（`youju coverage-inventory`，页面缓存 14 天内不重抓），发现导航变化（部门改名、网站迁移、新开发区）就更新格的网址，并在后台标"网址有变化，待复核"。
- 告警：某省"已收录"一天内掉了 5% 以上，或某个集约化平台整体失败（同一平台特征的来源一半以上失败），发管理员告警（复用现有告警通道）。
