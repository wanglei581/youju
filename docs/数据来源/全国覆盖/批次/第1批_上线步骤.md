# 第 1 批上线步骤：国家级 + 省级全部门（D-126，计划 11/14–15，在云托管）

**部署前协调会话再问创始人一次，他点头才开始。** 下面的命令都在线上 admin 容器里跑（创始人容器终端：前台运行、`| tee` 留日志），读的是镜像里的 `/app/docs/数据来源/全国覆盖/`。

## 〇、前提

- main 上已合：#460（覆盖看板，迁移 0048）、#466（清单按级写）、第 1 批 PR（导入文件、抽查证据、`import-sources --only-new`、`coverage-enable --verified`、`coverage-sample`、`coverage-accept`）。
- 发布 admin、api 新版本。迁移 0046 → 0048 只新增四张表，不动已有表，不用先发 api。
- 抽查已过：`抽查/第1批_汇总.md`，国家级 + 22 个省合格，共 284 个栏目；北京、山东、新疆、河北、福建、西藏、黑龙江这批不放（不通过的超过两成），广西、甘肃没有栏目。创始人复看约 5%（汇总文件末尾的列表）。

## 一、导入来源（新来源一律不启用）

```bash
youju import-sources --csv /app/docs/数据来源/全国覆盖/批次/第1批_国家级和省级.csv --only-new --dry-run
```

看两样：新增多少（不超过 284），"库里已有的网址"有哪些——已经在收的来源（以前的省级科技厅、工信厅等）`--only-new` 一律不碰。没问题再去掉 `--dry-run` 正式导入。

**不要在线上用 `crawl --include-disabled` 试抓**：小程序给用户看的文件不看来源启没启用，一抓进来就对用户可见。试抓已在本机做完（证据见抽查汇总）。

## 二、看板和抽查记录

```bash
youju coverage-import                                  # 全国清单写进看板表，导入后自动重算（约 4 万格）
youju coverage-accept --level 国家级 --by "Claude（主线）" --dry-run
youju coverage-accept --level 省级 --by "Claude（主线）" --dry-run
```

试算结果和抽查汇总一致（国家级合格；省级 22 个合格、7 个没过）再去掉 `--dry-run` 记进去。没过的省也记一条"没过"，门禁就不会打开它们。抽查记录在后台"覆盖看板"每省一行可见。

## 三、分省打开（D-122 门禁）

先试算，确认每省可启用的个数和抽查汇总里"进本批"的个数对得上：

```bash
for p in 国家; do youju coverage-enable --province $p --level 国家级 --by "协调会话" --verified --dry-run; done
for p in 天津 山西 内蒙古 辽宁 吉林 上海 江苏 浙江 安徽 江西 河南 湖北 湖南 广东 海南 重庆 四川 贵州 云南 陕西 青海 宁夏; do
  youju coverage-enable --province $p --level 省级 --by "协调会话" --verified --dry-run
done
```

`--verified`：线上没抓过、但试读可读的来源也开（本机试抓、抽查合格后第一次打开）。最近被 robots、401/403/412/521 拒绝的不开。没问题去掉 `--dry-run` 正式打开（284 个，在每天 2,000 个上限内）。每次打开都写审计日志（操作人、依据的抽查记录、来源编号）。

## 四、打开以后

- 下一轮抓取（6:30 / 20:30）会抓这些栏目。第一次抓会把列表页上现有的条目记成基线入库：按本机试抓 5,511 条（其中近 30 天发布的 1,710 条），标题、日期、链接马上能在小程序里看到。
- 正文：线上每轮补 600 份、每天 1,200 份，5,511 条要 5 天左右补完。建议上线当天手动先补近 30 天的（约 1,700 条）：
  `youju fetch-details --limit 3000 --workers 8 --since <30 天前的日期>`（同一网站仍间隔 3 秒）。
- 原网页检查（每天最多 3,000 份、近 90 天）会多出一批，输出里"该查还没轮到"连续几天不是 0 就调大 `--limit`；长期方案见第二阶段计划第九节。
- 看板：`youju coverage-refresh` 后省级应以"已收录"为主；"抓取失败"的格点开看原因。

## 五、回滚

在后台"来源接入"逐个停用；整批停用用下面这句（只停这一批打开的，备注里都写了"全国覆盖：××抽查合格（抽查记录 #n）后由 … 启用"）：

```sql
UPDATE sources SET enabled = 0 WHERE note LIKE '%全国覆盖：%抽查合格（抽查记录 #%';
```

已经入库的文件不会自动消失，要下架按现有下架流程。
