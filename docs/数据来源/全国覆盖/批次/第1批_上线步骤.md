## 一、导入来源（新来源一律不启用）

```bash
youju import-sources --csv /app/docs/数据来源/全国覆盖/批次/第1批_国家级和省级.csv --only-new --dry-run 2>&1 | tee -a 第1批.log
```

试算要看三样：
- 新增数：应为 248。
- "库里已有的网址"：已经在收的来源，`--only-new` 一律不碰。
- "和库里只差 http/https 等写法的"：同一个列表，不会新建。

批次文件已经去掉了仓库里线上清单的网址，所以后两样应该是空的。出现的是后台"来源接入"页加过的，记下来，不影响导入。没问题再去掉 `--dry-run` 正式导入。

**不要在线上用 `crawl --include-disabled` 试抓**：小程序给用户看的文件不看来源启没启用，一抓进来就对用户可见。试抓已在本机做完（证据见抽查汇总）。

## 四、打开以后

- **基线入库**：下一轮抓取（6:30 / 20:30）会抓这些栏目。第一次抓会把列表页上现有的条目记成基线入库，标题、日期、链接马上能在小程序里看到。按本机试抓，这 248 个栏目 4,757 条，其中近 30 天发布的 1,283 条。
- **正文**：线上每轮补 600 份、每天 1,200 份，4 天左右补完。建议上线当天手动先补近 30 天的：`youju fetch-details --limit 2000 --workers 8 --since <30 天前的日期> 2>&1 | tee -a 第1批.log`，同一网站仍间隔 3 秒。
- **原网页检查**：每天最多查 3,000 份、只查近 90 天，这批上线后会多出一批。输出里"该查还没轮到"连续几天不是 0，就调大 `--limit`。长期方案见第二阶段计划第九节。
- **看板**：跑 `youju coverage-refresh` 后，省级应以"已收录"为主；"抓取失败"的格点开看原因。

## 五、回滚

1. **停用来源**：在后台"来源接入"逐个停用；整批停用用下面这句。它只停这一批打开的，这批来源的备注里都写了"全国覆盖：××抽查合格（抽查记录 #n）后由 … 启用"。

   ```sql
   UPDATE sources SET enabled = 0 WHERE note LIKE '%全国覆盖：%抽查合格（抽查记录 #%';
   ```

2. **补记"没过"**：在后台"覆盖看板"给回滚的省记一条抽查"没过"。回滚后这些来源有成功记录、名下有文件，抽查记录要是还是"合格"，下次跑 `coverage-enable` 会把它们重新打开。
3. **已入库的文件**：不会自动消失，要下架按现有下架流程。
