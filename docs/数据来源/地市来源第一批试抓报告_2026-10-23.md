# 地市来源第一批：接入准备和本机试抓（2026-10-23，D-086 ④）

> **一句话：** 19 个已核实城市里，**31 个栏目（16 个城市）**已经配成来源，**默认关着**——线上不抓取、不进收录范围和城市筛选，小程序和 api 都看不到；开哪几个城市、什么时候开，等你定。本机礼貌试抓了近 8 周的数据：全开的话每周多约 72 份文件、25 份申报通知，你每周多花约 13–26 分钟核截止和确认转发组（转发规则补全以后上限约 40 分钟）。

## 结论

1. **配好了，关着。** 新清单 [地市来源第一批_2026-10-23.csv](./地市来源第一批_2026-10-23.csv) 里 31 行的验证状态都是"待开（……）"：导入后来源是停用的，定时抓取选不到（调试用的 `--include-disabled` 也选不到），收录范围和城市筛选只认"启用并且抓成功过"的来源，所以线上看不到。打开的办法是把要开的那几行改成"已验证（……）"再导入一次（第二节）。
2. **实测（2026-08-28 至 10-22 这 8 周，31 个栏目合计）：**
   - 每周新增约 **72 份**，其中申报通知约 **25 份**；没进任何转发组、也没和别的文件自动归并的"本地独有"申报通知约 **19 份**。
   - 转发版本：174 份申报通知里 **40 份（23%）**进了转发组，其中 **31 份（18%）**是和部里或省里同组的转发版本；按周算约 **4 个转发组**要你确认（D-055 逐组确认的口径）。Grok 逐组看过，窗口内 30 组同意 25 组；另有 45 份标题写着"转发"或上级机关、规则却没归组，Grok 判断其中 33 份确实在转某份上级通知——所以线上实际要确认的会更多（第四节第 2、3 条）。
   - 截止日期能摘出原句：读得出正文的申报通知里 **77%**（172 份里 133 份），口径和线上机器摘录一样（日期写在原句里、原句在当前正文里）。
   - 正文能读出来：**95%**（493 份里 469 份）。
3. **你每周多花：常规约 13–26 分钟**（约占 D-072 每周 10 小时的 2%–4%）：每周约 18 条截止要核，每条 0.5–1 分钟；约 4 个转发组，每组估 1–2 分钟。规则漏归的转发版本都归进来、AI 再找出规则漏掉的截止时，**上限约 40 分钟（约 7%）**；如果还想把规则没摘到原句的申报通知一份份读出日期，每周再加约 10–15 分钟。打开时另要一次性核约 64 条还没过期的截止。8 周里有国庆长假，平常周的量大约再多七分之一。但申报通知总量比现在的部委和省级（近 30 天约每周 43 份）多五成多。
4. **建议第一波开 4 个城市：广州、深圳、东莞、武汉**（8 个栏目）。它们本地独有的申报通知最多（合计每周约 8.5 份）、正文读出 98%、截止原句 76%（广州只有 56%，要多花时间读正文）；广东三市同一个省，顾问样品表好集中。你每周多花约 8–16 分钟，打开时一次性核约 32 条截止。这等于先定了首批省份（广东、湖北），所以要和你还没定的 D-072 第 4 件一起定（第六节）。
5. **要你定的事**单列在第六节：首批省份和第一波城市；什么时候开；开城后地市的转发组要不要再逐组确认 4 周。

## 二、配置和开关

**怎么关着：** 来源清单的"验证状态"决定导入后启不启用（`youju/sources/importer.py` 的 `mode_for`）。这次加了一个"待开"开头的状态：抓取方式记成 static（试跑通过、通用规则能识别），但不启用。线上看不到，是因为：

- 定时抓取（每天 6:30、20:30 的 `round.sh` → `youju crawl`）只选启用的来源；停用的不抓，就没有文件，补正文、抽截止、转发归组、提醒、周报都碰不到。调试用的 `youju crawl --include-disabled` 也跳过"待开"的来源（本 PR 加的）。
- 收录范围（`/api/v1/coverage`）的栏目和"已收录城市"、搜索的城市筛选（`cities=广东/广州`）只认"启用并且抓成功过"的来源；停用的就算记过成功时间也不算（测试里专门试了）。
- api 服务只开放 `/api/v1/` 和健康检查，来源列表那类接口在 api 上本来就打不开。

**测试**（`backend/tests/test_city_first_batch.py`）：清单 31 行都在 19 个已核实城市里、都是"待开"、不含 robots 不让抓或正文读不出的栏目，也不和候选清单、全国清单重复；导入后全部停用、和候选清单先后反复导入都不会打开；只有改了状态的那一行会打开；只开第一波 4 个城市时，收录范围只列这 4 个城市，没开的城市（如厦门）照样不能筛选；收录范围、城市筛选看不到停用的，`youju crawl` 带不带 `--include-disabled` 都选不到它们。

**怎么开（你说开哪几个城市以后）：**

1. **开之前先查一次生产库**（团队写好命令，你或团队在 admin 容器里跑，一两分钟）：线上应当还没有任何启用过的市级来源和市级文件（10/15 的两行清单写明"没有导入生产"；本机查不到生产库）。命令（全是英文字符，免得容器终端里中文乱码）：
   `python -c "from sqlalchemy import select, func; from youju.db import session_factory; from youju.models import Source, Document; s = session_factory()(); lv = chr(0x5e02) + chr(0x7ea7); print(s.scalar(select(func.count()).select_from(Source).where(Source.level == lv, Source.enabled)), s.scalar(select(func.count()).select_from(Document).join(Source, Source.id == Document.source_id).where(Source.level == lv)))"`
   应当打印 `0 0`；不是就先停下来处理，不要导入。
2. 团队开一个 PR：把那几个城市的行改成"已验证（2026-MM-DD 创始人同意开）"，测试里的数字跟着改；收录范围那句改成写明"科技局、工信局栏目，其他城市还没收录、以当地政府网站为准"；样品表、线索表的覆盖范围写法一起改。你同意后合并。
3. 部署 admin（要你同意），在 admin 容器里导入一次：`sh /app/backend/deploy/job.sh import-sources --csv /app/docs/数据来源/地市来源第一批_2026-10-23.csv`。
4. 下一轮定时抓取开始抓；第一次抓到的算基线，不当新文件提醒用户。之后看日报、收录范围和核对台。

**要注意：**

- **每个网址只在一份清单里：** 第一批的 31 个网址已经从候选清单里移走（测试检查两份清单不重叠）。否则两份清单先后导入，会按网址互相改回启用状态。
- **开了再关，已经抓到的文件不会自动下架**（和省级栏目一样，停用只是不再抓）；要撤得走下架流程。所以先别开，想清楚再开。
- 管理台"来源接入"页对已经在清单里的网址会提示"已经在来源里"，开城市走上面的清单导入，不走那一页。

**同一个 PR 里顺手修的三处抓取问题：**

1. **标题识别**（`crawler/listing.py`）：深圳工信的序号粘在标题前（"8市工业和信息化局关于……"），武汉工信整条做成一个链接、日期和正文开头都粘进了标题。通用标题识别补了两条很窄的规则（序号必须单独写在链接开头的一个元素里、后面不是"号""年""批"这类字；内层标题只在链接里分块写、另写着完整日期时才用）。**回归验证：** 37 个地市栏目的已存页面重新识别，只有这两个栏目的 61 条标题变了；线上已启用的 72 个国家和省级栏目，10/23 各抓一次列表第 1 页、新旧两版对比，**71 个一字不差，1 个变干净**（青海工信 15 条标题去掉了开头多出来的"·"，它也是整条做成链接的写法）；条数和日期都不变。已经入库的文件标题不改，只影响以后新抓到的。
2. **互动交流平台**（`crawler/detail_service.py`）：广州、深圳科技局和广东省工信厅列表里的"公开征求意见"链到政府网站的互动交流平台（`/hdjlpt/`），页面带验证码。以前抓取程序会请求一次、认出验证码再停；现在这类链接**一次都不请求**，直接记为防护页（agy 的意见）。
3. `youju crawl --include-disabled` 不再抓"待开"的来源（Grok、agy、Codex 都提了"只靠叮嘱不够"）。

## 三、试抓怎么做的

- **时间和工具：** 2026-10-23 下午在本机跑，工具是 `tools/team/city_trial.py`（放在仓库里，打开前可以再跑一遍；用法写在文件开头，当时用的是默认参数：每个栏目最多 4 页、窗口 8 周）。数据只进本机自己建的试抓库，没有连生产、没有把正文发给外部模型。
- **礼貌规则：** 全部用项目自己的抓取器——透明标识 YoujuBot、先读 robots.txt（取不到按禁止）、同一网站两次请求至少隔 3 秒、只抓政府网站、不跟到内网地址；网站拒绝就停，不换标识、不用浏览器绕过。列表页只跟页面上写着的翻页地址（"下一页"链接或页面脚本里写的翻页规则），还要在同一栏目里（同一目录、栏目查询参数都在、新页条目和第 1 页同一个目录），每个栏目最多 4 页。
- **请求量：** 地市列表页 79 次（35 个网站）、国家和省级列表第 1 页 72 次（和线上每轮一样）、正文 829 次（89 个网站：地市窗口内的 518 份，加上国家和省级标题相近的 311 份，用来判断转发）；回归验证又抓了 72 个国家和省级列表第 1 页、沈阳工信 3 份正文；另有每个网站一次 robots.txt。同一网站最多几十次、每次间隔 3 秒以上。
- **统计窗口：** 试抓前一天往前 8 整周（2026-08-28 至 10-22）。列表翻不到 8 周前的栏目（西安、厦门、长沙工信、广州工信），按实际盖住的天数折算成每周，表里标 ＊。
- **四项数字的口径：**
  - 每周新增：窗口里发布的文件数 ÷ 周数。
  - 转发版本：用线上同一套转发归组规则（`youju/repost.py`，D-055）在"国家和省级 + 地市"的文件上归组；"进转发组"是窗口里进了组的地市文件，括号里是其中和部里、省里文件同组的。国家和省级的文件用的是本机 9/28 的旧副本（只读）加 10/23 现抓的列表第 1 页，往前覆盖约 3 个月。
  - 截止能摘出原句：读得出正文的申报通知里，规则抽到截止、原句里写着这个日期、原句也在当前正文里的比例（D-061 机器摘录的前提，和线上同一个判断）。
  - 正文读出：正文抓成功、不是空的、也不是页面公共部分（页脚、版权、导航）的比例。
- **局限：** 8 周里有国庆长假，量可能偏低（平常周约多七分之一）；只按规则统计，线上配了 AI 时还会多找到一些截止；国家和省级的旧通知只到 9/28 的副本和现在列表第 1 页，有少量上级通知不在库里，相应的转发版本会少算（第四节第 3 条）。

几点说明：

1. **"同一文件"自动归并为 0。** 地市转发上级通知时标题都会改（加"转发""市科技局关于……"），发文机关也不同，所以没有一份是和部里、省里"同一文件"自动合并的；能合并的都要走转发组、要你确认。
2. **转发组准不准：** 规则提出的含地市文件的组一共 56 个，第一批栏目窗口内触到 30 个。Grok 逐组看了标题，这 30 组里同意 25 组（约 83%）：不是同一份通知的 1 组（广东、重庆各自组织参加进博会）；拿不准 4 组（两组"延长科技型中小企业评价申报期限"——各省自己延期、标题一样；"人工智能应用服务商""数字化转型典型案例"各一组）。这几组都是"疑似"或同名事项，正是 D-055 要你确认才合并的那类，确认时点"拆分"就行。
3. **规则漏归的转发版本：** 窗口里有 45 份地市文件（其中约 30 份申报通知）标题写着"转发"或上级机关名、却没进组。Grok 判断其中 33 份确实在转某份具体的上级通知（4 份本该并进已有的组，如"绿色工厂推荐""先进制造业企业增值税加计抵减"），12 份是地方自己的事。没归上的原因：①上级原件不在试抓库里（库里只有 9/28 的副本和现在的列表第 1 页）；②标题改写较多（"市经信局关于转发省经信厅办公室……"），核心标题对不上；③现行规则把核心标题里写"省级"的当成各省自己的项目、不归组，地市转发省里的"省级××申报"就归不进去。线上省级文件更全，①会少一些，所以**线上要确认的组会比上面算的多**——第五节按"每周再多 4 组"估了上限。没归组的只是在列表里和省里原件各占一行，不会算错截止；②③要改规则才能归（第五节后续事项）。
4. **脱敏核对（agy 的意见）：** 499 份地市正文扫过：没有漏遮的个人手机号；17–19 位的长数字都是公示名单里企业的统一社会信用代码（企业公开信息）或网址参数；已有 653 处按规则遮掉。
