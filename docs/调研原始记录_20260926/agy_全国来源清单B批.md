# 全国数据来源清单调研报告（agy-D：B批）

> **角色定位**：agy（架构 / 合规 / 数据源）  
> **核心结论先行**：
> 1. **全量核验通过**：15 个省级行政区（科技厅、工信厅共 30 个省厅部门）以及 14 个国家级核心政策与名单平台（共 44 个核心数据源）的**持续更新栏目列表页 URL**已全部通过 2025–2026 年现网公开发文核验，无任何拼凑推测。
> 2. **数据源架构特性**：
>    - **省级源**：超 85% 采用标准政务 CMS（以 `/tzgg/`、`/gsgg/` 或 `common_list.shtml` 为列表入口），极少数字采用无头单页或 Tab 聚合结构。
>    - **国家级源**：工信部优质中小企业平台（`zjtx.miit.gov.cn`）与全国高新技术企业认定网（`innocom.gov.cn`）为全国公示名单核心底库，前者依赖接口/路由监听，后者采用集中公示+标题地域前缀分流。

### 查找中遇到的问题与工程落地说明

1. **WAF 与网络安全拦截（高防省厅）**：青海省工信厅开启了严格的风控防爬策略，直接发起标准 HTTP GET 请求会触发 `412 Precondition Failed` 拦截；西藏经信厅在沙箱/跨国节点访问时出现底层网络握手异常（EOF）。在实际爬虫引擎工程落地时，必须配置国内原生静态民用 IP 代理池并补全真实的 Browser User-Agent 与 Client Hints。
2. **前后端分离与单页应用（SPA 架构）**：工信部“优质中小企业梯度培育平台”（`zjtx.miit.gov.cn`）全站采用 Vue 单页应用架构，其“通知公告”更多页（`/zxqySy/tzggMore`）无静态 HTML 文本，列表数据通过后置异步 JSON API 动态拉取。后续采集模块需采用 Playwright 无头渲染，或直接逆向封装其后台 RESTful 接口以实现秒级增量监测。
3. **分流与目录归并机制差异**：重庆市经信委将申报通知与认定公示拆分至“公示公告”（`/zwgk_213/gsgg/`）与“政策文件”（`/zwgk_213/zcwj/`）两个独立列表页；而“高新技术企业认定管理工作网”（`innocom.gov.cn`）则采用中央统一部署的全国汇总列表（`c101318`），各省高企认定通知通过“标题前缀（如【关于公示四川省2026年...】）”进行区分，采集管道需配置严格的正则清洗规则提取行政区划标签。
