# 上线运营与应急处置手册 v2（2026-10-19）

> 取代 [v1](上线运营与应急处置手册_v1.md)（9/30）。v1 写的"机器人待补""邮箱待补"都已补上；这一版按现在的服务、定时任务和提醒重写，加上了批量工具、AI、支付的处置。差距清单 O2、M2、B3、C3。
> 写给创始人（运营）和 AI 团队（技术）。部署、合并、删库、改环境变量这些仍然要创始人在聊天里同意。

## 零、先记住三件事

1. **每天早上企业微信群里有运维日报**：08:00 先做截止日期质检，质检做完才发日报，平时几分钟内就到。日报来了，说明 admin 服务和定时任务都活着。**08:30 还没收到，先当作出了问题**，按第四节第 1 条查。
2. **日报第二行就是今天要做的事**："今天先核：7 天内到期的截止待核对 N 条"。
3. **群里收到别的提醒**，在第三节的表里找到它，照"怎么办"做；不确定就截图发给 Claude。

## 一、每天、每周、每月

### 每天早上（15–20 分钟）

| 顺序 | 做什么 | 多久 |
|---|---|---|
| 1 | 看日报：第二行今天要核几条；"抓取"那行有没有"上次成功"是好几天前的栏目；"纠错待处理"是不是 0 | 2 分钟 |
| 2 | 管理台"截止日期 · 7 天内"：把这几条核完（D-061：7 天内到期的只显示人工核对过的） | 10–15 分钟 |
| 3 | 有纠错就处理（第四节第 6 条） | 0–3 分钟 |
| 4 | 有栏目"上次成功"是 3 天以前：截图发给 Claude | 1 分钟 |

哪天没空核：产品不会空，只是 7 天内到期的那几条不写日期；连续 3 个工作日没核，小程序首页会写"今日未更新"。

### 每周一（约 30 分钟）

- 管理台"定时任务"：看最近 7 天有没有失败的。
- 微信小程序后台"运维中心"：看有没有新的 JS 错误、页面打开慢的提示（M6）。
- 联系邮箱和投诉登记表：有没有投诉、查阅删除等个人信息请求，离 15 个工作日的期限还有几天（第四节第 5、7 条）。
- 管理台"转发归组""类型复核"：有空再处理（D-055 前 4 周要人工确认）。

### 每月（团队做，创始人看结果）

- **恢复演练**：Claude 用最近一份生产备份恢复到本机隔离库，逐表核对条数、外键，升级到当前迁移后读几个接口，记下耗时；临时副本用完就删。结果记在 [docs/迭代](../迭代/) 的当月记录里。上一次：10/15，38 张表 202881 行，18.7 秒。
- 个人信息合规自查（半年一次）：按《个人信息合规自查清单》走一遍（L8）。

### 日报每一行怎么看

| 行（日报里的写法） | 看什么 | 不对劲时 |
|---|---|---|
| 今天先核：7 天内到期的截止待核对 N 条（管理台"截止日期 · 7 天内"）；上次核对 X月X日（N 天前） | N 就是今天要核的条数；从没核对过时后半句写"还没核对过一条" | 上次核对是 3 个工作日以前：小程序首页会写"今日未更新" |
| 抓取：启用栏目 N 个，今天检查成功 N 个（x%）；异常 N 个：……（上次成功 X月X日） | 没有异常时只有前半句；有异常最多列 3 个，坏得最久的排前面；从没成功过的写"从没成功过，X月X日起" | "上次成功"是 3 天以前的，截图发 Claude |
| 新文件：……、核对：……、用户：……（三行） | 和管理台总览同一套数 | — |
| 接口（X月X日，小程序接口）：api N 次，5xx N 次、其他请求 3 秒及以上 N 次，3 秒内成功 x% | 前一天的数（admin 也有一段）；上线后要求 99% 以上（D-061） | 低于 99% 或 5xx 突然变多，发 Claude；写"没有汇总"：前一天的访问日志归档没跑成（看定时任务），或前一天没有小程序请求 |
| 数据（近 30 天发布）：申报通知 N 份，有正文 x%、有截止候选 x%；名单 N 份，解析出企业名单 x% | 数据全不全；份数是 0 时比例写"—" | 某个比例突然下降，多半是某个网站改版 |
| 用量：数据库约 N MB；附件副本 N 个，约 N MB；批量工具结果文件 N 个 | 东西占了多少；数据库大小查不到时写"数据库大小取不到" | 一周内涨得很快，发 Claude 看是不是有异常 |
| AI（X月X日）：调用 N 次、出错 N 次…… | 前一天 AI 的用量；从来没用过 AI 时没有这一行 | 出错多，发 Claude |
| AI 建议先核对（仅供参考）：…… | AI 从待核对里挑的几条，配了 AI 才有 | 只是参考，以管理台为准 |

某一行写"取不到（统计出错，看容器日志）"：那一项的统计出了错，其他行照常，截图发 Claude。

## 二、事件分级

| 级别 | 什么情况 | 多快响应 | 谁处理 |
|---|---|---|---|
| 紧急 | 小程序打不开、接口大面积报错（"接口出错""接口成批失败"一直来）、数据库连不上（"访问日志写入数据库失败"）、管理口令泄露、截止或名单大面积错了、付款扣了钱没开通、收到监管部门要求下架 | 30 分钟内响应，2 小时内止血 | 创始人定，Claude 修 |
| 重要 | 已发布的截止日期错了、定时任务连续失败、日报没来、某个栏目连续 3 天以上没抓到、收到侵权投诉 | 2 小时内响应，当天处理完 | 创始人管内容，Claude 查代码 |
| 一般 | 单条纠错、偶尔一次任务失败、个人信息请求邮件 | 纠错 24 小时内；邮件 15 个工作日内答复 | 创始人 |

## 三、群里会收到哪些提醒

提醒都以"【有据】"开头，只写摘要，不带用户信息和密钥。

| 提醒开头 | 是什么 | 怎么办 |
|---|---|---|
| 运维日报 X月X日 | 每天 08:00 质检做完后发一条（心跳） | 按第一节看。没来见第四节第 1 条 |
| 接口出错（api 或 admin 服务……）| 接口遇到没处理的异常，返回了 500；每个实例各自算，10 分钟最多一条，带这期间的次数 | 截图发 Claude；同时用手机打开小程序看能不能用。一直来就是紧急 |
| 接口成批失败（api 或 admin 服务，10 分钟内 N 次……）| 接口主动返回的 5xx（附件取不到、导出繁忙、内容安全检查不可用、支付不可用等）或其他请求超过 15 秒才答复，每个实例各自算，10 分钟内满 3 次；提醒过 1 小时内不重复（没发出去的 5 分钟后再试） | 截图发 Claude。偶尔一条多半是外部服务抖动；连着来就是紧急 |
| 访问日志写入数据库失败（X 服务……）| 那个服务连不上数据库或没有写权限；每个实例各自算，10 分钟最多一条 | 紧急：截图发 Claude，先确认小程序能不能用 |
| 任务 youju X 失败：退出码 N（原因）| 某个定时任务失败或超时 | 截图发 Claude（第四节第 2 条） |
| 今天栏目检查成功率 N/M…… | 今天有不少栏目没抓到（低于 95%），或者有栏目今天没检查到（漏检），或者一个启用的栏目都没有 | 一般是网络或政府网站临时问题，看下一轮；第二天还在就发 Claude |
| 这些栏目连续好几天没抓到…… | 每天早上抓取完检查一次：某个栏目连续没抓到第 3、7、14、30 天（之后每满 30 天）时提醒，多半是网站改版 | 截图发 Claude（第四节第 8 条） |
| 上一轮抓取和处理还没跑完，跳过…… | 上一轮太慢 | 偶尔一次不用管；连着几天发 Claude |
| 质检发现 N 条已发布的截止日期可能有误…… / 质检的 AI 抽查出错…… | 每天 08:00 质检回查已发布的截止，有存疑的；或 AI 抽查出错 | 管理台"质检"看，错了就"退回待核对"；AI 出错的明天自动重试，连续出错发 Claude |
| 启动时发现库里的迁移版本 X 比这版代码新…… | admin 刚回退到了旧版本（发版与回退第五节），没迁移、照常启动了；或者发错了版本（发布脚本平时会拦，只有加了 `--skip-main-check` 才发得出去）。只有那个版本本身带着这个处理（R4 修复之后的版本）才会照常启动；更早的版本遇到这种情况会起不来 | 回退是团队做的就不用管；不是在回退，就是发错了版本：按紧急处理，截图发 Claude |
| 告警验收测试，标记…… | 团队做受控测试时发的 | 不用处理，按团队要求回一句"收到" |
| 结果文件巡检：对象存储里有 N 个批量工具结果文件…… | 有没有任何记录指向的批量工具结果文件（团队手动跑巡检时才有） | 看 Claude 的说明再决定删不删 |

**服务启动时**，两个服务都会在容器日志里打一行告警地址配没配（`alert-probe`，只有 true/false）。部署后团队会看这一行；api 没配时，上面"接口出错""接口成批失败""访问日志写入数据库失败"这几条 api 的提醒都发不出来——请在云托管控制台给 **api 服务**也填 `YOUJU_ALERT_WEBHOOK`（和 admin 同一个机器人地址）。

## 四、具体怎么处理

### 1. 08:30 没收到日报

1. 打开管理台：打不开，或"总览"里定时任务心跳是很久以前 → admin 停了。能打开、心跳正常 → 看"总览"里 08:00 的质检和日报任务是失败了还是还在跑（质检慢会推迟日报）。
2. 云托管控制台看 admin 服务：实例数是不是 0、最新版本是不是"构建失败"或"异常"。
3. 截图发 Claude。admin 停着的时候：定时任务（抓取、备份、日报）都不跑，小程序首屏会改从 api 取数（慢一点，能用）。
4. 恢复后，Claude 看哪些任务漏了，给你补跑的命令（在 admin 的"实例 → 终端"里前台执行）。

### 2. 定时任务失败

1. 管理台"定时任务"看最近 7 天，确认是哪个任务、什么时间。
2. 截图发 Claude；Claude 用只读日志查原因，要改代码就修好发版（要你同意）。
3. 要补跑的，Claude 给命令，你在 admin 的"实例 → 终端"里执行：**在前台跑，并且 `| tee /tmp/<名字>.txt` 保存输出**；结果以 Claude 给的那一行英文检查结果为准，不看复制出来的中文（容器终端复制中文会随机出现乱码）。

### 3. 小程序打不开或接口大量出错

1. 手机打开小程序，截图发 Claude："小程序报错，请紧急排查"。
2. Claude 用只读工具看版本、实例数和日志；是新版本引起的，按[发版与回退](发版与回退流程.md)第五节回退（要你同意）。
3. 恢复后你再打开首页、详情、查名单看一遍。

### 4. 截止日期发布错了

1. 30 分钟内：点管理台"截止日期"页顶部提示里的"撤回"按钮（也可以按 `u`）。
2. 超过 30 分钟：管理台"质检"找到这条，点"退回待核对"，它立刻不再对外显示。
3. 对照原文核准后重新通过；纠错里有对应反馈的，标记处理。
4. 很多条一起错（程序抽错）：发 Claude 查规则。

### 5. 政府部门要求删除、或收到侵权投诉

**政府部门（网信、公安、通信管理、发文机关等）要求删除或下架**：这是紧急事件。
1. 先下架：管理台"用户反馈 → 下架"找到文件（编号、标题或原文网址），点"下架"，选原因、写说明；小程序所有页面马上不再出现，有记录、可恢复。
2. 按对方要求的方式和时限回复已处理（要回执的按要求出回执）；不要辩解，有疑问先处理再沟通。
3. 截图发 Claude：查同一来源还有没有同类文件，需要的话停用这个来源。

**个人或单位的侵权投诉**：
1. 查邮件里的证明材料（权利证明、身份证明），在投诉登记表里记下收到日期。
2. 材料基本齐全的，先下架再核实（同上第 1 步）；涉及已发布的截止，在"质检"退回。
3. 15 个工作日内回邮件：已下架或核实后的处理结果；不成立的说明理由（我们只收录政府网站公开发布的文件，每条附原文链接）。

### 6. 用户纠错

1. 管理台"纠错"看内容、对应文件、自动复查意见。
2. 对照原文：要改的改（截止在"截止日期"或"质检"处理）；原文就是这样的，不改。
3. 选处理结果（纠错：已更正 / 已核对，和原文一致，没有改 / 已下架这份文件 / 已收到，作为建议记下；申请覆盖：已接入这个栏目 / 暂不接入 / 已收到，作为建议记下；支付问题：已处理），写一句给用户的说明（最多 200 字，不要写别人的个人信息；支付问题选"已处理"时必须写，写清楚怎么解决的；其他可不写），再点"标记已处理"。用户在"我的 → 我的数据"里看得到结果和说明（差距清单 C1，第 6 批上线后）。
4. 选错了：改好再点"保存修改"（处理时间不变）；"撤回"会回到待处理，结果和说明一起清掉。
5. 纠错被采纳要送天数：先在"处理结果"里选"已更正"或"已下架这份文件"（不选就记成"已更正"），需要时写说明，再点"采纳并送 1 天"，它会同时标记已处理。本月已送满 3 天的这次记 0 天，按钮旁会写明。已经选了"和原文一致，没有改"这类结果的不能送，要先改结果。
6. 送过天数的不能撤回（天数不收回），结果也只能改成采纳类的。

### 7. 用户要求查阅、复制、删除、注销

1. 先引导用户在小程序"我的 → 我的数据"里自己操作（都是即时完成的）。
2. 邮件来的请求（解释说明、转移等）：在登记表里记下到达日期，**15 个工作日内**答复；需要从库里查的找 Claude 协助（只给去标识的结果）。

### 8. 某个栏目连续几天没抓到

1. 管理台"来源管理"找到这个栏目，用浏览器打开它的网址，看是不是改版、栏目换了地址、或者打不开。
2. 把栏目名和你看到的情况发给 Claude。
3. Claude 判断：改了地址的用"试跑"重新接入；改成脚本加载的，先确认是公开接口、没有访问控制才接；有访问控制或拒绝程序访问的，按规矩停用并在"收录范围"写明（D-013），不绕过。

### 9. 管理口令可能泄露

1. 你自己生成至少 32 位的随机口令（不发给任何人，包括 Claude）。
2. 云托管控制台 → admin 服务 → 环境变量，改 `YOUJU_ADMIN_TOKEN`，保存后会自动出新版本。
3. 新版本上线后流量全部切过去，旧口令就登不进去了；Claude 用只读工具确认旧版本已经没有流量、实例在缩到 0。
4. 用新口令登录验证；Claude 查泄露期间的管理操作记录，列出可疑的交你确认。

### 10. 数据库需要恢复

先看一眼云托管 MySQL 的控制台有没有自带的备份恢复（例如按时间点恢复）：有的话优先用它，团队给你核对步骤，不用把数据拿到本机（这一点团队还没核实过，第一次用前先确认）。没有的话，用我们自己每天的备份：

1. 你确认确实坏了，通知 Claude。
2. 你在云托管控制台 → 对象存储 → `backups/` 下载要用的那天的备份（每天 04:00 一份，保留 30 天），在本机交给 Claude（不发到聊天里）。
3. Claude 先在本机隔离库恢复、逐表核对（同每月演练），给出正式环境的步骤：云托管 MySQL 新建空库 → 迁移 → 恢复 → 核对。恢复和核对的命令只输出条数和校验值，不在屏幕上显示任何数据内容；备份文件只在这台电脑上处理，不发给任何人或外部模型，用完就删。
4. 你按步骤操作，最后在环境变量里把数据库地址换成新库（口令只由你填）。
5. 预计停服：本机恢复约 20 秒；正式环境含建库、迁移、核对，按 30–60 分钟准备（没演练过，第一次以实测为准）。停服期间小程序显示手机上缓存的旧数据。

### 11. 付款、开通、退款出问题（开卖以后）

按 [backend/PAYMENTS.md](../../backend/PAYMENTS.md) 的处置流程：管理台"支付"待办、`youju pay-refund` 命令，都要先 `--dry-run` 看清楚。
