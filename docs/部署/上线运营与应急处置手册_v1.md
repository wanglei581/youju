## 一、日常运营节奏

### 1. 上线第一周每日工作
- **早间巡检（08:15–08:35，约 20 分钟）**：
  1. 登录[管理后台](https://admin-321511-12-1498153640.sh.run.tcloudbase.com/admin)（口令只在页面里，刷新后要重新输入）。
  2. 查看**总览**与**定时任务**：看 06:30 抓取处理、08:00 质检和日报几个任务是否成功（日报内容要企业微信机器人配好才收得到）。
  3. 执行待办核对：逐一完成“截止日期核对”（可配合快捷键；如误触，30 分钟内可撤回）、“支持方式核对”与“类型复核”。牢记数据红线，未经核验不勾选发布。
  4. 查看**转发归组**（D-055）：同一份部里通知的各地版本，前 4 周每组都要在这里确认后才对外合并（每周约 2–3 组），见《管理台使用说明》“转发归组”一节。
  5. 查看**纠错**：查看用户反馈并标记处理。
- **晚间巡检（21:00–21:10，约 10 分钟）**：
  1. 进入**定时任务**：手动检查 20:30 抓取处理是否成功（因企微机器人**待补**，必须手动看）。
  2. 集中处理晚间待核对数据及纠错条目。

### 2. 常规运营节奏（第二周起）
- **每日**：保持早晚两查，重点完成核对与纠错，单日耗时约 15–20 分钟。
- **每周一（约 20 分钟）**：
  1. 检查**定时任务**最近 7 天运行记录，重点确认夜间底座任务（00:30 日志归档、03:30 清理、04:00 数据库备份）是否均连续成功。
  2. 检查**来源管理**抓取健康度。
  3. 查收联系邮箱（**待补**），核实处理用户权益申请与侵权投诉。

## 三、具体应急处置流程

### 1. 定时任务失败
- **创始人**：
  1. 在管理台**定时任务**页面查看最近 7 天结果，确认具体失败任务（抓取、日志、清理、备份或质检）。
  2. 复制任务名称与报错时间，发给 Claude。
- **Claude**：
  3. 根据任务名和时间排查原因，需要改代码的修复后发布。
  4. 需要补跑时，给创始人一条命令，由创始人在云托管控制台 admin 服务的 WebShell 里执行（Claude 进不了容器）。
- **创始人**：
  5. 刷新管理台，确认该任务执行状态已变更为成功。

### 2. 小程序打不开或接口大量出错
- **创始人**：
  1. 手机打开小程序验证故障现象，立即截图发给 Claude：“小程序报错，请紧急排查 api 服务”。
- **Claude**：
  2. 检查云托管 api 服务（最多 3 实例）负载与日志，排查公网限制及容器健康度。
  3. 若为新版本引入故障，立即通过命令 `wxcloud run:rollback` 或云托管控制台版本管理回退到上一可用版本。
  4. 确认服务恢复正常后通知创始人。
- **创始人**：
  5. 重新打开小程序首页、详情页验证，确认功能恢复。

### 3. 发现截止日期发布错了
- **创始人**：
  1. **未超 30 分钟**：直接在管理台**截止日期核对**点击“撤回”。
  2. **超过 30 分钟**：进入管理台**质检**模块，找到该记录点击“退回待核对”，该截止日期立即不再对外显示。
  3. 重新对照政府原件核验真实截止日，在待核对中更正后重新发布。
  4. 进入**纠错**模块，将对应反馈标记为“已处理”。
- **Claude**：
  5. 若系大面积字段异常解析，接收创始人反馈后复查清洗逻辑并发布修复。

### 4. 收到侵权投诉或政府部门要求删除
- **创始人**：
  1. 查阅联系邮箱（**待补**），核实来件证明材料（权属证明、公函真实性）。
  2. 立即在管理台**用户反馈 → 下架**里找到这份文件（按编号、标题或原文网址搜索）点“下架”，选原因、写说明——从小程序所有页面撤下该文件，如实填报下架原因并留痕。
  3. 如果涉及已发布的截止日期，在管理台**质检**里退回待核对。
  4. 邮件回复对方：已在第一时间下架核实，并说明平台第三方客观收录定位。
- **Claude**：
  5. 如需永久屏蔽抓取该网站来源，根据创始人提供的地址修改爬虫抓取规则并发布。

### 5. 用户要求查阅 / 删除 / 注销
- **创始人**：
  1. 引导用户直接在小程序“我的”→“我的数据”中自主操作“查看”、“复制”、“删除”或“注销”（均为系统全自动即时完成）。
  2. 若收到解释指引、信息转移等邮件请求，登记邮件到达日期（红线：隐私协议承诺 15 个工作日内答复）。
- **Claude**：
  3. 协助从数据库检索或脱敏提取该用户请求的相关数据。
- **创始人**：
  4. 整理文案，在 15 个工作日内邮件正式答复用户。

### 6. 管理口令可能泄露
- **创始人**（口令只由创始人本人处理，不发给任何人，包括 Claude）：
  1. 生成一段新的随机口令（至少 32 位）。
  2. 登录微信云托管控制台 → admin 服务 → 服务设置 → 环境变量，把 `YOUJU_ADMIN_TOKEN` 改成新口令并保存；服务会重启生效。
  3. 用新口令重新登录管理台验证（连续输错 5 次锁 10 分钟）。
- **Claude**：
  4. 查审计记录里口令泄露期间的管理操作，列出可疑的核对或下架操作，交创始人确认；需要时撤回或退回待核对。

### 7. 数据库需要恢复
- **创始人**：
  1. 确认发生严重数据损坏，向 Claude 下达数据库恢复指令。
- **创始人**：
  2. 在云托管控制台 → 对象存储 → `backups/` 下载要用的那天的备份文件（每天 04:00 一份，保存 30 天），交给 Claude（本机传文件，不发到聊天里）。
- **Claude**：
  3. 先在本机新建空库、用同一版本的代码迁移好，用 `youju restore` 恢复，逐表核对条数、外键和内容指纹，确认备份完好（恢复不会覆盖原库，任何一步不对就整体回滚）。
  4. 给出正式环境的恢复步骤：在云托管 MySQL 新建空库、迁移、恢复、核对。
- **创始人**：
  5. 按步骤操作，最后在环境变量里把数据库地址换成新库（数据库口令只由创始人填）。
- **创始人**：
  6. 登录管理台与小程序端，抽查 5 篇以上文件及核对列表，验证读写正常。

### 8. 政府网站改版导致某个来源抓不到
- **创始人**：
  1. 在管理台**定时任务**或**来源管理**发现特定来源连续无新增或报错。
  2. 在管理台**来源管理**里找到这个来源的栏目网址，用浏览器打开，看页面是否改版或栏目换了地址。
  3. 将原来源名称及改版后的网址提供给 Claude。
- **Claude**：
  4. 用管理台"来源管理"的"试跑"验证新地址能否识别条目；通用规则认不出时补抓取规则，本机调试通过后发布。
  5. 新地址要创始人在"来源管理"里确认接入。
- **创始人**：
  6. 在管理台查看下一轮抓取任务结果，确认数据已重新成功入库。
