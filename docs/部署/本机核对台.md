# 本机核对台（云托管开通前使用）

**现状（2026-09-28）：**

- 本机有 157 条截止日期候选待核对。
- 核对结果只存在本机数据库。正式环境部署后，用"导出核对结果 / 导入"搬过去。这个功能在 PR #64；合并前，本机服务已按 #64 的代码运行。
- 只有核对通过的截止日期，才会出现在小程序的日历和详情里。没核对的，小程序写"截止时间见原文"。

## 打开

1. **打开页面：** 浏览器打开 <http://127.0.0.1:8000/admin/review>。打不开，说明本机服务没开（比如电脑重启过），在 Claude Code 里说"启动本机核对台"即可。
2. **填管理口令：** 口令在 `backend/.env` 文件里 `YOUJU_ADMIN_TOKEN=` 后面那串。只在本机使用，不要发给任何人，也不要贴进聊天。
3. **载入：** "核对人"填自己的名字，点"载入"。一次显示 50 条，最新抽出的在前，看完点"再载入 50 条"。

## 核对

每张卡片是程序从原文里找到的一个日期，下面是原文里的那句话。点标题可以打开原文对照。

| 情况 | 操作 |
|---|---|
| 确实是截止日期，日期和时间都对 | **通过** |
| 不是截止日期（会议时间、公示期、发文日期等），或者看不出来 | **驳回** |
| 是截止日期，但程序抽错了日期或时间 | 在卡片上改日期（和时间），点**改日期后通过** |
| 这个截止日期后来被新通知改了（延期、提前、取消） | 点**原通知截止已变更？**，找到新通知后点**标为已变更** |

- "标为已变更"点错了，可以撤回。
- "通过"和"驳回"目前不能在核对台撤回，点之前看清楚。点错了告诉 Claude 处理。

## 搬到正式环境（云托管部署后）

1. **导出：** 在本机核对台点"导出核对结果"，保存下载的文件。
2. **等正式环境跑完一轮：** 正式环境要先跑完一轮抓取和截止日期抽取（每天 4 轮，任意一轮之后都可以），否则很多条会显示"这边还没有文件"。
3. **预览：** 打开正式核对台（云托管 admin 服务的地址），选择文件，点"预览导入"。看各项数字：将导入、已相同跳过、冲突、这边还没有文件、还没有截止候选、还没有变更通知。
4. **确认导入：** 没问题再点"确认导入"。
   - 冲突的不会覆盖正式环境里已有的核对结果，按预览列出的清单人工处理。
   - "还没有……"的条目，等正式环境下一轮跑完后，用同一个文件再导入一次。已导入的会自动跳过。
