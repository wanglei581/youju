# 部署：微信云托管 + 云托管自带 MySQL（#32 草案）

> 状态：草案。镜像还没有构建验证过（本机没有 Docker），开通云托管后第一次构建时验证，结果补在本文。
> 依据：微信官方文档（2026-09-28 本机直接访问核对），链接见文中。
> 数据库：创始人决定先用免费的（D-022），用云托管自带的 MySQL 8.0，不另买腾讯云 PostgreSQL。

## 一、结构

| 服务 | 用途 | 公网 | 实例数 | 环境变量 `YOUJU_ROLE` |
|---|---|---|---|---|
| 小程序接口 | 小程序全部接口（`/api/v1/*`） | **关闭** | 按量伸缩 | `api` |
| 核对台和定时任务 | 截止日期核对台、管理接口；每天定时检查栏目、补详情、抽截止、解析名单 | 开启（只挂核对台和管理接口，用口令） | **固定 1 个** | `admin` |

两个服务用同一个镜像（仓库根目录 `Dockerfile`）。

- **为什么小程序接口关闭公网：** 小程序用 `wx.cloud.callContainer` 调用时，服务收到的请求头自动带用户身份（`X-WX-OPENID` 等），官方建议只有小程序调用的服务关闭公网访问，并用 `X-WX-SOURCE` 判断来源（[容器内变量信息](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/weixin/index)、[调用云托管服务](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/development/call/mini.html)）。关闭公网后，别人无法伪造用户身份头。
- **为什么定时任务服务固定 1 个实例：** 云托管没有单独的定时触发器，官方做法是在容器里跑 cron（[定时触发](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/practice/trigger.html)）。多个实例会各跑一遍，缩到 0 个实例则不跑，所以固定 1 个。
- **限制：** `callContainer` 请求不超过 100 KiB、返回不超过 1000 KiB（导出文件要控制在这以内）；小程序基础库最低 2.23.0。

## 二、定时任务（北京时间）

| 时间 | 命令 | 作用 |
|---|---|---|
| 06:30、11:30、15:30、20:30 | `round.sh`（每天 4 轮，按顺序执行下面 5 步；整轮加锁，上一轮还没跑完就跳过这一轮并提醒） | |
| ① | `youju crawl` | 检查全部启用栏目，发现新文件 |
| ② | `youju check-sources` | 抓取成功后才运行：核对今天（北京时间零点起）各启用栏目的最近一次检查，成功率低于 95% 或有漏检就发提醒 |
| ③ | `youju fetch-details --limit 300 --workers 4` | 补抓详情（正文、机关、文号、附件） |
| ④ | `youju extract-deadlines` | 从正文抽截止候选，进入核对台 |
| ⑤ | `youju parse-lists` | 解析名单附件（单次最多 200 个附件） |
| ⑥ 只在 06:30 那一轮 | `youju notify` | 这一轮全部做完后发微信订阅提醒（截止前 3 天、关注有新文件），每天一次 |
| 03:30 | `youju cleanup` | 按保存期限删除过期的个人信息（纠错、提醒授权、埋点） |

抓取规则不变：YoujuBot 标识、遵守 robots、每站 3 秒、遇拦截即停。同一任务不重叠（上一次没跑完就跳过这次并提醒），单次最长 3 小时，超时算失败并提醒。任务日志打到容器标准输出，在云托管"服务日志"里看。提醒渠道待创始人确定；配置企业微信群机器人后，可用 `youju alert "测试文本"` 验证。`check-sources` 已发送详细提醒时，任务包装器不再重复发送通用失败提醒。

数据库迁移只在 admin 服务启动时执行，并用 MySQL 命名锁（`GET_LOCK`）：滚动发布时即使新旧两个实例同时启动，也只有一个在迁移。

## 三、环境变量

| 变量 | 服务 | 说明 |
|---|---|---|
| `YOUJU_ROLE` | 两个 | `api` 或 `admin` |
| `YOUJU_DATABASE_URL` | 两个 | 云托管 MySQL 的内网地址（控制台 MySQL 页"网络信息"），形如 `mysql+pymysql://账号:密码@内网地址:3306/youju?charset=utf8mb4`；admin 用 `youju_admin`，api 用 `youju_api`。**由创始人在云托管控制台填写，不要发给任何人** |
| `YOUJU_ADMIN_TOKEN` | admin | 核对台口令；由创始人设定，只在控制台填写；至少 32 位随机字符 |
| `YOUJU_ALERT_WEBHOOK` | admin | 可空；企业微信群机器人地址，由创始人仅在云托管控制台填写，不要发给任何人，也不要写入日志 |
| `YOUJU_TRUST_WX_HEADERS` | api | 填 `true`：用户身份只取云托管注入的 `X-WX-OPENID`（且要有 `X-WX-SOURCE`）。api 服务不填不启动 |
| `YOUJU_DEV_OPENID` | 都不填 | 本机开发用的固定身份；线上两个服务填了不启动（否则所有请求都会被当成同一个用户） |
| `YOUJU_SEND_WX_MESSAGES` | admin | 填 `true` 时定时任务真正发送订阅消息（经云托管开放接口服务）；不填只演练、不发送 |
| `YOUJU_TEMPLATE_DEADLINE`、`YOUJU_TEMPLATE_NEWDOCS` | 两个 | 订阅消息模板（JSON：模板 ID 和字段对应）。创始人在小程序后台选定模板后，由 Claude 按模板字段生成 |

**数据库账号分开（最小权限）：** 建库和建账号的语句在 `backend/deploy/mysql_accounts.sql`。admin 服务用 `youju_admin`（可建表迁移、写入抓取数据）；api 服务用 `youju_api`（能读全部表，只能写用户、关注、订阅、纠错、埋点这 5 张表）。云托管 MySQL 最多 3 个账号，正好是 root 加这两个。本机验证过：`youju_api` 删内容表、建表都会被拒绝。注意这是**按表**的权限：`youju_api` 能写这 5 张表里任何用户的行，只能写自己的数据由代码保证（每个写入都按当前用户过滤，有测试覆盖）；分开账号的作用是即使接口出问题，也改不了政府文件、截止日期这些内容表，更删不了表。

## 四、首次部署步骤

**创始人（需要实名和付费）：**
1. 开通微信云托管（[控制台](https://cloud.weixin.qq.com/cloudrun)，微信扫码），创建环境：环境名 `prod`，服务名 `admin`。第一个环境有 3 个月免费额度，删掉后不再有，不要建了又删。
2. 开通 MySQL：控制台 → MySQL → 开通，版本选 **8.0**（开通后不能改）。设一个 root 密码，自己保管。8.0 开通时要选表名是否区分大小写，选默认即可（我们的表名都是小写）。同一环境里的服务和数据库天然内网互通，不用另配网络。
3. 在 MySQL 页"数据库管理"用 root 登录，执行 `backend/deploy/mysql_accounts.sql` 的第①部分（建库、建 `youju_admin`）。
4. 生成 CLI 密钥（控制台 → 设置 → CLI 密钥，管理员扫码），在自己电脑的终端运行 `wxcloud login -a <AppID>`，按提示粘贴密钥。之后由 Claude 用命令行部署。
5. 在 `admin` 服务里填上面的环境变量（密码、口令这类只由创始人填）。

**Claude（创始人开通后）：**
1. 先发布 admin 服务：启动时自动迁移数据库。之后请创始人执行 `mysql_accounts.sql` 的第②部分（建 `youju_api`，按表授权要求表已建好）。
2. 在 admin 的"登录实例"里准备首轮数据。
   - 执行（镜像里的脚本，放到后台跑，关掉登录窗口也不中断）：

     ```sh
     nohup /app/backend/deploy/first-round.sh > /tmp/first-round.log 2>&1 &
     ```
   - 脚本依次执行：导入来源 → 抓取 → 补详情（一次补完）→ 抽截止 → 名单。
     - 每一步都经 `job.sh`，有超时、失败提醒和单任务锁，某一步失败就停下；
     - 各步日志在云托管日志里（容器标准输出）；
     - 执行期间拿着每轮任务的锁，定时任务那一轮会跳过并发一条提醒，属正常；
     - 定时任务正在跑时脚本会提示后退出，等它结束再执行。
   - 耗时参考 [上线演练记录](./上线演练记录_2026-09-28.md)：
     - 抓取约 1 分钟，首轮全部记为基线，不触发提醒；
     - 补详情一次补完约 30 分钟（定时任务每轮只补 300 份，首轮要一天多）；
     - 名单约 20 分钟。
3. 把本机核对结果导入正式库（见[本机核对台](./本机核对台.md)）：本机导出 → 正式核对台"预览导入" → "确认导入"。
4. 再发布 api 服务，关闭公网访问。
5. 小程序 `utils/config.js` 填 `cloudEnv`、`cloudService`，真机验证（验收清单 B、D 节），并完成第七节里"上线前必须通过"的实测。
6. 做一次数据库备份和恢复演练（验收清单 A6）。云托管 MySQL **没有自带备份**（官方说明要备份需另到腾讯云控制台建备份计划），要自己做：每天把数据导出存到云托管对象存储，方案见第八节。

## 五、安全和合规要求（agy 审阅后补充，Claude 已核对法条）

1. **网络日志留存不少于六个月。** 《网络安全法》（2025 年修改，2026 年 1 月 1 日起施行）第二十三条第（三）项：网络运营者应当"采取监测、记录网络运行状态、网络安全事件的技术措施，并按照规定留存相关的网络日志不少于六个月"（[网信办公布的现行全文](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm)，2026-09-28 核对）。容器标准输出的保留期限有限（**待核实**云托管日志保留期限、能否接入腾讯云日志服务 CLS 长期保存）；上线前必须落实：接口访问日志、核对台操作日志、定时任务日志至少保存 6 个月。隐私保护指引要写明日志收集的内容和期限。
2. **核对台开公网，口令要防猜（已实现）：** admin 服务启动时检查口令至少 32 位，不足不启动；口令输错限流：同一来源 10 分钟内错 5 次锁定（不设全局锁定，免得别人故意输错把管理员锁在外面；口令足够长，换来源地址也猜不中）；核对台每次操作（通过、驳回、标记变更、撤回）和每次口令错误都记审计日志（操作人、来源 IP、时间），纳入上一条的日志留存。按角色开放路径：api 服务访问核对台返回 404；admin 服务只开放核对台、管理接口和健康检查；线上两个服务都不开放接口文档（/docs、/openapi.json）。云托管能否限制公网访问来源（IP 白名单）**待核实**。
3. **数据库账号分开**（见第三节）。
4. **健康检查：** 两个服务都配置存活检查，地址 `/health`（检查数据库连接）；admin 服务还检查定时任务心跳——cron 每 5 分钟写一次，超过 15 分钟没更新就报不健康，由云托管重启容器，避免 cron 停了而每天的检查悄悄中断。
5. **名单里的个人信息：** 已处理——名单解析只取企业和机构名称列，表头是姓名、联系人、电话、身份证等的列一律丢弃；招聘、职称、考试合格人员等个人名单不解析（#45、#44）。
6. **抓取不访问内网（已实现）：** 每次连接前检查域名解析出的地址，内网、本机、云服务器元数据（169.254.169.254）等非公网地址一律不连；页面跳转、robots.txt 跳转同样逐跳检查。连接直接固定到检查过的地址（证书仍按原域名校验），检查之后 DNS 结果被改动也连不到内网；收到响应后再核对一次实际连上的地址。抓取直连，不走环境变量里的代理，也不复用连接。防止某个政府网站的域名或跳转指向云托管内部服务。
7. **线上只认平台注入的身份（已实现）：** 见第三节 `YOUJU_TRUST_WX_HEADERS`、`YOUJU_DEV_OPENID`，配错服务不启动（admin 服务开公网，设了 `YOUJU_TRUST_WX_HEADERS` 也不启动）。api 服务必须关闭公网访问：只有经 `callContainer` 进来的请求，身份由平台填写；公网请求里的这些请求头可能是请求方自己带的。

## 八、数据库（云托管 MySQL）

- **Serverless：** 算力按用量在 0.25–16 份之间自动伸缩（1 份约等于 1 核 2G）；10 分钟没有连接会自动暂停，暂停期间不收算力费，下次连接要等它恢复。代码连接时遇到"恢复中"会自动重试（`youju/db.py`）。
- **实际不会暂停：** 两个服务的健康检查都要查一下数据库（`/health` 会执行 `select 1`），所以数据库会一直按最低 0.25 份算力计费。头 3 个月在免费额度内（720 份·小时，0.25 份全天运行 90 天约 540），之后约 62 元/月（0.342 元/份·小时）。如果要省这部分，可以让健康检查不查数据库，代价是早上第一个请求要等数据库恢复几秒。
- **本机开发：** `backend/scripts/dev_mysql.sh start` 启动项目内的 MySQL 8.0（端口 33306，root 无密码，只监听本机）。
- **写法约定：** 时间一律按 UTC 存（`DATETIME(6)`，见 `youju/dbtypes.py`）；正文用 `MEDIUMTEXT`（开发库最长的正文约 40 万字节，超过 `TEXT` 的 64KB）；事务隔离用"读已提交"；网址类字段参与唯一索引，所以有长度上限（文件网址 512 字，名单来源网址 400 字，超长的跳过并记日志）。
- **备份（验收 A6，待做）：** 云托管 MySQL 没有自带备份。计划由 admin 服务每天凌晨把数据导出、压缩后存到云托管对象存储，保留 30 天，并做一次恢复演练。
