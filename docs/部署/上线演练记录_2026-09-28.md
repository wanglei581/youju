# 上线演练记录（2026-09-28，空库）

**目的：** 部署配置还没在云托管上真正跑过。先在本机从空库按部署顺序完整走一遍，记下每步耗时，把"空库、首次抓取、基线"这些没人走过的路径提前走通。

**条件：**

- 代码：main 加上 #64（核对结果导出、导入）和 #66（安全加固）的第一版，在临时目录本地合并，没有推送。#66 之后按 Codex 意见补了对端校验、DNS 限时、不走代理，另用两个真实政府网站试过，抓取正常。
- 数据库：本机新建的空库。
- 网络：本机网络。正式环境从云服务器的固定 IP 抓取，政府网站对机房 IP 可能更严，这一点只能上线后实测。

**说明：**

1. **首轮抓取：**
   - 72 个栏目中 71 个成功，识别 1630 条，入库 1575 条。
   - 首轮入库的全部算基线，不算"新增"，不会触发新文件提醒。
   - 海南工信厅的 robots.txt 当时取不到，按规范整站跳过。事后 0.2 秒就返回 404，属于偶发。
2. **补详情：**
   - 283 份成功，2 份 PDF 超过 200 页。
   - 吉林工信厅的 15 份失败，原因是 robots.txt 当时取不到。按规范当轮整站跳过，下一轮重试；事后 0.45 秒就返回 404，属于偶发。
3. **名单：**
   - 172 份名单类文件，成功解析 98 份，入库企业和机构记录 14.9 万条。
   - 下载附件 130 个（单次上限 200），没有留到下一轮的。
   - 没解析出来的原因：没有企业或机构名称的表格 94 份，旧版或专有格式 28 份，扫描件 2 份，详情不可用 7 份。另有 2 份 PDF 超过 300 页，只解析了前 300 页。

## 发现和处理

1. **首轮补详情要一天多才补完。** 补详情按文件编号顺序，每轮最多 300 份。首轮 1575 份要 6 轮，按每天 4 轮算约 1.5 天。在这之前，后导入栏目的新文件没有正文，也就抽不出截止日期。
   - 处理：首次部署时在 admin 服务里手动跑一次 `youju fetch-details --limit 2000 --workers 4`。按本次速度，约 30 分钟。
   - 之后再依次跑 `extract-deadlines` 和 `parse-lists`。
2. **内网地址检查（#66）没有误拦。** 72 个真实政府网站的域名都解析到公网地址。
3. **偶发取不到 robots.txt 的影响可控。** 当轮跳过整站，下一轮重试，栏目检查仍达标。
4. **上线第一天日历是空的。** 正式库里没有核对过的截止日期，日历只显示核对过的。
   - 处理：云托管开通前在本机核对。部署后正式环境跑完一轮，再把核对结果导入（#64，见[本机核对台](./本机核对台.md)）。
