# 有据 2.0 自建服务器：搭建、切换与回退手册

> 状态（11/5）：代码都在开关后面，默认就是云托管现在的做法，**线上什么都没动**。本手册写的是 2.0 切换那天怎么做。
> 架构是创始人 11/5 定的（"按这个做"）：**本机**（创始人的 Windows 主机）做抓取和处理，存公开数据主库和原始文件；**一台 2 核 4G 的云服务器**服务小程序，放用户数据和公开数据副本；本机每 10 分钟把公开数据的变化推到服务器，单向推送，只推公开内容。
> 1.3.1 继续在云托管上提审、运行；2.0（全国全覆盖）上线时一起切换，切换后再停掉云托管。

## 一、全貌

```
 微信小程序 2.0 ──HTTPS(wx.request)──► 云服务器（2核4G，已备案域名）
                                        ├─ Caddy：自动 HTTPS；只放行小程序接口、消息推送、本机同步
                                        ├─ api：小程序接口（自己的登录凭证）
                                        ├─ worker：AI 任务、支付、提醒、清理、备份；收本机推来的公开数据
                                        ├─ MySQL 8：用户数据 + 公开数据副本
                                        └─ 硬盘：附件副本、批量工具结果、整库备份（30 天）
                                              │ 每天加密后 ▼
                                        腾讯云 COS 归档存储：异地备份（30 天，服务器自己解不开）
 本机（Windows 11 + Docker Desktop）──每 10 分钟推公开数据（签名、只推公开表）──► 服务器 /api/sync/
   ├─ MySQL 8：公开数据主库（触发器记变更）
   ├─ worker：每天两轮抓取、补详情、附件文字、AI 核对、名单、附件副本、周报
   └─ 本机存储：附件副本、主库备份
   每 5 分钟从外面看一次服务器的 /health，不通就提醒到群里
```

**存储放哪里（创始人 11/5 定，原则是最省钱）：**

| 放哪里 | 放什么 | 为什么 |
|---|---|---|
| 服务器自己的硬盘 | 给用户下载的文件：批量工具结果（30 天后自动删）、附件副本；整库备份（30 天） | 对象存储按下载流量收钱，这部分量小，放本机硬盘不花流量费 |
| 腾讯云 COS（低频存储） | 只放**加密后**的每天整库备份（30 天）；以后可选再放一份附件原件的冷备份 | 冷数据便宜；低频能直接下载，本机才拉得到副本（归档要先"恢复"几小时） |
| 本机（Windows 主机） | 原始网页、附件原件、公开数据主库；**加密**整库备份的第二份副本（密文，本机没有私钥，解不开） | 本机不花钱、空间大；用户数据的明文从不到本机 |
| 云托管对象存储 | 切换当天搬空（近期的结果文件、访问日志归档、附件副本、近 7 天的整库备份），跟着云托管一起注销 | 见第六节第 3 步 |

COS 价格参考（2025 年一篇文章里的数字，**买的时候以腾讯云官网价格页为准**）：标准约 0.099 元/GB/月、低频 0.08、归档 0.03，另按下载流量收费。我们的备份一份几十到几百 MB、留 30 份，每月几毛到几块钱。

谁在哪里做：

| 活 | 云托管现在 | 2.0 |
|---|---|---|
| 抓取、补详情、附件文字、截止抽取、AI 核对、名单、附件副本、周报、原网页检查 | admin | **本机** |
| 小程序接口、AI 工具任务、支付、订阅提醒、纠错复查、清理、访问日志归档、备份 | api / admin | **服务器** |
| 核对台改公开数据（截止核对、下架、类型……） | admin | **本机**（服务器上会拒绝，`YOUJU_PUBLIC_REPLICA`） |
| 核对台处理纠错、发票（用户数据） | admin | **服务器**（SSH 隧道访问） |

## 二、开关一览（默认都是现在的做法）

| 环境变量 | 默认（云托管） | 2.0 服务器 | 2.0 本机 | 作用 |
|---|---|---|---|---|
| `YOUJU_HOSTING` | cloudrun | self | self | self 时不信任任何 X-WX-* 请求头 |
| `YOUJU_SESSION_LOGIN` | false | true | — | wx.login → 换 openid → 加密的登录凭证（7 天） |
| `YOUJU_SESSION_SECRET` | — | 随机 64 位 | — | 凭证的密钥；换掉等于让所有人重新登录（无感） |
| `YOUJU_WX_OPEN_API` | cloudrun | token | — | 用 AppSecret 取 stable_token，自己带 access_token |
| `YOUJU_WX_APPID` / `YOUJU_WX_APPSECRET` | — | 创始人给 | — | 登录、取 access_token、付款换会话密钥 |
| `YOUJU_WX_PUSH_MODE` | cloudrun | signed | — | 消息推送只收安全模式：msg_signature 验签、解密、加密回包（明文模式的签名不覆盖包体，不用） |
| `YOUJU_WX_PUSH_TOKEN` / `_AES_KEY` | — | 生成后填进小程序后台 | — | |
| `YOUJU_STORAGE_BACKEND` | cloudbase | disk | disk | 对象存储换成服务器硬盘（也支持 s3：COS 带密钥、MinIO） |
| `YOUJU_STORAGE_DIR` | — | /data/storage | /data/storage | |
| `YOUJU_STORAGE_BUCKET` | youju-self | 原云托管存储桶名 | 同左 | 文件 ID 里的存储桶一段，填原来的，库里的旧文件 ID 一字不变 |
| `YOUJU_CLIENT_IP_HEADER` | x-original-forwarded-for | x-forwarded-for | — | 来源 IP 取哪个头（Caddy 覆盖写入） |
| `YOUJU_LOG_MASK_IP` | false | true | — | 容器日志里的 IP 只留前一半（库里照旧完整留 190 天） |
| `YOUJU_SYNC_SECRET` | — | 随机 64 位 | 同一个 | 本机推公开数据的签名密钥；服务器配了才开放 /api/sync/ |
| `YOUJU_SYNC_URL` | — | — | https://接口域名 | |
| `YOUJU_PUBLIC_REPLICA` | false | true | — | 服务器上不能改公开数据 |
| `YOUJU_OFFSITE_*` | — | COS 归档存储桶、子账号密钥、age 公钥 | — | 异地备份 |
| `YOUJU_CRONTAB` | deploy/crontab | deploy/selfhost/server/crontab | deploy/selfhost/local/crontab | 定时任务表 |
| 小程序 `config.apiBaseUrl` | ''（走云托管） | https://接口域名 | | 填了就 wx.request 直连、自动登录 |

配错（比如自建服务器还信任请求头、只填了一半的密钥）程序直接不启动，报错写明缺哪一项。

## 三、创始人要提供或亲自操作的（按先后）

1. **定一个接口域名并备案**（1–3 周，可以现在就开始）：如 `api.你的域名`。服务器买在哪个腾讯云账号下，就在那个账号里备案（轻量服务器要买满 3 个月才能备案）。备案好以后把域名解析（A 记录）到服务器的公网 IP。
2. **买服务器**：腾讯云轻量应用服务器 2 核 4G，系统选 Ubuntu 24.04（或带 Docker 的镜像），地域选离用户近的（如上海、广州）。买好后把**公网 IP** 告诉我；防火墙只开 22、80、443。要我来装的话，在服务器上加我给你的 SSH 公钥（只给这一台）。
3. **AppSecret**：小程序后台"开发管理 → 开发设置 → AppSecret"。**先问我线上现在有没有在用**：如果云托管上已经填了 `YOUJU_WX_APPSECRET`，直接用那一个，**不要点"重置"**（重置后旧的立刻失效，线上付款会出错）。拿到后只填进服务器的 `.env`，不要发在聊天里。
4. **IP 白名单**：同一页"IP 白名单"里加服务器的公网 IP（不加的话取 access_token 报 40164，付款、内容安全、提醒全都不能用）。
5. **服务器域名**：小程序后台"开发管理 → 开发设置 → 服务器域名"，request 合法域名加 `https://api.你的域名`（一个月能改 50 次，可以提前加，不影响 1.3.1）。
6. **消息推送**（切换当天做，见第六节）：小程序后台"开发管理 → 消息推送"，URL 填 `https://api.你的域名/api/wx/push`，Token、EncodingAESKey 用我生成、填在服务器 `.env` 里的那两个，**消息加密方式选"安全模式"**，数据格式 **JSON**。
7. **异地备份**：腾讯云对象存储 COS 建一个存储桶（地域和服务器不同更好，存储类型"**低频**"），再建两个子账号：一个只给这个存储桶的上传、列表、删除权限，密钥填进服务器 `.env`；另一个只给列表、下载权限，密钥填进 Windows 主机的 `.env`（本机每天下一份密文再留一份）。
8. **备份密钥**：在 Windows 主机上（装好 Docker 以后）运行 `docker run --rm youju-selfhost age-keygen`，把显示的整段（`# public key: age1…` 和 `AGE-SECRET-KEY-…`）存进你的密码管理器，再抄一份放 U 盘。**私钥只在你手里**，服务器上只填公钥（`age1…` 那一行）。丢了私钥，异地备份就解不开了。
9. **镜像仓库**（建议）：腾讯云"容器镜像服务 个人版"开一个命名空间（免费），服务器和 Windows 主机都从这里拉镜像。登录密码只在机器上 `docker login`，不写进文件。
10. **Windows 主机**：装 Docker Desktop（WSL2），按第五节运行一键脚本。
11. **2.0 小程序提审**：`config.apiBaseUrl` 填接口域名、`cloudEnv` 清空，隐私保护指引升新版本（草稿见 `docs/合规/隐私保护指引_2.0自建服务器_草稿.md`，要你先定稿）。

## 四、服务器搭建（有 SSH 我来做；没有的话你照着做）

1. 系统：`sudo apt update && sudo apt -y upgrade`，装 Docker（`sudo apt install -y docker.io docker-compose-v2`），开自动安全更新（`sudo apt install -y unattended-upgrades`），加 2G 交换分区（内存只有 4G，构建和偶发高峰时防止被杀）。
2. 防火墙：轻量服务器控制台只放行 22（最好只放你的 IP）、80、443。MySQL、核对台都不对外。
3. 代码和镜像：把 `backend/deploy/selfhost/` 拷到服务器（如 `/opt/youju/`）；镜像从镜像仓库拉，或在服务器上构建：`sh /opt/youju/build.sh`（要整个代码仓库）。
4. 配置：`cd /opt/youju/server && cp env.example .env && chmod 600 .env`，按注释填好（随机串用 `openssl rand -hex 32`）。
5. 启动：`docker compose up -d`；`docker compose ps` 三个服务都 healthy；`curl https://api.你的域名/health` 回 `{"status":"ok"}`。
6. 核对台：`ssh -L 8080:127.0.0.1:8080 服务器`，本机浏览器开 `http://127.0.0.1:8080/admin`（只能处理纠错、发票；改公开数据会被拒）。

内存预算（2 核 4G）：MySQL 限 1.4G（缓冲池 768M、关掉性能统计）、api 512M、worker 640M、Caddy 128M，合计约 2.7G，留 1.3G 给系统。抓取和附件解析都不在服务器上，服务器只有接口、AI 任务（调模型、不占本机算力）和每天几次的批处理。

硬盘：数据库现在约 0.45G（11/4 线上快照，名单占 86%）；全国全覆盖按每天 1000–2000 份估算，数据库一年多 50–120G。轻量服务器自带 60–80G 的盘一年左右要加数据盘，或只在服务器上留近半年的附件副本（数据保留规则等创始人定）。

## 五、本机（Windows 主机）搭建

机器：Windows 11、16G 内存、空余约 500G。只能 UU 远程，所以全部做成一键脚本。

1. 装 **Docker Desktop**（安装时选 WSL2）。装好后打开设置：
   - General：勾选 **Start Docker Desktop when you sign in**；
   - Resources → Advanced：**Disk image location** 改到空间大的盘（如 `D:\DockerData`），内存给 **8 GB**、CPU 给一半。
2. 把我给的 `local` 文件夹（含 `setup.ps1`、`docker-compose.yml`、`env.example`、`mysql.cnf`、`crontab`，以及没有镜像仓库时的 `youju-selfhost.tar`）用 UU 远程传到 `D:\youju\local`。
3. 在这个文件夹里右键"在终端中打开"，运行：`powershell -ExecutionPolicy Bypass -File .\setup.ps1`。脚本会：检查 Docker → 生成 `.env`（数据库密码和核对台口令自动生成，服务器地址和同步密钥要你粘贴）→ 载入镜像 → 启动 → 等健康 → 问你要不要把电脑设成插电源时不睡眠。
4. 电脑要一直开着、登录着（Docker Desktop 在登录后启动）；Windows 更新重启后会自动恢复（容器设的是 `restart: unless-stopped`）。建议在"Windows 更新 → 高级选项"里设好"活动时间"，别在每天 6:30、20:30 的抓取时段重启。
5. 核对台：这台电脑的浏览器开 `http://127.0.0.1:8080/admin`，口令在 `.env` 的 `YOUJU_ADMIN_TOKEN`。
6. 起步导入（切换当天，见第六节第 5 步）。

## 六、切换步骤（2.0 上线那天）

**原则：**用户数据只能有一份在写。先停云托管的写入**和定时任务**，最后一份整库备份恢复到服务器，然后放 2.0。整段停写安排在夜里（如 1:00–2:00），预计 30–60 分钟。

**提前一周：**
- 服务器、本机都按第四、五节搭好；用最近一份云托管整库备份在服务器上**预演一遍**下面第 2–5 步（数据之后会被正式的覆盖）；
- 2.0 小程序上传体验版、连这台服务器，走一遍主路径（登录、同意、关注、纠错、AI、批量工具、购买的下单前一步）；
- 2.0 小程序提审。审核期间审核员连的是这台服务器（预演的数据），1.3.1 用户照旧连云托管，互不影响；
- 服务器、本机、云托管三处代码版本一致（恢复要求迁移版本相同；同步会核对两边的迁移版本，不一致就不推）。云托管那次发版要带上这个分支（`YOUJU_CRONTAB` 开关和 `deploy/selfhost/crontab.idle` 在里面）。

**切换当晚（审核通过以后）：**

1. **停云托管的写入和定时任务**：
   - admin 服务的环境变量加 `YOUJU_CRONTAB=/app/backend/deploy/selfhost/crontab.idle`（只写心跳，不跑任何任务：付款补单、AI 任务、提醒、抓取、清理全停）、去掉 `YOUJU_SEND_WX_MESSAGES`，重新发布 admin；在"登录实例"里 `crontab -l` 核对只剩心跳那一行。**这个设置一直保持到注销云托管**，不然云托管会拿冻结的旧库接着发提醒、补单、跑 AI 任务，和服务器两边一起干；
   - api 服务的实例数调成 0（1.3.1 用户这时看通知不受影响：首页、检索、详情走 admin；关注、纠错、AI、付款会提示网络不好）。等 1 分钟，让进行中的请求结束。
2. **最后一份整库备份**：云托管 admin 服务"登录实例"里运行 `/app/backend/deploy/job.sh backup`，在云托管控制台"对象存储"下载 `backups/youju-当天日期.jsonl.gz`。
3. **搬空云托管的对象存储**（它跟着云托管一起注销，留下的就没了）：同一个"登录实例"里运行
   - `youju storage-export`：批量工具结果 `advisor/out/`、访问日志归档 `logs/`（要留够 6 个月）、附件副本 `attachments/`；
   - `youju storage-export --prefix backups/ --since-days 7`：近 7 天的整库备份（回退用）。
   在控制台"对象存储"下载这两个 `exports/storage-时间.tar.gz`。导入时两个包都导（第 4 步）。
4. **恢复到服务器**（我来做，或你照做）：
   ```
   # 停掉接口和定时任务（不让它们在恢复前往库里写东西）
   docker compose stop api worker caddy
   # 清掉预演留下的存储文件（预演那一周 worker 归档过访问日志、生成过结果文件，留着会挡住
   # 云托管那边真的同名文件）
   docker compose run --rm worker sh -c 'rm -rf /data/storage/*' 
   # 清空预演的数据：删库重建，迁移到和备份同一个版本（代码版本要和云托管线上一样）
   docker compose exec mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "DROP DATABASE youju; CREATE DATABASE youju CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin; GRANT ALL ON youju.* TO \"youju\"@\"%\";"'
   # 一次性容器（不起定时任务）：迁移、恢复、导入存储里的文件
   docker compose run --rm -v "$PWD:/move" worker youju db-upgrade
   docker compose run --rm -v "$PWD:/move" worker youju restore --fresh /move/youju-当天日期.jsonl.gz
   docker compose run --rm -v "$PWD:/move" worker youju storage-import --file /move/storage-时间.tar.gz
   docker compose run --rm -v "$PWD:/move" worker youju storage-import --file /move/storage-备份那一包.tar.gz
   docker compose up -d
   ```
   `youju restore` 会核对条数、外键和每张表的 SHA-256，全部对上才提交；对不上整个回滚，库保持空的。`--fresh` 只删迁移写进去的种子行，别的表有数据就拒绝。两个下载的文件先拷到服务器的这个目录（`scp`），用完删掉。
5. **本机起步**：服务器上 `docker compose run --rm -v "$PWD:/move" worker youju sync-export --output /move/youju-sync-export.jsonl.gz`，取出来传到 Windows 主机（UU 远程传文件）。本机先停定时任务（导入到对上进度之间不能有新变更，不然会被当成"已经同步过"而漏推），用一次性容器做，做完再启动：
   ```
   docker compose stop worker
   docker compose run --rm -v ${PWD}:/move worker youju sync-import --file /move/youju-sync-export.jsonl.gz
   docker compose run --rm worker youju sync-setup
   docker compose run --rm worker youju sync-push --mark-synced
   docker compose start worker
   ```
   导出的是全部公开表（下架的照样过来，下架备注清空；用户线索生成的截止日期不过来），本机各表的自增编号起点设成服务器的，以后本机新建的行不会和服务器撞编号。导入后两边一致，`--mark-synced` 直接把服务器进度对齐，不用全推。
6. **消息推送换地址**：云托管控制台"设置 → 其他设置 → 消息推送"删掉原来的配置；小程序后台"开发管理 → 消息推送"按第三节第 6 条填好、提交（微信会先发一次验证，服务器验签通过才能保存）。
7. **发布 2.0**：小程序后台把审核通过的 2.0 全量发布。打开过小程序的用户会看到"新版本已准备好"（app.js 的更新提示），下次打开就是 2.0；2.0 第一次请求会自动登录、要求同意新版隐私保护指引。
8. **上线后马上走一遍**：用真机打开 2.0：首页、检索、详情、附件打开、同意协议、关注、纠错、AI 解读、我的订单。服务器上 `docker compose logs --since 10m api worker` 没有报错。

## 八、日常运维

> 2.0 暂时不跑"纠错复查截止日期"（triage-feedback）：它把复查结果写在截止日期上，那是本机同步过来的行，服务器上改了会被下次同步盖掉。要改成只把结果记在纠错上以后再加回服务器的定时任务。


- **备份**：服务器每天 4:00 整库备份（存服务器硬盘，保留 30 天）→ 4:40 校验 → 5:10 用 age 加密后传 COS 低频存储（保留 30 天）→ 本机 6:00 把这份密文下到本机再留一份（`youju offsite-pull`，保留 30 天）。本机主库（公开数据）每天 4:00 另备份到本机存储；本机坏了还能从服务器导回公开数据（`youju sync-export`）。
- **从异地备份恢复**：从 COS（低频能直接下载）或本机的 `offsite-backups/` 取一份 `.age` 文件，在创始人电脑上 `age -d -i 私钥文件 youju-日期.jsonl.gz.age > backup.jsonl.gz`，再在刚迁移好的空库上 `youju restore --fresh backup.jsonl.gz`。
- **监控**：本机每 5 分钟从外面看一次服务器的接口服务和定时任务服务（`/health`、`/health/worker`），连续 2 次不通提醒到群里、恢复了再说一声；容器自带健康检查，坏了自动重启；每天早上 9:00 服务器、8:00 本机各发一份运维日报；任务失败由 job.sh 提醒。
- **同步**：本机每 10 分钟推一次（`youju sync-push`），失败提醒。查进度：本机 `docker compose exec worker youju sync-status`（待推的变更、两边各表条数差）。
  - 两边条数对不上（本机库是好的）：先 `youju sync-push --full --dry-run` 看服务器上多出来多少行，再 `youju sync-push --full`；要删的超过 200 行且超过 1% 会停下，确认后加 `--force`。
  - **本机库坏了、从备份恢复了、重装了**：不能推（程序会拦下：本机的自增编号落到服务器已有的以下），也**不能用 `--full`**（会把服务器上本机没有的行删掉，连带用户数据里指向它们的）。按第六节第 5 步重新起步：从服务器导出、本机导入。
- **升级**：构建新镜像（`build.sh`，推到镜像仓库）→ 服务器先升 worker（会跑迁移）再升 api：`docker compose pull && docker compose up -d worker && docker compose up -d api` → 本机升 worker。两边迁移版本一致前，同步会停下并提醒，不会推错。删表、删列的迁移照云托管的规矩反过来（先 api 后 worker）。
- **证书**：Caddy 自动申请和续期，不用管；要 80、443 端口一直开着。
- **日志**：容器日志每个服务最多 5×20MB 轮转；访问日志在库里留 190 天（每天归档到存储），容器日志里的 IP 只留前一半；Caddy 不记访问日志。
- **系统补丁**：unattended-upgrades 自动装安全更新；Docker 镜像每次升级时会带上基础镜像的更新。
