> 状态（11/5）：代码都在开关后面，默认就是云托管现在的做法，**线上什么都没动**。本手册写的是 2.0 切换那天怎么做。
> 架构是创始人 11/5 定的（"按这个做"）：**本机**（创始人的 Windows 主机）做抓取和处理，存公开数据主库和原始文件；**一台 2 核 4G 的云服务器**服务小程序，放用户数据和公开数据副本；本机每 10 分钟把公开数据的变化推到服务器，单向推送，只推公开内容。
> 1.3.1 继续在云托管上提审、运行；2.0（全国全覆盖）上线时一起切换，切换后再停掉云托管。

> **11/9（D-126）：服务器不另买，用创始人现有的一台腾讯云轻量服务器（和别的项目共用），装法、改了什么、怎么回退见第十节。**第三、四节写的是单独一台服务器的做法，第六节起的切换、回退、运维两种都适用（命令里的 `docker compose` 在共用服务器上换成 `youju-shared.sh` 的子命令）。

## 一、全貌

```
 微信小程序 2.0 ──HTTPS(wx.request)──► 云服务器（2核4G，已备案域名）
                                        ├─ Caddy：自动 HTTPS；只放行小程序接口、消息推送、本机同步
                                        ├─ api：小程序接口（自己的登录凭证）
                                        ├─ worker：AI 任务、支付、提醒、清理、备份；收本机推来的公开数据
                                        ├─ MySQL 8：用户数据 + 公开数据副本
                                        └─ 硬盘：附件副本、批量工具结果、整库备份（30 天）
                                              │ 每天加密后 ▼
                                        腾讯云 COS 低频存储：异地备份（30 天，服务器自己解不开）
 本机（Windows 11 + WSL 里的 Docker）──每 10 分钟推公开数据（签名、只推公开表）──► 服务器 /api/sync/
   ├─ MySQL 8：公开数据主库（触发器记变更）
   ├─ worker：每天两轮抓取、补详情、附件文字、AI 核对、名单、附件副本、周报
   └─ 本机存储：附件副本、主库备份
   每 5 分钟从外面看一次服务器的 /health，不通就提醒到群里
```

**存储放哪里（创始人 11/5 定，原则是最省钱）：**

| 放哪里 | 放什么 | 为什么 |
|---|---|---|
| 服务器自己的硬盘 | 给用户下载的文件：批量工具结果（30 天后自动删）、附件副本；整库备份（30 天） | 对象存储按下载流量收钱，这部分量小，放本机硬盘不花流量费 |
| 腾讯云 COS（低频存储） | 只放**加密后**的每天整库备份（30 天）；以后可选再放一份附件原件的冷备份 | 冷数据便宜；低频能直接下载，本机才拉得到副本（归档要先"恢复"几小时） |
| 本机（Windows 主机） | 原始网页、附件原件、公开数据主库；**加密**整库备份的第二份副本（密文，本机没有私钥，解不开） | 本机不花钱、空间大；用户数据的明文从不到本机 |
| 云托管对象存储 | 首发前的导出窗口带走访问日志归档、附件副本；最后一份整库备份试恢复后加密归档（D-127）。跟着云托管一起注销 | 见第六节 |

COS 价格参考（2025 年一篇文章里的数字，**买的时候以腾讯云官网价格页为准**）：标准约 0.099 元/GB/月、低频 0.08、归档 0.03，另按下载流量收费。我们的备份一份几十到几百 MB、留 30 份，每月几毛到几块钱。创始人 11/5 说的是归档，做的时候改成低频：备份只留 30 天，归档最短按 90 天计费，而且读之前要先恢复（标准取回 3–5 小时），本机每天拉不到副本；低频最短按 30 天计费、能直接读（腾讯云《存储类型概述》，2026-10-12 版）。

谁在哪里做：

| 活 | 云托管现在 | 2.0 |
|---|---|---|
| 抓取、补详情、附件文字、截止抽取、AI 核对、名单、附件副本、周报、原网页检查 | admin | **本机** |
| 小程序接口、AI 工具任务、支付、订阅提醒、纠错复查、清理、访问日志归档、备份 | api / admin | **服务器** |
| 核对台改公开数据（截止核对、下架、类型……） | admin | **本机**（服务器上会拒绝，`YOUJU_PUBLIC_REPLICA`） |
| 核对台处理纠错、发票（用户数据） | admin | **服务器**（SSH 隧道访问） |

## 三、创始人要提供或亲自操作的（按先后）

1. **买服务器**（备案要用它，所以先买）：腾讯云轻量应用服务器 2 核 4G（云服务器 CVM 也行），**中国大陆地域、包年包月、买满 3 个月**（备案期间还要剩 1 个月以上），系统选 Ubuntu 24.04（或带 Docker 的镜像），地域选离用户近的（如上海、广州）。买好后把**公网 IP** 告诉我；防火墙只开 22、80、443。要我来装的话，在服务器上加我给你的 SSH 公钥（只给这一台）。
2. **定一个接口域名并备案**（1–3 周）：如 `api.你的域名`。在买服务器的那个腾讯云账号里、用这台服务器办备案：域名没在腾讯云备过案的，要先有这样一台备案用的服务器；别家备过案、转到腾讯云的"接入备案"也一样（腾讯云备案文档 243/18908、243/37403，2026-10-16 版）。备案好以后把域名解析（A 记录）到服务器的公网 IP。
3. **AppSecret**：小程序后台"开发管理 → 开发设置 → AppSecret"。D-127 以后云托管不用了，可以重置一个新的（重置后旧的立刻失效）。只在服务器的网页终端里用 `youju-shared.sh secret YOUJU_WX_APPSECRET` 录（第六节第 11 步），不要发在聊天里。
4. **IP 白名单**：同一页"IP 白名单"里加服务器的公网 IP（不加的话取 access_token 报 40164，付款、内容安全、提醒全都不能用）。
5. **服务器域名**：小程序后台"开发管理 → 开发设置 → 服务器域名"，request 合法域名加 `https://api.你的域名`（一个月能改 50 次，可以提前加，不影响 1.3.1）。
6. **消息推送**（切换当天做，见第六节）：小程序后台"开发管理 → 消息推送"，URL 填 `https://api.你的域名/api/wx/push`，Token、EncodingAESKey 用我生成、填在服务器 `.env` 里的那两个，**消息加密方式选"安全模式"**，数据格式 **JSON**。
7. **异地备份**：腾讯云对象存储 COS 建一个存储桶（地域和服务器不同更好，存储类型"**低频**"），再建两个子账号：一个只给这个存储桶的上传、列表、删除权限，密钥填进服务器 `.env`；另一个只给列表、下载权限，密钥填进 Windows 主机的 `.env`（本机每天下一份密文再留一份）。
8. **备份密钥**：本机端装好以后，你**自己**在 Windows 主机上（UU 远程里）运行 `wsl -d youju -u root -e docker run --rm --log-driver none youju-selfhost:latest age-keygen`（`--log-driver none`：不写 Docker 日志，私钥不会留在本机磁盘上；不要让 Codex 或别的 AI 代跑：私钥会进它们的会话记录），把显示的整段（`# public key: age1…` 和 `AGE-SECRET-KEY-…`）存进你的密码管理器，再抄一份放 U 盘，然后关掉这个终端窗口。**私钥只在你手里**，服务器上只填公钥（`age1…` 那一行）。丢了私钥，异地备份就解不开了。
9. **镜像仓库**（建议）：腾讯云"容器镜像服务 个人版"开一个命名空间（免费），服务器和 Windows 主机都从这里拉镜像。登录密码只在机器上 `docker login`，不写进文件。
10. **Windows 主机**：用管理员终端运行一次 `wsl --install --no-distribution` 并重启（只有这一步要你做）；其余按第五节由 Codex 跑一键脚本 `setup-wsl.ps1`。
11. **首发版提审**（D-127 以前写的是 2.0）：`config.apiBaseUrl` 填接口域名、`cloudEnv` 清空，隐私保护指引升新版本（草稿见 `docs/合规/隐私保护指引_2.0自建服务器_草稿.md`，要你先定稿）。

## 四、服务器搭建（有 SSH 我来做；没有的话你照着做）

1. 系统：`sudo apt update && sudo apt -y upgrade`，装 Docker（`sudo apt install -y docker.io docker-compose-v2`），开自动安全更新（`sudo apt install -y unattended-upgrades`），加 2G 交换分区（内存只有 4G，构建和偶发高峰时防止被杀）。
2. 防火墙：轻量服务器控制台只放行 22（最好只放你的 IP）、80、443。MySQL、核对台都不对外。
3. 代码和镜像：把 `backend/deploy/selfhost/` 拷到服务器（如 `/opt/youju/`）；镜像从镜像仓库拉，或在服务器上构建：`sh /opt/youju/build.sh`（要整个代码仓库）。
4. 配置：`cd /opt/youju/server && cp env.example .env && chmod 600 .env`，按注释填好（随机串用 `openssl rand -hex 32`）。
5. 启动：`docker compose up -d`；`docker compose ps` 三个服务都 healthy；`curl https://api.你的域名/health` 回 `{"status":"ok"}`。
6. 核对台：`ssh -L 8080:127.0.0.1:8080 服务器`，本机浏览器开 `http://127.0.0.1:8080/admin`（只能处理纠错、发票；改公开数据会被拒）。

内存预算（2 核 4G）：MySQL 限 1.4G（缓冲池 768M、关掉性能统计）、api 512M、worker 640M、Caddy 128M，合计约 2.7G，留 1.3G 给系统。抓取和附件解析都不在服务器上，服务器只有接口、AI 任务（调模型、不占本机算力）和每天几次的批处理。

硬盘：数据库现在约 0.45G（11/4 线上快照，名单占 86%）；全国全覆盖按每天 1000–2000 份估算，数据库一年多 50–120G。轻量服务器自带 60–80G 的盘一年左右要加数据盘，或只在服务器上留近半年的附件副本（数据保留规则等创始人定）。

## 五、本机（Windows 主机）搭建

机器（11/8 查过）：Windows 11、8 核、16G 内存。数据放 **E 盘**（空间大；D 盘太小，不能用）。只能 UU 远程，所以全部做成一键脚本，由 Windows 上的 Codex 照着跑。

Windows 版本：创始人 11/8 定「不用管 Windows 版本」，照现在的版本装（WSL 方式不受影响）；以后升级系统时，升到微软还在支持的版本。

**推荐：WSL 方式（`setup-wsl.ps1`，不要 Docker Desktop）。** Docker Desktop 4.49 以后要 Windows 11 23H2 以上，这台的版本不够；WSL 方式在 WSL 2 里装一个 Ubuntu 24.04，里面直接装 Docker 引擎，Windows 不用升级。

1. **开启 WSL（创始人亲自做一次，要管理员）**：开始按钮右键「终端(管理员)」，运行 `wsl --install --no-distribution`，重启。
2. 安装包 `youju-local-<版本>.zip`（`make-local-package.sh` 打的，里面是一个 `local` 文件夹：两个一键脚本、compose 文件、程序源码，和起步用的 `youju-sync-export.jsonl.gz`）用 UU 远程传到 Windows，解压到 `E:\youju`（得到 `E:\youju\local`）。
3. 在 `E:\youju\local` 里打开普通终端（**不要用管理员**，脚本会拦下），运行 `powershell -ExecutionPolicy Bypass -File .\setup-wsl.ps1`。中途不用输入，第一次 15–30 分钟，输出另存在 `E:\youju\setup-wsl.log`。数据固定放在安装包所在盘的 `\youju\wsl`，和安装包解压在哪个子文件夹无关（要放别处加 `-DataRoot`）：
   - 从中科大镜像站下载 Ubuntu 24.04 的 WSL 包（约 370 MB，按 Ubuntu 官方校验值核对），导入成发行版 `youju`，放在 `E:\youju\wsl`（数据库、原始文件都在里面的 `ext4.vhdx`）；
   - 发行版里：用腾讯云软件源装 Docker 引擎；Docker Hub 经 DaoCloud 镜像站拉（基础镜像都按摘要锁定，内容会校验）；用源码构建镜像；生成 `/opt/youju/local/.env`（数据库密码、核对台口令随机生成；服务器地址、同步密钥先留空）；先建表、导入起步数据，再启动定时任务；
   - 装 Docker 之前先加好并启动计划任务 `youju-wsl`：登录 Windows 后在隐藏窗口里让发行版一直开着（WSL 里没有进程时会自己关掉），WSL 被关掉（更新、`wsl --shutdown`）30 秒后自动再开；
   - 起步数据只在「库是空的、还没配服务器」时自动导入；以后重跑（升级）库里有数据就不导。
4. 电脑要一直开着、**登录着**：计划任务在登录后才启动，重启后停在登录界面时本机端不会自己起来，在 UU 远程里登录一下就行。「插入电源时睡眠」设为「从不」（创始人自己改）。别在每天 6:30、20:30 的抓取时段重启。
5. 核对台：这台电脑的浏览器开 `http://127.0.0.1:8080/admin`；口令用 `wsl -d youju -u root -e grep YOUJU_ADMIN_TOKEN /opt/youju/local/.env` 看。
6. 日常命令都在发行版里：`wsl -d youju -u root --cd /opt/youju/local -e bash` 进去，再 `docker compose ps`、`docker compose logs worker --tail 100`。升级：先删掉 `E:\youju\local`（里面只有安装包，数据在 `E:\youju\wsl`），把新安装包解压到 `E:\youju`，重跑 `setup-wsl.ps1`（删掉旧源码重新构建镜像、迁移、重建容器；数据和 `.env` 不动）。
7. **服务器买好以后**：在 `/opt/youju/local/.env` 填上 `YOUJU_SYNC_URL`、`YOUJU_SYNC_SECRET`（和服务器的一样），按第八节"本机重新起步"起步。先单独跑过一段的，起步前清掉本机的试运行数据（导入只接受空库，编号要和服务器一致）：`docker compose down -v`（删掉 mysql、storage 两个卷），再 `docker compose up -d --wait mysql`、`docker compose run --rm worker youju db-upgrade`（建表），然后照第八节"本机重新起步"导入服务器的导出。清空以后、导入之前如果重跑了 `setup-wsl.ps1`，它看到库是空的、又配了服务器，只会提示手动起步，不会自动导入，也不会启动 worker。

**另一种：Docker Desktop（`setup.ps1`，要 Windows 11 23H2 以上）。**

1. 装 Docker Desktop（选 WSL 2）。设置里：General 勾选 **Start Docker Desktop when you sign in**；Resources → Advanced 把 **Disk image location** 改到数据盘（如 `E:\DockerData`）。
2. 安装包解压到 `E:\youju`（得到 `E:\youju\local`），在 `local` 里打开终端，运行 `powershell -ExecutionPolicy Bypass -File .\setup.ps1`：检查 Docker → 生成 `.env`（服务器地址、同步密钥要粘贴，没买服务器直接回车）→ 用源码构建镜像 → 启动 → 等健康 → 问要不要把电脑设成插电源时不睡眠。
3. 起步导入照脚本最后打印的命令做。

## 六、首发前切换（D-127：首发就用自己的服务器）

> 创始人 11/11 定（D-127，"按推荐"）：1.0 首发**不再用微信云托管**。小程序直连第十节那台服务器，用户数据只在服务器上；本机照旧抓取、推公开数据；云托管只恢复 1–2 天用来导出（导出的原则：一样都不能丢），第 13 步再问创始人要不要注销。前提是 1.3.1 没提审、没有真实用户：导出脚本打印汇总数（只有数字）来核对。

    - 离这个期限不到 7 天还没记"删了"，每天 5:50 的 `archive-prune` 先发提醒（告警通道；后面删到期存档出错也照发，发不出去这个任务就按失败退出），过了期限照样每天提醒。注销了运行 `youju-shared.sh cloudrun-gone deregistered`，只删了库运行 `youju-shared.sh cloudrun-gone deleted`，记下来以后不再提醒。

## 七、回退

- **提审前**：能退。云托管环境和数据库在第六节第 13 步之前一直留着（导出只读；第 9 步只删了对象存储里已经存档到服务器的副本，库没动，admin 调回 1 以后每天的备份照常做）。第 9 步以后再退回云托管有两样回不去：批量工具的旧结果下载不了（任务记录还在，结果文件删了；服务器上的加密包是存档，不放回去），访问日志的旧归档不在云托管上了（在服务器的存档里）；都是测试期创始人和测试的人的数据。服务器上的改动按第十节第 2 小节回退，`.env` 用 `env-set`、`env-unset` 改回。
- **第 9 步以后退回过云托管，再切回服务器**：退回期间云托管又有了新数据、新的每日备份，所以第六节第 4–9 步要整个重走一遍（停写或核对新写入、导出、下载、试恢复、存档、带下架记录、清理），不能只清理。重走前先 `youju-shared.sh export-reset`：清掉上一批"存档过"的标记，不然 `fetch-export` 会拒绝；明文的备份、交易记录还在它就停下。新的一批照常加密存档，存档名里带这一批的导出时间，不盖掉上一批（上一批的批量工具结果第 9 步已从云托管删掉，第二批里没有它们）：各份照样按自己的起算日到期，云托管删库的最晚日期按新的最后一份整库备份重算。
- **发布以后**：首发没有上一个版本可以回退，在服务器上修好再发版；要先停接口就 `cd /opt/youju/server && docker compose stop api`（数据都留着）。数据出问题按第八节"从异地备份恢复"。

## 八、日常运维

> 2.0 暂时不跑"纠错复查截止日期"（triage-feedback）：它把复查结果写在截止日期上，那是本机同步过来的行，服务器上改了会被下次同步盖掉。要改成只把结果记在纠错上以后再加回服务器的定时任务。


- **备份**：服务器每天 4:00 整库备份（存服务器硬盘，保留 30 天）→ 4:40 校验 → 5:10 用 age 加密后传 COS 低频存储（保留 30 天）→ 本机 6:00 把这份密文下到本机再留一份（`youju offsite-pull`，保留 30 天）。本机主库（公开数据）每天 4:00 另备份到本机存储；本机坏了还能从服务器导回公开数据（`youju sync-export`）。本机的密文副本从 COS 下载，按外网下行流量计费（约 0.5 元/GB，以官网为准；一份几十到几百 MB，每月几块钱）；也可以改成从服务器拉（轻量服务器套餐含流量），但本机要多一个能连服务器的凭据。为了保持「本机只往服务器推、不从服务器拿任何东西」，先从 COS 拉。
- **首发前的旧库存档**（D-127，第六节第 6、7 步）：在服务器存储和异地的 `archive/` 下，文件名里写着到期日；每天 5:50 的 `archive-prune` 删到期的（两边各删各的），删了什么记在服务器存储的 `archive/deletions.jsonl`。整库存档自备份起最长 30 天，交易记录按起算日（下单或赠送的日期）分份、每份最长 3650 天，批量工具结果按生成日期每天一份、各自最长 30 天（隐私保护指引写的期限）；导进来的云托管访问日志（只在服务器存储，不加密，和服务器自己的访问日志归档一样）自日志那天起最长 190 天。到期日怎么算见第六节开头。
- **从异地备份恢复**：从 COS（低频能直接下载）或本机的 `offsite-backups/` 取一份 `.age` 文件，在创始人电脑上 `age -d -i 私钥文件 youju-日期.jsonl.gz.age > backup.jsonl.gz`，再在刚迁移好的空库上 `youju restore --fresh backup.jsonl.gz`。
- **监控**：本机每 5 分钟从外面看一次服务器的接口服务和定时任务服务（`/health`、`/health/worker`），连续 2 次不通提醒到群里、恢复了再说一声；容器自带健康检查，坏了自动重启；每天早上 9:00 服务器、8:00 本机各发一份运维日报；任务失败由 job.sh 提醒。
- **同步**：本机每 10 分钟推一次（`youju sync-push`），失败提醒。查进度：本机 `docker compose exec worker youju sync-status`（待推的变更、两边各表条数差）。
  - 两边条数对不上（本机库是好的）：先 `youju sync-push --full --dry-run` 看服务器上多出来多少行，再 `youju sync-push --full`；要删的超过 200 行且超过 1% 会停下，确认后加 `--force`。
  - **本机库坏了、从备份恢复了、重装了**：不能推（程序会拦下：本机的自增编号落到服务器已有的以下），也**不能用 `--full`**（会把服务器上本机没有的行删掉，连带用户数据里指向它们的）。按下面"本机重新起步"做：从服务器导出、本机导入。
- **本机重新起步**（本机库坏了、重装了）：服务器上 `cd /opt/youju/server && docker compose run --rm --no-deps -v /opt/youju/export:/move worker youju sync-export --output /move/youju-server-export.jsonl.gz`（文件名和安装包里起步用的 `youju-sync-export.jsonl.gz` 不同，免得重跑安装脚本时被那份盖掉；共用服务器上先 `cd /opt/youju/server && docker compose stop api worker`，导完 `/opt/youju/bin/youju-shared.sh up`：临时容器占 worker 的那份内存，有据合计不超过 1.5G），传到 Windows 主机（只含公开数据，用完两边都删掉）。本机先照第五节第 7 条清掉旧数据，再在发行版里（`wsl -d youju -u root --cd /opt/youju/local -e bash`，导出文件拷进这个目录）：
  ```
  docker compose stop worker
  docker compose run --rm -v ${PWD}:/move worker youju sync-import --file /move/youju-server-export.jsonl.gz
  docker compose run --rm worker youju sync-setup
  docker compose run --rm worker youju sync-push --mark-synced
  docker compose up -d worker
  ```
  先停定时任务：导入到对上进度之间不能有新变更，不然会被当成"已经同步过"而漏推。导出的是全部公开表（下架的照样过来，下架备注清空；用户线索生成的截止日期不过来），本机各表的自增编号起点设成服务器的，以后本机新建的行不会和服务器撞编号；`--mark-synced` 直接把服务器进度对齐，不用全推。
- **升级**：构建新镜像（`build.sh`，推到镜像仓库）→ 服务器先升 worker（会跑迁移）再升 api：`docker compose pull && docker compose up -d worker && docker compose up -d api` → 本机升 worker。两边迁移版本一致前，同步会停下并提醒，不会推错。删表、删列的迁移照云托管的规矩反过来（先 api 后 worker）。
- **证书**：Caddy 自动申请和续期，不用管；要 80、443 端口一直开着。
- **日志**：容器日志每个服务最多 5×20MB 轮转；访问日志在库里留 190 天（每天归档到存储），容器日志里的 IP 只留前一半；Caddy 不记访问日志。
- **系统补丁**：unattended-upgrades 自动装安全更新；Docker 镜像每次升级时会带上基础镜像的更新。

### 3. 步骤

"执行命令"指腾讯云控制台 → 实例 `<实例>` → 执行命令（root；"执行记录上传"保持关着，开了要付 COS 费用）。`<版本>` 是 8 位提交号，`<哈希>` 是打包时打印的 SHA-256。装好以后脚本在 `/opt/youju/bin/youju-shared.sh`（不在 PATH 里，命令写全路径）；装之前用解包出来的 `/opt/youju/releases/<版本>/shared/youju-shared.sh`。要用域名的子命令（`check`、`site`、`cert`、`renew`、`uninstall`）前面加 `YOUJU_DOMAIN=<接口域名>`。

1. **快照**：控制台 → 快照 → 创建（免费额度：每个实例 2 个；对话框里没有费用项才拍，有费用就停下问创始人）。回退：快照回滚会把整台机器连别的项目一起回到快照时刻，只在整机出大问题时用，用前先问创始人。
2. **建传文件的用户**（执行命令；和脚本的 `key` 子命令做的一样）：
   ```
   id youju >/dev/null 2>&1 || useradd --no-create-home --home-dir /home/youju --shell /bin/sh youju; usermod -p '*' youju; install -d -m 755 /opt/youju; install -d -m 750 -o youju -g youju /opt/youju/incoming; install -d -m 755 -o root -g root /home/youju /home/youju/.ssh; printf '%s\n' 'restrict,command="/usr/lib/openssh/sftp-server -d /opt/youju/incoming -P read,opendir,readdir,readlink,symlink,hardlink,copy-data" <youju-deploy 公钥整行>' > /home/youju/.ssh/authorized_keys; chown root:root /home/youju/.ssh/authorized_keys; chmod 644 /home/youju/.ssh/authorized_keys; ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
   ```
   家目录、`.ssh`、钥匙文件都归 root（youju 用 sftp 改不了自己的限制）；这把钥匙只能上传，不能下载、不能列目录。最后一行打印服务器的指纹，第一次连接时核对。SSH 的全局配置不改。
3. **打包、上传**（Mac）：`sh backend/deploy/selfhost/make-server-package.sh <输出目录>`，记下打印的哈希；`scp -i ~/.ssh/youju_deploy_ed25519 -o IdentitiesOnly=yes <输出目录>/youju-server-<版本>.tar.gz youju@<服务器IP>:/opt/youju/incoming/`。
4. **核对哈希、解包、只读检查**（执行命令）：先把包拷到只有 root 能进的目录，核对和解包都用这份拷贝（incoming 归 youju，核对完到解包之间文件可能被换掉）；哈希是在 Mac 上算的、手抄进命令。第一次（脚本还没装上）：
   ```
   install -d -m 700 /opt/youju/staging && install -m 600 /opt/youju/incoming/youju-server-<版本>.tar.gz /opt/youju/staging/ && echo '<哈希>  /opt/youju/staging/youju-server-<版本>.tar.gz' | sha256sum -c - && install -d -m 755 /opt/youju/releases && rm -rf /opt/youju/releases/<版本> && mkdir -m 755 /opt/youju/releases/<版本> && tar -xzf /opt/youju/staging/youju-server-<版本>.tar.gz -C /opt/youju/releases/<版本> --no-same-owner && rm -f /opt/youju/staging/youju-server-<版本>.tar.gz && YOUJU_DOMAIN=<接口域名> bash /opt/youju/releases/<版本>/shared/youju-shared.sh check
   ```
   以后升级用脚本做同样的事：`/opt/youju/bin/youju-shared.sh unpack <版本> <哈希>`。
5. **停桌面、远程桌面和打印服务**：`bash /opt/youju/releases/<版本>/shared/youju-shared.sh desktop off`（先记原状；停完打印前后的内存、还在的登录会话、远程桌面端口还有没有程序在听）。开机默认要改成无桌面：先查有没有别的服务只挂在桌面模式（graphical.target）下，有就停下、什么都不动，列出来问清是谁的，确认没问题再加 `--force`。回退：`desktop on`。
6. **装、启动**（执行命令的超时改成 3600 秒，第一次构建 5–15 分钟）：`bash /opt/youju/releases/<版本>/shared/youju-shared.sh install <版本>`，再 `/opt/youju/bin/youju-shared.sh env <版本>`、`/opt/youju/bin/youju-shared.sh up`。回退：`uninstall`。
7. **站点和证书**。每次改 nginx 前后都用 `/opt/youju/bin/youju-shared.sh sites <别的站点域名>...` 经本机 nginx 取别的站点的状态码，前后要一样（站点清单和改动前的值记在本地文件）：
   - `site http`（只为申请证书）；
   - DNSPod 给接口域名加 A 记录 → `<服务器IP>`（要创始人点确认或明确同意：自动模式把它算作域名改动）；
   - `cert`（Let's Encrypt，HTTP 验证；要以创始人的名义同意它的用户协议，先问他）；
   - `site https`（正式转发，加续期定时任务）。
   `site` 每次先把整个站点目录打包备份，再写文件；现有配置过不了 `nginx -t` 就不动；新文件过不了就撤回、不重载；通过才平滑重载（`nginx -s reload`，不断开现有连接）。
8. **自测**（Mac）：`https://<接口域名>/health` 回 `{"status":"ok"}`；`/health/worker` 通；`/admin`、`/api/admin/` 回 404；`/api/sync/` 不带签名被拒；`http://` 跳到 `https://`。服务器上 `/opt/youju/bin/youju-shared.sh status`：三个容器 healthy、内存在上限内。
9. **和本机同步**（UU 远程；用 UU 主窗口里的"终端"直接开 Windows 的 PowerShell，不用进远程桌面）：Windows 的 `/opt/youju/local/.env` 填 `YOUJU_SYNC_URL=https://<接口域名>` 和服务器 `.env` 里的 `YOUJU_SYNC_SECRET`（测试期这样传，上线前两边一起换一个新的），然后在发行版里 `docker compose run --rm worker youju sync-setup`、`docker compose run --rm worker youju sync-push --full`（服务器是空库，本机的编号都比它大）。推之前先 `docker compose stop worker`，推完 `docker compose up -d worker`，再 `docker compose exec -T worker youju sync-status` 看各表条数差是不是空的。起步数据里的附件副本文件在云托管存储里、本机没有，全推时会提示"本机存储里没有附件副本，跳过"，正式切换时按第六节导出、导进服务器。两边代码的迁移版本要一样，不一样同步会停下提醒：先用同一版本重打本机安装包、重跑 `setup-wsl.ps1`。

### 4. 上线前（切换那天之前，按第六节）

- `.env`：云托管的不涉密配置照原值写进来（`config-from-export`）、打开定时任务（`env-set YOUJU_CRONTAB`）、删掉 `YOUJU_WX_API_BASE`（`env-unset`）；真的 AppSecret 等密钥由创始人自己在网页终端用 `secret` 录（不发聊天）；异地备份的 COS 配置和 age 公钥；两边一起换同步密钥（`rotate-sync`、本机 `set-secret.sh`）；改完 `/opt/youju/bin/youju-shared.sh up`。步骤见第六节第 3、10、11 步。
- 小程序后台：request 合法域名加 `https://<接口域名>`、IP 白名单加 `<服务器IP>`、消息推送地址（第三节第 4–6 条）。
