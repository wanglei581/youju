> **D-074（10/19）**：沙箱和测试名单的购买入口**只在开发版、体验版出现**，正式版谁也看不到（运营规范 5.19）；现网收费**只对代码包里带着定稿付费协议版本号的小程序开放**，所以开卖要单独提审一版，老版本永远看不到价格。整个顺序见[商业模式与收费开通方案](../商业/商业模式与收费开通方案_2026-10-19.md)第四节。

| `workbench_90d` | 批量工具90天 | 79 元 |

## 第 4 步：记下基础配置

虚拟支付 → 基本配置 → 基础配置：**OfferId** 可以告诉团队；**沙箱 AppKey**、**现网 AppKey** 只填到第 6 步。

## 第 5 步：云托管开放接口服务（api、admin 两个服务都要）

微信云托管控制台 → 服务 → **开放接口服务** → 接口权限列表加上：`/xpay/query_order`、`/xpay/refund_order`、`/xpay/notify_provide_goods`、`/xpay/download_bill`、`/xpay/download_ios_settlement_bill`、`/sns/jscode2session`。
admin 每分钟补单、退款、每天对账也要调这些接口，所以两个服务都加。开启后要重新发布一次版本才生效（团队发布时自然满足）。

## 第 6 步：环境变量（api、admin 两个服务都填同样的值）

| 变量 | 填什么 | 说明 |
|---|---|---|
| `YOUJU_PAY_ENABLED` | `true` | 只在沙箱联调期间打开；联调完可改回 `false`。打开后**默认只对测试名单开放** |
| `YOUJU_PAY_AUDIENCE` | `whitelist` | 沙箱联调、受控真实付款都保持 `whitelist`：只有名单里的人、而且只在体验版看得到。你批准开卖、提交开卖那一版审核时才改成 `all`（D-074）。沙箱付款不扣真钱，所以沙箱下就算填了 `all` 也只给名单里的人 |
| `YOUJU_PAY_OPENIDS` | 测试人员的 openid，逗号分隔 | 测试人员在小程序「我的 → 我的数据」里「完整标识」那一行点「复制」发给你（没有这一行时点「复制全部数据」，里面 user 下的 openid 就是）；和 AI 内测白名单是同一个标识 |
| `YOUJU_XPAY_OFFER_ID` | 第 4 步的 OfferId | |
| `YOUJU_XPAY_ENV` | `1` | 1 = 沙箱。正式收费时改成 0 |
| `YOUJU_XPAY_APPKEY_SANDBOX` | 沙箱 AppKey | **密钥，只填这里** |
| `YOUJU_XPAY_APPKEY_PROD` | 现网 AppKey | **密钥，只填这里**；正式收费前再填也可以 |
| `YOUJU_XPAY_PRICE_PASS` | `2900` | 30 天那一档，单位是分，必须和第 3 步道具价格一致，否则下单失败；不填这一档就不卖 |
| `YOUJU_XPAY_PRICE_PASS_90` | `7900` | 90 天那一档，同上 |
| `YOUJU_RENEW_BONUS_ENABLED` | `true` | 续买多送（到期前后 7 天内续买，每次多送 3 天）。开卖时和收费一起打开；收到平台提醒就改回 `false`（已经送的不收回） |
| `YOUJU_CORRECTION_REWARD_ENABLED` | 先不填（可选） | 纠错被采纳送 1 天、每人每月最多 3 天。要做再填 `true`；打开后管理台纠错列表出现「采纳并送 1 天」 |
| `YOUJU_PAY_INVOICE_TYPE` | 先不填 | 能开哪种发票，你确认后填一句（如"增值税电子普通发票，个人或单位抬头"），购买页照这句显示。沙箱联调不用填；正式收费（`YOUJU_XPAY_ENV=0`）不填就不卖 |
| `YOUJU_PAY_TERMS_VERSION` | 先不填 | 沙箱联调不用填。《付费服务协议》按 D-065 定稿（Codex、Grok 审阅，Claude 核对）、写进小程序代码包后，由团队告诉你填什么——要和代码包里的版本号一字不差：现网只对带着这个号的小程序开放（D-074）。现网（`YOUJU_XPAY_ENV=0`）不填就谁也不卖 |
| `YOUJU_WX_APPID` | `wxcf20754e505e9bfa` | 不是密钥 |
| `YOUJU_WX_APPSECRET` | **先不填** | 只有线上试出「开放接口服务换不到 session_key」时才由你自己填 |

改环境变量会生成一个新版本（备注 server config change）。改完告诉团队，团队用只读工具核对新旧版本的流量和实例。

## 第 7 步：消息推送（发货推送要用）

微信云托管控制台 → 设置 → 全局设置 → **消息推送**：环境选我们的环境；服务选 **api**；path 填 `/api/wx/push`；格式 JSON；用小程序管理员微信扫码确认。微信会发检测请求，后台自动应答成功。
一个小程序的所有消息推送都发到这个路径。

## 第 8 步：数据库授权（团队发布了迁移 0032 之后）

执行 `backend/deploy/mysql_accounts.sql` 里「支付权限」那四行（`pay_orders`、`pay_events`、`workbench_passes`、`invoice_requests` 的写权限），再执行「批量工具两档开卖权限」那三行（随订单记赠送天数、退款时收回、体验期内购买时结束体验）。团队发布时会提醒你。

## 沙箱联调怎么验（团队给步骤，你用安卓手机点）

0. 准备：团队上传带购买页、订单页的新体验版（会告诉你版本号）；你自己以外的测试人员，先在小程序后台 → 管理 → 成员管理 → **体验成员**里加上（填微信号），否则打不开体验版。
1. 测试人员用**安卓手机**打开体验版：工具表单用完免费次数后出现「批量工具」的价格 → 进购买页 → 选 30 天或 90 天 → 勾选协议 → 付款。沙箱环境（`YOUJU_XPAY_ENV=1`）下购买页顶部写着「沙箱测试，不扣真钱」，协议没定稿也能点付款；现网（`0`）必须协议定稿后付款按钮才可用。沙箱先在开发者工具里试；体验版真机能不能用沙箱，官方文档没写，不行就只在开发者工具里做，真机留到下面的"受控真实付款"。
2. 回到页面应显示「已开通，使用期到 ××」；「我的 → 我的订单」能看到这笔订单。
3. 7 天内、没用过付费额度时点「申请退款」，确认钱原路退回、使用期取消。
4. 另买一笔，在订单页「申请发票」填抬头和邮箱；团队在管理台「开票」里看到申请。
4a. 续买：团队把这个测试账号的使用期改到「7 天内到期」后，再买一笔，订单页应写「续买多送 3 天」；退掉这一笔，送的 3 天一起收回。
4b. 体验期内买：新的测试账号先开始加量体验，再买一笔，体验应立即结束、剩下的体验时间折成天数加在后面（订单页「加量体验折算」）。
5. 非测试名单的微信号同时打开小程序：不应看到任何购买入口、价格或「我的订单」。测试人员自己打开**正式版**（不是体验版）：同样看不到（D-074）。

苹果手机：官方不支持沙箱，只能在正式收费时用现网真付款验证一次（金额 29 元，苹果手机不能由我们主动退款）。

## 受控真实付款（现网，只在体验版，D-074）

前提：沙箱联调、500 家完整流程实测都过了；《付费服务协议》已定稿、写进开卖候选包，候选包已上传为体验版（团队会告诉你版本号）；你和会计定好了发票那一句。

1. 现网 AppKey 填进云托管 api、admin 两个服务；两个道具发布到**现网**版本。
2. 环境变量（两个服务一样）：`YOUJU_XPAY_ENV=0`、`YOUJU_PAY_TERMS_VERSION`（团队给的定稿号）、`YOUJU_PAY_INVOICE_TYPE`（发票那一句）、`YOUJU_RENEW_BONUS_ENABLED=true`；`YOUJU_PAY_AUDIENCE` 仍是 `whitelist`。这时只有名单里的人、用候选体验版才看得到价格；正式版（老版本）谁都看不到。
3. 安卓手机真付 29 元，到"我的 → 我的订单"自助退款，确认钱原路退回；续买多送、体验期内购买折算各走一遍。
4. 苹果手机真付一笔 29 元（苹果没有沙箱，我们退不了）。
5. 体验版能不能用现网付款，第 3 步就能看出来；不能的话告诉团队，开卖前的这一步另定，不在发布当天绕过。

## 开卖（你批准以后）

团队把开卖那一版（就是上面真付用的候选包，没有改动）提交审核前，你只改一项：`YOUJU_PAY_AUDIENCE=all`。审核期间带定稿号的版本只有审核人员和体验版能打开；审核通过、发布后就是所有人。小程序简介加上"含付费功能"（运营规范 14.1）。

## 退款和发票（D-074）

已开过发票的订单，退款不等冲红：团队核实后先原路退款（`youju pay-refund`），再由你在管理台开票页选"要冲红"，按退款金额开红字发票。
