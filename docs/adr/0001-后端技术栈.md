# ADR 0001：后端技术栈

- **状态：** 已采纳（2026-09-26）
- **相关：** 总方案 v7 §6.2；决策记录 D-003

## 背景

数据底座要做三件事：抓取和解析政府网站、存储结构化资料并支持检索、对小程序提供接口。后续还要接入大模型抽取和多格式导出。团队是 1 位创始人 + AI，维护成本必须低。

## 决定

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.12 | 抓取、HTML/PDF 解析、大模型调用、Excel/Word/PPT 生成都是 Python 生态最成熟 |
| 包管理 | uv + `uv.lock` | 安装快；锁文件保证本机和 CI 依赖一致 |
| Web 框架 | FastAPI | 类型校验和接口文档自动生成；同步写法即可满足当前规模 |
| 数据库 | PostgreSQL 16 | 一个库同时承担业务数据、JSONB 配置、全文检索（pg_trgm）和后续向量检索（pgvector） |
| ORM 与迁移 | SQLAlchemy 2 + Alembic | 迁移脚本入库；测试检查"迁移建出的表结构和模型一致" |
| HTTP 客户端 | httpx | 支持超时、重定向和自定义 TLS；测试可用 MockTransport 模拟任意网站 |
| HTML 解析 | lxml | 对不规范的政府网页容错好、速度快 |
| 代码规范 | ruff（检查 + 格式化） | 一个工具完成，CI 强制执行 |

本地开发不用 Docker：`backend/scripts/dev_db.sh` 在项目目录里启动独立的 PostgreSQL 实例，不注册系统服务、不改系统设置。CI 使用 GitHub Actions 自带的 PostgreSQL 服务容器。

## 放弃的方案

- **Elasticsearch：** 数据量到百万级之前没有必要，先用 PostgreSQL 的 pg_trgm。
- **Scrapy：** 适合大规模爬虫；我们是一百来个栏目的低频检查，简单的抓取器更容易控制礼貌抓取和合规规则。
- **异步（asyncio）全栈：** 同一网站必须串行、限速，并发来自"不同网站并行"，线程池足够，代码更简单。

## 后果

- 后续大模型抽取、PDF 解析、文件导出都在同一个 Python 项目里完成。
- 原有的 `services/api` 本地样机保留作参考，新功能都写在 `backend/`；功能覆盖后删除旧样机。
