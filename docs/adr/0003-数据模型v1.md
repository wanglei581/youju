# ADR 0003：数据模型 v1

- **状态：** 已采纳（2026-09-26）
- **相关：** 总方案 v7 §4.5、§6.4

## 背景

Sprint 1 只做"发现新文件"：知道哪些栏目在监测、每次检查的结果、发现了哪些文件。正文、附件、结构化字段（截止日、金额、名单行）在后续迭代加入。

## 决定

三张表：

| 表 | 一行代表什么 | 关键字段 |
|---|---|---|
| `sources` | 一个被监测的栏目 | 网址（唯一）、抓取方式（static / browser / manual / blocked）、是否启用、健康状态、连续失败次数、最后成功检查时间、`parser_config`（个别栏目的识别规则覆盖） |
| `source_checks` | 对一个栏目的一次检查 | 状态（ok / http_error / network_error / ssl_error / robots_disallowed / robots_error / parse_empty）、识别条目数、新入库数、是否基线检查、耗时、错误原因 |
| `documents` | 一份被发现的文件（题录） | 规范网址键（全库唯一）、原始网址、标题、发布日期、首次和最后一次看到的时间、是否基线 |

**基线规则：** 一个栏目第一次检查成功时，页面上已有的条目标记为"基线"，不算"新增"。这样前台的"本周新增"不会被首次接入的历史资料冲掉。

**先抓取、后短事务入库：** 抓取和识别期间不开数据库事务（网络请求可能持续几十秒）。入库时开一个短事务：先 `SELECT … FOR UPDATE` 锁住来源行并重新读取"是否成功检查过"，再判断基线、写入文件和检查记录、更新健康状态，然后提交。两个检查同时处理同一来源时，后提交的一方能看到前一方的结果，不会把期间新发布的文件也记成基线（Grok 在 PR #10 审阅中指出）。

**健康规则：**
- 检查成功：健康状态为 ok，连续失败清零；
- 失败：先标为 degraded，连续 3 次失败标为 failing 并告警；
- robots 禁止：标为 blocked；
- 抓取成功但识别不到条目（parse_empty）也算失败，因为这通常意味着网站改版。

**同一份文件只存一份：** 以规范网址键 `url_key` 判断是不是同一份文件：不区分 http 和 https，去掉 80、443 端口和会话参数（`;jsessionid=`、`PHPSESSID` 等；`sid` 不算，不少网站用它区分栏目），折叠 `/./` 与 `/../`，目录默认页（`index.html` 等）收成目录，查询参数按名称排序。`url` 保留第一次看到的原始网址，用于展示和访问。同一份文件出现在两个栏目里（常见于"通知公告"和"政策文件"），只存一条，记在第一次发现它的栏目下。

入库用一条按 `url_key` 排序的 `INSERT … ON CONFLICT DO UPDATE`：多个线程同时写入重叠的文件时加锁顺序一致，不会死锁。区分新插入和更新用的是 PostgreSQL 的 `xmax = 0`，这是 PostgreSQL 特有的做法，有测试覆盖。

**改规范化规则时：** 规则变了，旧键可能合并成同一个新键，直接更新会违反唯一约束。做法是两步迁移：新增一列算出新键 → 离线合并重复的文件（保留最早的一条，合并最后看到的时间）→ 切换唯一约束并删除旧列。

**来源只停用、不删除：** `documents.source_id` 外键为 `RESTRICT`，删除来源不会连带删掉已发现的文件（PR #10 审阅时 agy 指出原来的级联删除有丢数据风险）。

## 审阅记录（PR #10）

- **agy（第二轮）：**
  - 采纳：锁不应跨网络请求持有，改为"先抓取、后短事务入库"。
  - 采纳：记录改规范化规则时的两步迁移做法。
  - 未采纳："异常时没有回滚"：`crawl_sources` 捕获异常后已调用 `session.rollback()`。
  - 未采纳："删除来源的外键不一致"：来源用 `enabled` 停用，不删除；检查记录随来源级联删除是有意的。"连接池会被耗尽"也不成立：最多 8 个线程，低于默认的 15 个连接。

## 放弃的方案

- **文件与栏目的多对多关系表：** 目前只需要知道文件最早出现在哪里。前台需要"这份文件出现在哪些栏目"时再加。
- **把检查记录只写日志不入库：** 前台要显示"截至上次成功检查"，运营要追溯失败原因，所以入库。

## 后果

- 下一迭代加 `document_versions`（正文与版本）、`attachments`、结构化事实表和 `evidence_spans`。
- 迁移测试保证模型改动必须附带迁移脚本。
