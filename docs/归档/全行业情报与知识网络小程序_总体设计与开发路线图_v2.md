## 1. 产品决策：一句话定位与首个付费任务

**定位：**面向职场人的“行业情报工作台”。它把分散在政府、企业、研究机构、协会和已授权数据商的资料连接成可检索的来源目录；按用户确认的任务持续发现变化，生成能逐条核证、编辑和交付的周报；也支持随时提问与跨行业研究。

**首个付费用户假设：**中小政策咨询/科技服务机构里，每周为多家企业客户制作政策与企业认定名单周报的顾问。该场景有固定截止时间、多客户复用、真实文件交付，能测量节省工时和质量。企业政府事务/战略团队是第二类试点；园区、协会和公众随后扩展。这个排序需要真实访谈与付款验证，当前不是已证明的市场结论。

**第一项可售成果：**“某行业×某地区，本周新增/修订政策、申报节点和企业认定名单状态”的 XLSX 清单与可编辑 DOCX 简报。每条结论附原站链接、发布日期/统计期、采集时间及状态。小程序先承担提醒、初筛、核证与下载；大量文字和表格的编辑可在电脑上完成，是否另建 Web 工作台由试点验证。

**产品范围原则：**第一天支持全行业分类、跨行业搜索和来源目录；每个行业/地区的监测覆盖程度单独公示。首批只承诺已校验的 2–3 个“行业×地区”专题、3–5 个官方来源及 5–10 个报告来源的题录导航。不能把“可选全部行业”写成“全国全行业全部资料已实时收录”。

## 2. 用户旅程和界面设计

### 两种工作模式

| 模式 | 用户说法 | 产品动作 | 用户拿到什么 |
|---|---|---|---|
| 每周任务 | “每周一帮我看山东医疗器械政策、相关统计和新公示的专精特新企业” | AI 解析为可修改的任务卡；用户确认来源、地区、名单状态、关注企业、频率；先试跑过去四周，再按周增量检查 | 基线简报、本周变化清单、失败来源提示、XLSX/DOCX、授权提醒 |
| 临时研究 | “比较储能与汽车零部件在江苏和山东的政策及公开数据，找几份企业白皮书” | 多行业检索→按权利发现资料→挑入证据篮→对齐口径→生成有出处的研究草稿 | 可追问的证据、对比表、缺口说明；获授权后再导出和分享 |

### 小程序信息架构

**底部四栏：**`本周`（简报收件箱）｜`任务`（客户/项目及周监测）｜`发现`（搜索、行业与来源地图）｜`我的`（文件、席位、授权连接和用量）。AI 出现在任务配置、简报与证据详情中，不单独占一个底栏。研究台作为从简报或搜索结果进入的项目页面。

**三个先设计、先测试的屏幕：**

1. **任务确认：**“看什么、看哪里、关注哪些企业、何时交付给谁”四块卡。展示具体已接入来源、覆盖层级和模糊词待确认项；主操作是“试跑过去四周”，次操作是“只搜一次”。超出覆盖范围时列出缺哪些来源。
2. **本周简报：**顶部显示“已检查/失败来源/截至时间”；正文按新增、修订、状态变化和待核分组，每条可“纳入、剔除、批注、看原文”。标明“官方文件、官方统计、企业观点、机构研究”。底部按已选条目生成文件，显示版本与异步状态。
3. **发现与证据：**搜索结果分政策、官方数据、研究报告，并能按出版机构找来源。每张卡显示为什么匹配、原始链接、发布时间、可用权限。问答抽屉逐条引用证据；只有题录的报告明确显示“AI 未读全文”。

**第一次使用：**可先浏览已接入的专题模板→一句话修改→确认范围→试跑四周→看“基线简报”→挑选条目→导出；在保存为周期任务或开通邮件提醒前再完成必要登录/授权。基线结果不计作“本周新增”。无资料、站点失败、报告无许可、名单只有公示版分别设计清楚的状态。

**参考“数看三医”截图：**沿用首页易懂的搜索入口、法规库的筛选方式和个人中心的文件/历史入口。面向全行业时，在搜索前增加“行业×地区×主题”的范围确认，在结果中增加发布方、来源类型、时效、资料权限和检查状态；首页主操作放“创建每周任务”，让需要定期交报告的人直接进入工作流程。截图中的热榜、积分与会员页只说明该产品已有相应界面，不能据此推断其真实数据覆盖、收费转化或后台能力。

## 3. 功能分期：首版做成一条真实闭环

| 能力 | 验证版/G0 | MVP/受控 Alpha | 付费 Beta | 扩张期 |
|---|---|---|---|---|
| 行业与来源 | 国家行业分类映射、来源清单、人工整理样本 | 全行业入口；已校验专题；报告题录和原站导流 | 更多地方源及发布方目录推送 | 授权报告、更多地区、发布方后台 |
| 周监测 | 人工+半自动连续两周对照 | 任务卡、四周基线、每周/手动运行、增量和失败提示 | 团队任务共享、审批、来源健康面板 | 复杂规则、更多频率和跨组织协作 |
| AI | 人工标注的证据与错误集 | 自然语言任务解析、带引用摘要；缺证据提示 | 限定证据的自由问答、跨行业研究 | 更复杂的多文档分析与行业模板 |
| 交付 | 样本周报、真实工时记录 | XLSX 明细、可编辑 DOCX、应用内查看、授权邮件提醒 | PDF、固定模板 PPTX、首个客户需要的工作应用连接 | 品牌模板、更多连接与授权数据包 |

MVP 中的少量官方统计指标先显示最新值、统计期、单位和原表位置，不把按月/季度发布的数据伪装成每周都有新值。PPTX 与四格式统一报告对象是产品目标；未在真实 Office/WPS 和目标手机上通过验证的格式不展示成已可用。

## 4. 数据来源、权利和事实模型

**首批来源组合：**[国务院政策文件库](https://sousuo.www.gov.cn/zcwjk/)和[国家数据](https://data.stats.gov.cn/)可作为官方入口样本；部委/地方政府名单栏目逐站评估；[腾讯云白皮书目录](https://intl.cloud.tencent.com/zh/resources/whitepaper?lang=zh)可作为企业报告发现样本。用户提到的[腾讯云产业互联干货库入口](https://file.polaris.tencent-cloud.com/)目前需手机打开，目录和权利尚未核实。来源“可访问”不自动授予批量采集、全文 AI 处理或二次分发权；腾讯云[账号协议](https://cloud.tencent.com/document/product/301/91174)也对网站内容使用设有限制。

**每条资料的动作权限分开记录：**展示题录、预览片段、存全文、AI 处理、下载原件、生成衍生文件、对外分享、署名方式、到期日。企业白皮书初期以题录和原站链接为主；拿到相应许可后才开放全文 AI 与再分发。用户上传材料限定在个人/团队租户；源站撤稿、授权到期或用户断连时，派生内容进入重核。

**来源可信度不能混写：**政策原文记录机关、文号、发布/实施/废止状态；统计指标记录定义、单位、地区、统计期和修订；企业报告标“发布方观点”并展示研究方法/年份；名单记录申报、拟认定/公示、正式公布、复核/撤销等状态。公示中不能写“已获奖”，公示结束但未找到正式名单也不能自动写“落选”。

**最小结构对象：**`Publisher`、`SourceCollection`、`SourceConnector`、`ResourceRecord`、`DocumentVersion`、`RightGrant`、`EvidenceSpan`、`DatasetSeries`、`CompanyEntity`、`RecognitionEvent`、`MonitorTask`、`FetchRun`、`Digest`、`Claim`、`ExportJob`、`DeliveryAttempt`、`AuditEvent`。所有 `Claim` 指向某个版本中的段落、页码或表格单元格；报告修改不能静默覆盖旧版本。

## 5. 最小可信系统架构

```text
微信小程序                    可选 Web 编辑/运营后台
      │                             │
      └────────── API / 登录 / 团队权限 ──────────┘
                          │
             核心业务服务 + 关系数据库/全文索引
              ├─ 来源与权限台账、行业/主题映射
              ├─ 任务配置、项目、简报、审计
              └─ 检索与证据查询
                          │
                 异步任务队列和工作进程
              ├─ 公共来源集中同步（同一源只取一次）
              ├─ 网页/PDF/表格解析、去重和版本比较
              ├─ 任务匹配、AI 摘要、字段校验、待核队列
              ├─ XLSX/DOCX/PDF/PPTX 文件渲染
              └─ 经授权的邮件/工作应用投递
                          │
                  对象存储（按权利保存）
```

**建议起步技术形态：**一个后端服务、一个任务队列、一套关系数据库与全文索引、对象存储、小程序前端和简单运营后台；检索召回不足时再加向量检索，不从第一天建立复杂多智能体或知识图谱。后端语言/云平台以团队现有能力、国内可用性和试点成本确定；当前没有仓库，不能把某一框架写成既定事实。

**来源连接器契约：**输入为已批准的站点/栏目、访问条件、频率、权利；输出为发现的 URL、文件/版本指纹、原始时间字段、解析状态、失败原因和检查时间。优先官方接口、RSS、发布目录或合作推送；逐站评估网页采集与使用条款，限频，不绕过访问控制。一个公共来源的采集结果复用给多个周任务；客户私有来源按租户隔离。

**周任务状态：**`待运行→检查来源→增量匹配→生成草稿→待核→可交付→已送达/失败`。某来源失败可形成注明缺口的“部分完成”简报，绝不写“本周无更新”。导出和投递都带唯一任务键，重试不能重复扣费或群发。源站结构改变、OCR 错行、企业同名或日期异常进入运营队列。

## 6. AI 怎样回答，怎样避免“信息孤岛变成错误拼接”

```text
用户问题/任务 → 解析为行业、主题、地区、时间、来源与交付需求
→ 用户确认 → 按权利筛选证据 → 检索段落/表格
→ 生成结构化 Claim（事实/观点/推断/来源位置）
→ 校验文号、金额、日期、单位、企业名单状态和版本
→ 标出资料不足/待核项 → 用户确认 → 简报与文件渲染
```

跨行业报告先检查指标定义、统计期、单位和地区层级。口径不同则并列解释，不直接求和。只有报告题录时只推荐原站，不能声称“根据全文得出”。关键结论的原文证据、来源类型和生成时间同时出现在页面与导出文件。生成内容的标识及面向公众服务的要求须在上线前核对[《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)和[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)的实际适用范围。

**金标集先于自由问答：**从试点客户的脱敏周报中建立政策文号/金额/日期、统计口径、名单状态、无答案、授权拒绝、跨行业冲突等案例。每次更换来源解析器、模型或提示词都重跑受影响评测。关键字段无证据、使用越权全文、将公示写正式、来源失败却写“无更新”属于阻断交付的错误。评测目标和抽检比例在试点前与客户确定，不宣称模型能达到绝对零错误。

## 7. 开发顺序、人员与验收门槛

| 阶段 | 估算与负责人 | 要交付的可检查结果 | 继续条件 |
|---|---|---|---|
| G0 问题与来源验证 | 约 2–3 周；产品/销售 + 数据研究 | 15–20 名目标用户访谈、最近四周脱敏样本、2 周人工/半自动周报、3–5 个来源的权利与技术盘点、真实报价 | 至少有真实试点付费意向和可行来源；记录人工基线，不用“愿意以后考虑”代替付款 |
| G1 可开发规格 | 约 1–2 周；产品 + 设计 + 工程 | 三关键屏可点原型、任务和名单状态规则、来源/权限表、API 契约、金标集首版、明确未覆盖范围 | 5 名目标用户能完成“建任务→核证→导出”的原型测试；关键规则无歧义 |
| G2 核心开发 | 约 6–8 周；后端/AI + 小程序 + 数据研究 | 官方来源连接器、公共同步池、题录地图、任务调度与四周基线、简报编辑、XLSX/DOCX、运营质检 | 真实来源连续运行；用户可逐条回到证据；禁下资料不能绕过前端从 API 取得 |
| G3 受控试点 | 约 4–6 周；全团队 + 法务/安全参与 | 5–10 家机构真实周报、计费/成本、邮件提醒、失败补跑、真机文件测试；按需求加入 PDF/PPTX、问答或首个工作应用 | 连续四次周任务有成功/失败记录；抽样确认名单状态、出处、权限；实际用户节省时间并愿续用 |
| G4 商用决策 | 试点后；负责人 | 付款、复用、人工修订、漏报、成本、授权与平台审核复盘 | 只有资料权利、质量、运营、发布与客户验收证据齐全才扩大范围 |

约 12–18 周形成受控试点是 4 人左右团队的粗估，G0/G1 可与部分技术验证交叠；数据授权和平台审核会影响节奏，不作为上线承诺。最小角色：产品/销售、数据与质量、后端/AI、小程序；设计测试与法律合规按阶段参与。开发时至少安排一人持续维护来源健康和用户纠错。

**第一批工程任务，按依赖顺序：**

1. 确认 2–3 个专题及每个专题的必看网址、样本周报和权利依据；建立 `Source/RightGrant/DocumentVersion` 表。
2. 做 1 个政策、1 个统计、1 个名单来源的真实连接器；记录首次同步、重复运行、修订、失败和撤回。
3. 做“来源健康 + 内容待核”运营台，能人工修正文号、日期、名单状态和企业同名；保留审计。
4. 接任务解析 API、用户确认页、四周试跑和每周调度；只让已批准来源进入任务。
5. 接证据卡、条目筛选与批注、XLSX/DOCX 异步导出；文件含出处和截至时间。
6. 加限定证据的 AI 摘要与评测；再扩问答、PDF/PPTX 和工作应用。

**建议接口边界：**`POST /tasks/parse`（只给建议、不保存）→`POST /tasks`（保存确认范围）→`POST /tasks/{id}/dry-run`→`GET /digests/{id}`→`POST /digests/{id}/selections`→`POST /digests/{id}/exports`。所有写接口按团队身份与资料权利授权；外发接口另核对接收目标。接口名仅用于明确边界，开发可按实际框架调整。

## 8. 商业模式与 30/90 天决策

**收费对象：**团队持续使用的来源监测、核验和交付能力；可采用团队席位与一定文件额度，超额导出或授权数据包另计。普通用户可浏览有限目录与来源链接。来源发现可给发布方导流；若有合作推广，搜索结果必须显著标识，不能影响证据权威性排序。

**最强替代：**政府免费检索/订阅 + 通用联网 AI + Excel/PPT。用户不会仅为“多一个政策搜索框”付费。企业报告目录也容易被复制；能形成持续价值的部分是约定来源的稳定增量、企业名单状态核验、人工可改的周报和每条结论可追溯。

**30 天证伪实验：**给至少 8 家目标机构展示其真实任务的样本周报与明确报价，记录实际预付而非口头兴趣；对至少 10 份脱敏任务做人工现状与产品流程计时；5–10 个报告来源先用题录导航，测用户是否发现此前不知道且会真正纳入周报的资料。任何价格和阈值在实验前冻结为内部假设，不能写成现有市场数据。

**90 天继续条件（待与试点客户确定）：**至少 3 家机构真实付费或预付，试点团队连续四周使用；同类周报的中位制作时间较其自身基线有明显下降，关键字段和授权错误均有可解释的抽检结果，单份交付的模型、解析、人工质检成本可算。未达付费、资料召回或人工节省的门槛，先缩小行业和来源，不继续堆功能。已有商业方案中的“≥40%”只是待验证的内部目标。

## 9. 四方评审的结论与分歧

| 角色 | 本轮可用结论 | Codex 决定 |
|---|---|---|
| Claude | 周任务应成为首页；模板和四周基线让用户第一次就见到结果；手机适合提醒与初筛，重度编辑需验证电脑端 | 采用四栏导航与三关键屏；G1 用真实顾问任务测移动端初筛，必要时补 Web 编辑台。其对小程序消息限制的判断未联网核实，不作为事实写入排期 |
| Grok | 免费政策库+通用 AI 是最强替代；报告目录本身不是壁垒；预付、工时和资料发现的使用行为要尽早验证 | 把付费主张锁定在周报闭环；30 天做付费和人工对照；来源目录先以导流验证，不以内容独占作为假设 |
| Antigravity | 统一公共来源同步、动作级权利拦截、证据引用、部分失败状态和外发防重复是架构要点 | 采用最小单体+任务队列；其“单测率 100%”“零幻觉”等绝对门槛未作为工程承诺，改为真实金标与硬错误阻断 |
| Codex | 结合公开来源与权利文件，收敛首批客户、来源和格式；把每阶段的真实证据与概念设计分开 | 当前结论为**方案可行，产品未开发**；可进入 G0/G1，商业上线仍需来源授权、真机、质量、运营和客户验收 |

这份方案不代表四个模型达成了市场实证共识。Claude 阅读了方案、原型代码和用户截图；Grok 阅读了商业与来源方案；Antigravity 阅读了工程与来源方案；三方均未访谈客户或测试真实系统。新版[周报与来源地图交互原型](./designs/industry-research/全行业情报助手_周报与来源地图_v2.html)已呈现本版四栏导航、任务草稿、来源发现与权限提示；它仍是界面原型，不是 G1 用户可用性或真实数据接入证据。前一版[交互原型](./designs/industry-research/全行业研究小程序_交互原型.html)可作为“搜索+研究”方向的设计对照。
