# 全行业资料库与 AI 情报小程序：完整产品、功能与开发规格 v5

**日期：**2026-09-24  
**方案状态：**Codex 综合 Claude、Grok、agy 的只读评审及公开资料形成的产品与开发方案；第十至十六节进一步把功能拆成页面、业务规则、数据结构、接口和开发任务。当前只有可点击的[界面原型](./designs/industry-research/全行业情报助手_周报与来源地图_v2.html)、案头调研、未运行的本地试点脚本；没有已上线小程序、持续数据连接、用户访谈、付费客户或真机验收。本文件用于决定做什么及如何做，不是上线承诺。

## 一、先回答四个问题

**这是什么产品？**面向要持续查行业政策、企业名单、官方数据和市场报告的职场人，提供一个“发现来源→检查变化→核对证据→AI 辅助整理→生成可交付文件”的工作台。微信小程序负责发现、提醒、核证、轻编辑和取文件；后台负责来源维护、数据质检、权限和异步导出。

**为什么值得做？**[工信部报道](https://www.miit.gov.cn/xwfb/mtbd/wzbd/art/2025/art_e41072f894cb4f1da08576f70845e3da.html)曾将“政策不好找、读不懂、不会办”列为企业反馈的痛点。但[长三角“政策通”](https://hzjl.sh.gov.cn/n1315/20240326/235d5e07259d4f28adcd71ecedd1d970.html)已有免费检索与企业匹配，[浦东“浦易达”](https://www.shanghai.gov.cn/nw15343/20251014/47f40700bcdd4e1881628d4a3f6363b8.html)已覆盖政策问答和申报流程，[企查查招股说明书申报稿](https://dataclouds.cninfo.com.cn/sjother2/documents/2025/20251010/3b60ceaf651c4ea0947338d28dc00778.pdf)披露专项查询、导出及关注企业周报等权益。因此本产品的待验证价值是：**按用户约定的跨来源范围稳定检查变化、区分名单状态、显示证据缺口，并交付可编辑的报告。**公开资料能证明问题与替代品存在，尚不能证明购买意愿。

**为什么可以覆盖所有行业？**“全行业”先指统一分类与来源导航。每个“行业×地区×主题”组合都公开显示三档覆盖：①已监测并质检；②仅有题录与原站入口；③暂无覆盖。只有第一档能承诺周期监测。扩行业靠标准化连接器与运营台账逐步增加，不靠一次性抓取全网。

**最后解决什么问题？**让用户不必每周重复打开许多网站、手工比较不同版本、猜测“公示”是否等于“获奖”、再从零拼 Excel/Word；一份报告中的事实可以追到原始发布页、版本和统计口径。真正省下多少时间、是否愿意付款，必须用真实任务测量。

## 二、用户与首个场景

| 用户 | 常见任务 | 产品优先级与理由 |
|---|---|---|
| 政策咨询、科技服务、产业研究顾问 | 同时为多家客户做政策、申报节点、认定名单周报 | **首个高频任务假设。**有明确的周期工作和文件成果，适合检验产品是否真正省事；无需先找到付费客户才能启动 |
| 企业战略、政府事务、市场研究人员 | 跟踪本企业、竞争对手、行业政策及报告 | 第二批试点；更在意可追溯与跨部门分享 |
| 园区、协会、商会运营人员 | 汇总辖区企业变化和政策，为会员提供服务 | 团队版与合作发布方潜在客户 |
| 普通企业主与公众 | 想快速了解某项政策、名单或资料出处 | 以免费发现和有限查询获取用户，不先作为主要付费收入 |
| 报告发布方、研究机构、数据商 | 让有价值的报告被目标人群发现 | 合作供给侧；先题录导流，后逐项谈授权 |

**第一个可核验专题：**青岛专精特新中小企业名单状态。官方[2026 年复核公示](https://www.qingdao.gov.cn/zwgk/xxgk/fzj/gkml/zdly/cycx/202605/t20260525_10603014.shtml)先写“拟通过复核”，后有[正式继续授予通知](https://www.qingdao.gov.cn/zwgk/xxgk/fzj/gkml/zdly/cycx/202606/t20260603_10624597.shtml)。这组真实历史材料可用于检查状态时间线和报告文案。它只是工程切片，不代表未来产品只做青岛或专精特新。

**没有现成用户也能启动：**这是一项由产品判断驱动的建设，不以客户访谈、预订单或付费意向作为开发许可。先选公开、可核验、重复检索价值高的专题，做出真实资料库、历史样本和可用的免费基础功能；开放后观察真实搜索、保存任务、证据核对、导出和复访。访谈和付费测试可以帮助调整方向，但不阻止前期建设。尚无使用数据时，所有“用户需要”“会付费”都标为待验证假设。

## 三、产品结构和用户旅程

### 3.1 四个底部入口

| 页面 | 用户在这里完成什么 | 首版要显示什么 |
|---|---|---|
| **本周** | 看任务运行结果，决定纳入哪些条目并导出 | 已检查/失败来源、截至时间；新增、修订、名单状态、待核分组；无变化与部分完成状态 |
| **任务** | 用自然语言或模板确认监测范围 | 行业、地区、主题、关注企业、必看来源、频率、交付对象；先试跑历史基线，再保存周期任务 |
| **发现** | 按行业与来源找政策、统计、报告 | 覆盖地图、发布方目录、权限标签、原站入口、专题搜索、申请新覆盖 |
| **我的** | 管理成果与授权 | 文件柜、历史版本、团队席位、连接状态、用量、纠错与隐私入口 |

AI 不单设底栏。它在任务解析、证据问答、简报起草和跨行业对比时出现，并明确标示“依据哪些资料”和“哪些资料尚未读到全文”。

### 3.2 两条主流程

**周期工作：**“每周帮我看青岛某行业新政策、申报截止和企业认定变化”→ AI 提议范围→用户确认来源和地区→试跑过去四周形成**历史基线**→每次运行记录成功/失败来源→用户核对、批注、剔除→导出 XLSX/DOCX→有权且经用户授权后提醒或投递。

**临时研究：**“比较储能与汽车零部件在山东、江苏的政策和公开指标，找报告”→按行业与地区召回资料→显示每份资料能否预览、AI 阅读、下载→放入证据篮→对齐指标单位、年份和口径→生成带出处的比较草稿→导出。它依赖多行业真实覆盖和指标模型，放在付费 Beta 后期。

**状态文案必须准确：**“拟认定/公示中”“正式公布”“复核通过”“撤销”分别记录；公示期结束而未发现正式文件时显示“待正式公布”，不能写“已落选”。某来源检查失败时显示“本次不完整”，不能写“本周无更新”。

## 四、完整功能说明：为什么做、怎么做、什么时候做

`MVP` 指单专题受控可用版本；`Beta` 指多专题付费试点；`扩张`指跨行业深化。所有收费档位只开放真正可用的资料范围。

| 模块与阶段 | 解决的问题、为什么做 | 用户功能与实现方式 |
|---|---|---|
| **行业分类与覆盖地图（MVP）** | 允许“全行业选择”，同时避免误以为全量实时收录 | 行业/地区/主题三维目录；每个组合从来源台账计算“已监测/仅导航/未覆盖”、上次核查和缺口；未监测组合可申请覆盖 |
| **来源网络与权利卡（MVP）** | 用户不知道可信资料在哪，也不知道能否下载 | 发布方主页、资料题录、发布日期/统计期、原站、来源类型、授权动作；企业白皮书先以目录与跳转展示 |
| **统一搜索（MVP→Beta）** | 多站点检索重复且口径混杂 | 先搜已接入题录与官方文件；按行业、地区、发布方、时间、状态筛选；结果标“官方事实/企业观点/研究推断”；后期扩跨行业查询 |
| **任务模板和一句话需求（MVP）** | 降低复杂设置门槛 | AI 只把话转成可编辑的行业、地域、关键词和来源建议；用户确认后才保存任务，不让模型自行决定订阅或外发 |
| **来源检查与增量监测（MVP）** | 每周手动刷站会漏看、误以为没有更新 | 公共来源集中同步；每次记录时间、成功/失败、指纹与版本；去重并匹配任务；失败给出缺口和补跑状态 |
| **政策、指标、名单结构化（MVP→Beta）** | 不同文档难以比较，关键状态容易写错 | 政策记录机关、文号、发布/实施/废止；统计记录单位、地区、统计期和修订；名单记录批次、公示/正式/复核/撤销及企业实体；难判的条目进人工待核队列 |
| **证据抽屉与纠错（MVP）** | 用户需要向领导或客户说明出处 | 每条结论显示原站链接、文档版本、段落/页码/附件行、采集时间；用户可报错，运营修订留痕；只有题录时显示“AI 未读全文” |
| **本周简报和编辑（MVP）** | 资料汇总仍需人工取舍 | 按新增/修订/名单状态/待核分组；纳入、剔除、批注；显示“无变化但检查成功”和“部分完成”两种不同结果 |
| **AI 摘要与问答（MVP 末→Beta）** | 节省阅读和写作时间 | 先限定在已授权且可追溯证据内；生成结构化事实/观点/推断；文号、日期、金额、单位和名单状态过规则校验；证据不足时明确说明 |
| **跨行业整合（Beta）** | 战略人员需要把相邻产业放在一张图里 | 从证据篮生成比较表与报告；指标口径不同则并列解释，不直接相加；每张图表保留来源、年份和定义 |
| **文件导出（MVP→Beta）** | 用户最终要把工作成果交出去 | 同一份结构化简报渲染 XLSX 明细和 DOCX 可编辑报告；PDF 固定阅读版、PPTX 汇报模板在 Beta 分别验收后开放；生成任务异步执行、可重试且不重复扣额度 |
| **团队与外部应用（Beta）** | 报告需跨同事、客户和工作系统协作 | 团队/客户项目、只读与编辑权限、版本；邮件、企业微信、飞书等按用户/企业授权接入，默认外发摘要和查看链接，附件权限另核对 |
| **运营与发布方后台（MVP→扩张）** | 来源改版、附件解析和权利到期需要持续维护 | 来源健康、待核工单、许可台账、撤稿/过期处理、审计；合作发布方后期可提交题录和更新接口，审核后展示 |

### 4.1 资料库怎样才算“全面”

按层建设，而非把所有文件复制进小程序：

1. **来源层：**政府部委和地方栏目、官方统计、协会、企业白皮书、智库、授权数据商。每个来源有所有者、访问方式、检查频率和健康状态。
2. **题录层：**统一记录标题、作者/机构、行业、地区、时间、主题、版本、文件格式、摘要和原站；解决“谁做过这份报告、在哪能找到”。
3. **内容层：**仅对有明确权限的全文/数据建立检索、AI 阅读和导出；报告发布方可选择导流、授权预览或商业合作。
4. **关系层：**把政策、统计指标、企业、认定事件、产业主题和报告连起来，让“关注这家公司/行业”能看到相关变化。

[国务院政策文件库](https://sousuo.www.gov.cn/zcwjk/)适合用户跳转核验，但其搜索域名的[robots.txt](https://sousuo.www.gov.cn/robots.txt)在 2026-09-24 显示 `Disallow: /`，不作为自动采集连接器。企业报告初期只做题录和原站导流；例如[腾讯云账号协议](https://cloud.tencent.com/document/product/301/91174)对其网站内容的复制、修改、出售与传播设有限制，全文 AI、原件下载和再分发需单独核权。

## 五、系统与 AI 开发方案

### 5.1 从一个可维护的系统开始

```text
微信小程序 ── 登录/团队权限/API ── 业务后端 ── 关系数据库 + 全文检索
                                        │
                         ┌──────────────┴──────────────┐
                         │                             │
                  来源与权利台账                   周任务/项目/文件柜
                         │                             │
                集中同步 + 解析队列             AI/核证/导出任务队列
                         │                             │
                版本/证据/待核队列                  对象存储/投递记录
                         └──────────────┬──────────────┘
                                  Web 运营后台
```

先用**模块化单体后端 + 异步作业队列**，配小程序和一个运营后台。一个公共栏目只同步一次，再匹配多个用户任务；客户私有资料在租户内隔离。首版关系库与全文索引足以支撑可核验检索，只有召回率证据显示不足时再加入向量索引或更复杂的模型编排。

**关键数据对象：**`Publisher`、`Source`、`RightGrant`、`Resource`、`DocumentVersion`、`FetchRun`、`EvidenceSpan`、`Company`、`RecognitionEvent`、`DatasetSeries`、`MonitorTask`、`Digest`、`Claim`、`ExportJob`、`DeliveryAttempt`、`AuditEvent`。其中 `Claim` 必须指向具体版本的 `EvidenceSpan`；内容被撤稿或许可到期时，相关结论进入重新核验。

**来源连接器契约：**只接入通过审核的 URL/接口，记录访问条件、合理频率、版本指纹、原始日期、解析状态和错误原因；优先官方接口、目录、RSS 或合作推送，逐站判断网页采集条件。不绕过登录、验证码或限制。自动抓取失败时不推断“没有新信息”。

**AI 处理链：**用户问题→建议的任务结构→用户确认→权限过滤→检索段落/表格→生成事实、观点或推断类型的结论→校验文号、金额、日期、单位、状态→显示来源与不足→人工确认→文件渲染。多行业分析先对齐统计口径。对名单、补贴资格和强监管行业，AI 只辅助研究，关键结论需要责任人核证。

**文件与连接：**先从一个 `Digest` 对象渲染 XLSX/DOCX，后续再衍生 PDF/PPTX，以免四种文件出现不同数据。导出有任务状态和唯一键；重复点击、网络重试不能生成多份收费结果或多次外发。连接器区分“输入资料”和“输出消息”，撤销授权后立即停投递。

**安全与规则：**最小化收集个人信息，按团队隔离，敏感文件加访问控制与审计；用户可管理授权、删除和纠错。上线前逐项核对[《个人信息保护法》](https://www.miit.gov.cn/jgsj/zfs/fl/art/2022/art_515a4b20c12f430eab54bb4f56d89f56.html)、[《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)和[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)的适用范围。小程序类目、支付、订阅消息、文件预览与分享能力以申请主体在当时的微信开发者后台、官方文档和真机结果为准；本方案不预设费率或 iOS 能力。

## 六、营销推广：产品功能与运营动作一起设计

### 6.1 获客路径

```text
有出处的公开样本/来源页 → 看覆盖范围 → 试跑历史基线
→ 核对一条证据 → 导出样稿 → 保存周期任务 → 付费或团队试点
→ 连续交付 → 分享给获授权的同事/客户 → 申请新专题
```

推广围绕“让用户看到真实完成的工作”，不靠内容热榜或夸大的全行业覆盖。第一个对外样本可用青岛公示与正式公布的历史变化，清楚标注日期、来源和覆盖缺口。

### 6.2 小程序内要做的营销功能

| 功能与阶段 | 怎么做 | 为什么、衡量什么 |
|---|---|---|
| **真实样本馆（MVP）** | 可浏览经过核验的历史简报、来源卡和导出样张；标注“历史示例” | 让第一次来的人看到结果；衡量样本→试跑→保存任务，不用假“本周数据” |
| **覆盖申请（MVP）** | 在“仅导航/未覆盖”组合下提交行业、地区和用途，取得同意后记录联系需求 | 由需求决定下一批连接器；统计申请数和转成试点的比例 |
| **分享来源卡与简报摘要（Beta）** | 分享卡保留官方原站、日期、状态和覆盖范围；分享权按资料许可过滤 | 让顾问向同事或客户展示证据；衡量分享后真实任务创建，不设置强制分享解锁 |
| **团队邀请与品牌模板（Beta）** | 邀请同事协作；付费团队可用机构 Logo 和自己的报告模板 | 机构内部扩席位；顾问对外报告由其决定是否显示工具品牌 |
| **发布方主页（Beta）** | 发布方核实身份后维护题录、原站和授权范围；给出导流统计 | 帮更多人发现优质企业报告；合作内容与广告显著标识，不改变证据权威排序 |
| **推荐资料库与纠错（MVP）** | 用户提交链接或指出错误；进入审核队列再发布 | 扩充长尾来源，测量新增来源被真正使用的比例 |
| **活动与归因面板（Beta）** | 给公众号文章、机构合作、研讨会等入口使用单独活动码；只记必要的转化事件 | 知道哪个渠道带来“已核证报告”和付费，避免只看浏览量 |

### 6.3 站外推广与合作

1. **启动期：**先做有预算上限的真实资料与功能试点，发布公开可浏览的历史样本、来源导航和免费试用入口；从公众号、行业社群和专业内容引导愿意尝试的人进入。可以邀请顾问演示并记录反馈，但不以找到指定数量的受访者为启动条件。
2. **内容：**围绕已覆盖的专题写“本周变化说明”“名单公示与正式区别”“来源导航”，每篇都标原站与截至时间。可在公众号、行业社群、专业活动展示，再引到小程序的具体证据卡；不能自动编造“全行业本周热点”。
3. **合作：**与园区、协会、报告发布方谈题录导流和联合专题；企业报告全文的 AI 使用、下载和衍生报告须另签权利。任何合作推广位都明确标注，不影响官方来源的排序。
4. **留存：**用户授权后按任务发送完成/失败提醒；打开后第一屏展示实际检查情况。企业邮件或工作应用只发许可范围内的摘要与安全链接，并能取消订阅。

**不采用的增长机制：**强制分享解锁、虚构热榜、批量群发、来源未核实就生成宣传稿、对顾问的客户直接营销。平台分享、订阅消息和支付规则在上线前按现行官方要求复核。

**推广指标：**来源页访问→试跑基线→核一条证据→首次导出→保存任务→连续四次任务→付费/续用。北极星指标是**按期交付且出处可核的报告数**；同时跟踪来源失败率、人工修订分钟数、漏报、名单状态错误和每份报告的服务成本。

## 七、收费与单位经济

收费对象是持续监测、证据核验、报告交付、协作和授权数据服务；公开原站链接与基础题录适合免费开放。以下是**价格实验区间**，尚无用户或成本数据证明合理：

| 层级 | 实验报价 | 产品边界 |
|---|---:|---|
| 免费 | ¥0 | 全行业来源导航、已开放题录、有限的历史样本与原站链接 |
| 按份自动报告 | ¥29–79/份 | 一个已监测专题的自动草稿与标准 XLSX/DOCX，标注覆盖和待核项 |
| 个人专业版 | ¥99–199/月 | 少量周期任务、证据问答与月度导出额度；仅限已监测专题 |
| 团队版 | ¥799–1,999/月 | 多席位、客户项目、共享模板、版本与审计、更多任务额度 |
| 专项服务或授权数据 | 按合同报价 | 人工复核、定制来源、品牌交付、版权方授权全文、企业系统对接 |

**试价办法：**先开放基础资料发现和真实样本，记录自愿试用者的搜索、任务保存、导出与复访；有持续使用后，再向需要高频监测或团队交付的人展示两档价格，记录实际购买、拒付原因和四周使用。按“合同收入－模型/解析/存储－人工质检－资料授权－支付与服务成本”核算单份贡献。若一份报告持续需要大量专家重写，就把它作为“软件加专家服务”单独报价。小程序内购买、对公合同开通与后续自动续费的实现路径须依据当期平台规则核验，不用外部支付绕开审核。

## 八、开发阶段、交付物与继续条件

**建议团队：**产品兼客户研究/商务 1 人、数据源与质检 1 人、后端/AI 1–2 人、小程序前端 1 人；设计、测试、法律/版权顾问按阶段参与。来源维护和用户纠错是持续岗位，不只是上线前的开发任务。

| 阶段与粗估 | 交付物 | 为什么才能进入下一阶段 |
|---|---|---|
| **S0 规格和来源验证，约 1–2 周** | 完整 PRD、覆盖分级、首个专题金标、来源权利表、3 个关键屏、预算上限与免费入口设计 | 官方样本、规则和未覆盖范围说得清楚；无需等待客户或预订单 |
| **S1 真实技术切片，约 4–6 周** | 2–3 个获准试验的官方栏目连接、版本和失败日志、状态机、证据卡、运营待核台、真实 XLSX/DOCX 样本 | 历史回放中关键状态不混写；来源失败不假称无更新；样本可逐条回原站 |
| **S2 小程序受控 Alpha，约 4–6 周** | 任务确认、本周简报、覆盖地图、文件柜、限定证据的 AI 摘要；iOS/Android 真机文件检查 | 目标人员能无引导完成建任务、核证和导出；连续运行与人工基线有记录 |
| **S3 公开 Beta 与收费实验，约 4–6 周** | 更多已校验专题、团队与权限、授权提醒、首个外部连接；对高频功能试价，必要时增加 PDF/PPTX | 公开使用路径能跑通，质量、授权和平台审核通过；收费只针对已可靠交付的功能 |
| **S4 扩行业，持续进行** | 来源模板化、地区和行业扩充、发布方合作、跨行业比较、更多格式与连接 | 按来源稳定、真实搜索和覆盖申请、任务复访、服务成本及后续付费证据决定扩张顺序 |

按上述阶段顺序，约 13–20 周形成受控付费试点只是粗估；来源授权、平台审核和实际团队能力会改变排期，不是交付承诺。

**首批验收硬线：**①无证据的关键结论不能导出为确定事实；②公示不得写成正式认定；③来源失败必须显式显示；④只有题录权限不能经 API 取到全文；⑤导出的 XLSX/DOCX 包含出处、状态和截至时间，并在目标手机与 Office/WPS 打开；⑥重复导出与投递不重复扣费或发消息。错误率、可用性和省时阈值在试点前冻结，以真实样本测量；不承诺模型“零幻觉”。

**现有材料需对齐：**当前 v2 原型默认“山东医疗健康”并列出尚未接入的全国来源。进入 S0 时要把历史回放、覆盖徽章和首个青岛专题的来源范围改成一致；现有原型只能用于讨论布局，不能视为已通过可用性测试。此前[无客户启动调研](./无客户启动_市场证据与真实数据试点_v3.md)支持有预算上限地先做技术验证；本方案进一步明确，用户访谈和付费意向不是启动门槛，实际使用会指导后续扩展与收费。

## 十、页面级功能规格：用户实际会看到什么

### 10.1 首次使用和全局交互

首次进入先让用户选行业、地区、关注主题；行业支持搜索和多选，地区支持全国/省/市三级，主题至少区分政策、申报、认定名单、统计指标、行业报告、企业研究。选择后立即显示**覆盖说明**，例如“该组合有 2 个已监测栏目、5 个可跳转来源、统计指标本月未更新”，不能把“可找到原站”写成“已完整收录”。无需注册即可浏览公开题录和历史样本；保存监测任务、导出个人文件、订阅提醒时再登录。

所有资料卡统一呈现：标题、发布者、资料类型、发布日期或统计期、地区与行业、来源链接、获取权限、核查状态。主要动作是**看原站、加入证据篮、问这份资料**。若只有题录，问答只允许针对题录，明确标示“未读取原文”。

### 10.2 五个核心工作页面

| 页面 | 默认内容与主操作 | 必须处理的状态 |
|---|---|---|
| **本周简报** | 任务切换、截至时间、已检查/失败来源数、变化分组、纳入/剔除/批注、导出 | 首次历史基线、检查成功但无变化、部分来源失败、待人工核对、导出排队/失败 |
| **任务编辑** | 一句话输入与模板、行业/地区/主题/关键词/关注企业、必看来源、频率、接收人；主操作“试跑历史基线” | 需求含糊时要求确认，选到未覆盖组合时显示缺口，任务暂停/恢复须留痕 |
| **发现资料** | 综合搜索、行业目录、地区、发布方主页、来源地图、政策/指标/名单/报告分栏 | 没有结果给原站建议与申请覆盖；来源失效显示最后核验时间；付费或登录限制不能冒充无资料 |
| **证据与 AI** | 原站、可用正文段落/附件页码、版本、相关变化、AI 问答、引用清单 | 无全文权限、证据冲突、来源撤稿、AI 服务不可用时说明原因；不编造答案 |
| **我的文件与团队** | 报告版本、导出状态、下载与删除、授权连接、团队权限、用量与纠错 | 文件过期、无权访问、生成失败、重复点击、成员离开团队后权限收回 |

**手机与电脑分工：**小程序负责发现、提醒、核证、轻量编辑、发起导出和下载；几十页报告的深度改写可先用导出的 DOCX/XLSX 在电脑完成。只有真实使用证明需要多人在线编辑时，再建独立 Web 研究台，避免首版同时造两套编辑器。

### 10.3 用户说一句话以后发生什么

示例：“每周一帮我找青岛医疗器械政策、新公布的企业认定名单和行业报告，做一份周报。”

1. AI 返回**待确认任务卡**：行业、地区、时间范围、主题、名单状态、关键词、候选来源、周一频率、预期文件格式；每项可修改。
2. 后端根据来源台账显示候选来源的权限、覆盖档位、上次成功检查和计划频率；用户决定是否保留未监测来源的原站链接。
3. 用户点“先试跑”，系统回放可获取的历史资料并生成**历史基线**，绝不把历史条目标成“本周新增”。
4. 用户确认保存后才建立周期任务。调度器按时运行，成功与失败来源分别计数；对有版本变化的条目去重、识别状态、进入待核队列。
5. 用户在本周页决定哪些条目进入报告，再生成结构化报告。AI 只能使用当前用户有权使用的资料；导出文件保留来源和截至时间。
6. 用户明确开启提醒或外部连接后才投递；后台记录投递对象、时间、状态和重试，防止重复发送。

**一次性搜索**走同一检索与证据链，但不自动建立周期任务。用户给出一个 URL 时，先按该站的访问条件和资料权利判断能否抓取与分析；不能处理全文时仍可存题录、跳转原站或请求授权。

## 十二、必须明确的业务规则与状态

| 对象 | 状态或字段 | 规则 |
|---|---|---|
| 覆盖范围 | `MONITORED / DIRECTORY_ONLY / UNCOVERED` | 只有 `MONITORED` 可承诺定期检查；覆盖地图给出最后核查时间与必看来源缺口 |
| 内容权利 | 题录、链接、短摘、全文存储、AI 阅读、导出、再分发、团队分享 | 各动作单独授权；未获权内容不能因用户订阅或后台 API 而升级权限；许可到期自动停用 |
| 来源检查 | 待检查、成功、未变化、发现变化、失败、待人工处理 | “未变化”必须建立在成功检查上；失败进入补跑和缺口提示 |
| 周任务运行 | 排队、检查中、部分完成、待核、可交付、已交付、失败 | `部分完成` 报告允许查看，但显示失败来源并避免“全部无变化”的表述 |
| 名单事项 | 申报、拟认定/公示、正式公布、复核、撤销、未知 | 以官方发布动作和附件行级证据为准；公示结束但未见正式文件仍是“待正式公布” |
| 报告结论 | 官方事实、发布方观点、模型推断、待核 | 每个确定性事实至少关联一个具体来源版本和位置；矛盾证据呈现并列状态 |
| 文件 | 生成中、可下载、失败、已过期、已撤销 | 重试不重复扣额度；撤稿、用户删除或授权到期触发文件处置策略 |

**规则示例：**一篇标题含“某企业拟入选”的公示，先记录通知级状态；只有解析并核验附件中该企业的行，才能对该企业形成“拟入选”记录。后来出现正式名单，建立新事件并关联原事件，不直接把旧文档改成正式版。这样可还原变化时间线。

```text
Resource(id, source_id, canonical_url, title, type, published_at,
         period_start, period_end, region_tags, industry_tags, access_level)
DocumentVersion(id, resource_id, source_hash, observed_at, effective_at, status)
EvidenceSpan(id, version_id, page_or_row, excerpt, exact_location, confidence)
Company(id, official_name, registration_key_if_available, aliases)
RecognitionEvent(id, company_id, version_id, program, batch, stage, event_date)
DatasetSeries(id, resource_id, indicator, value, unit, region, period, method)
MonitorTask(id, tenant_id, owner_id, scope_json, schedule, source_ids, status)
FetchRun(id, source_id, started_at, ended_at, outcome, error_code, version_ids)
Digest(id, task_id, run_id, cutoff_at, coverage_snapshot, status)
Claim(id, digest_id, statement, claim_type, evidence_span_ids, review_state)
ExportJob(id, digest_id, format, report_revision, state, object_key, idempotency_key)
DeliveryAttempt(id, digest_id, channel, recipient, state, idempotency_key)
AuditEvent(id, actor, action, object_type, object_id, at)
```

`Resource` 是资料本身，`DocumentVersion` 记录变化，`EvidenceSpan` 是被引用的位置，`Claim` 是报告中可核查的句子。用户上传的私有资料附加 `tenant_id`，公共资料和私有资料在检索、缓存、模型输入、导出与分享层均隔离。原始附件是否保存、保存多久，由权利和数据生命周期规则决定。

### 13.2 API 契约草案

| 接口 | 输入/输出重点 | 保护规则 |
|---|---|---|
| `GET /v1/catalog/coverage` | 行业、地区、主题→覆盖等级、来源数、最后核查 | 不把未监测来源计入监测成功数 |
| `GET /v1/resources/search` | 查询、过滤、分页→资料卡及可用动作 | 服务端再做权限过滤；不能只靠前端隐藏按钮 |
| `POST /v1/tasks/interpret` | 自然语言→待确认结构及模糊项 | 仅建议，不创建或外发任务 |
| `POST /v1/tasks/preview` | 确认的范围→覆盖说明、历史基线作业 ID | 预览有成本配额；历史资料单独标记 |
| `POST /v1/tasks` | 确认后的范围、来源与频率→任务 ID | 认证、配额、幂等键 |
| `GET /v1/runs/{id}` | 每个来源的检查结果、失败原因、截止时间 | 不隐藏部分失败 |
| `POST /v1/questions` | 问题、已选资料或证据篮→回答、引用、缺口 | 严格按 `RightGrant` 与租户权限召回 |
| `POST /v1/digests/{id}/exports` | 格式、报告版本→导出作业 ID | 异步、幂等、额度在作业确认后结算 |
| `GET /v1/exports/{id}` | 状态、有效期、受控下载链接 | 权限复查、短时链接、审计 |
| `POST /v1/connections` | 渠道、授权范围→连接状态 | 明示授权、撤销与失败恢复 |

接口错误需统一返回 `code/message/request_id/retryable`。列表使用游标或稳定分页；状态变更留审计。正式编码前把响应样例、字段校验、权限矩阵和版本策略冻结成可执行契约。

### 13.3 后台作业怎么串起来

```text
批准来源 → 定时发现 URL/接口数据 → 保存抓取结果与失败日志
→ 规范化题录 → 去重及版本比较 → 权利检查
→ 允许的正文/表格解析 → 日期、文号、指标、名单状态提取
→ 规则验证与人工待核 → 进入搜索索引
→ 按任务匹配增量 → 简报草稿/证据 → 用户确认 → 异步导出/授权投递
```

公共来源由平台集中同步一次，匹配给多个用户任务；不要为每个用户重复抓同一个政府栏目。临时网络检索优先调用有授权的搜索服务或已批准站点；搜索到新站先进入来源审核，不让 AI 自主绕过登录、验证码、反爬限制或资料许可。未授权的企业库可以收录其公开题录和原站入口，但全文问答与原件下载需要另行核权。

## 十四、参考技术栈与工程实施

**建议而非已选型：**微信原生小程序 + TypeScript/WXML/WXSS；Python API 服务与解析/AI 工作者；PostgreSQL 存业务及来源版本元数据，先用关键词全文检索；Redis/作业队列跑采集、AI、导出和投递；对象存储放获权附件与导出件；简单 Web 运营台管理来源、权利、待核项与纠错。这样前台与后台边界清楚，Python 可复用文档解析能力。具体框架、云服务、模型供应商和成本要在 S0 按团队能力、许可与部署地区定稿；不要为首版引入多智能体平台或复杂知识图谱。

**代码模块拆分：**`miniapp`（四栏及证据/导出页）、`api`（身份、目录、任务、权限、报告）、`ingest`（逐站连接器和解析器）、`ai`（任务解释、限定证据问答、结论校验）、`exports`（四格式渲染器）、`ops`（来源和审核后台）、`infra`（队列、存储、监控）。一个模块一个责任人和验收记录；连接器有统一输入输出契约，不能把特定网站选择器写进通用业务逻辑。

**AI 的边界：**AI 负责把需求结构化、提炼非关键摘要、组织已有证据和比较建议；文号、金额、日期、统计单位、名单阶段、权利许可和“是否检查成功”由结构化字段与确定性规则约束。模型回答应包含引用 ID、原文位置和“不足以回答”的理由；模型升级、提示词变更、解析器变更都对金标案例回归。无模型或调用失败时，用户仍能查看来源目录、原文入口和非 AI 简报，界面明确显示 AI 暂不可用。

**质量与运行：**每个连接器记录成功率、上次成功时间、页面结构变化和解析错误；来源异常触发运营工单。作业队列设限频、重试上限、幂等键与死信处理；导出保存输入的报告版本，以免 AI 后续重写导致同名文件内容变化。备份、恢复、审计、敏感日志脱敏、团队隔离、授权撤销后停投递，均需在对外开放前实测。

**外部应用路线：**第一批仅做用户明确授权的邮件或一个团队工作应用的摘要投递；第二批增加授权导入企业资料、发布方提交题录、组织级目录同步。每个连接器分别处理身份、令牌过期、速率限制、服务故障、撤销和重复投递。对外只发有分享权的摘要与受控查看链接；不要把版权文件自动转存进第三方应用。

## 十五、开发任务、人员和交付验收

### 15.1 按依赖顺序开发

| 迭代 | 工程任务 | 可检查的成果 |
|---|---|---|
| A：规格与样本 | 定来源台账、资料权利卡、行业标签、名单状态机；建立 20–50 条人工核验的真实金标案例；冻结页面流程与 API 样例 | 金标每条有原站/日期/预期结果；尚未覆盖清单公开 |
| B：数据底座 | 实现 2–3 个获准连接的栏目、抓取日志、规范化、版本、失败补跑、运营待核台 | 反复运行不会重复记录；公示与正式通知可重放；故障可见 |
| C：小程序闭环 | 登录与目录、搜索、任务确认、历史基线、本周简报、证据抽屉、XLSX/DOCX | 用户能从一句话需求走到带证据的可编辑文件；失败与空状态可见 |
| D：AI 与公开 Beta | 限定证据摘要/问答、模型评测、来源覆盖申请、样本馆、分享卡、隐私与错误报告 | 无权资料不进入模型；无答案能拒答；公开样本与真实运行分开 |
| E：扩展 | PDF/PPTX、团队、首个外部连接、跨行业证据篮、价格实验 | 每项独立验收；只开放已通过的格式和渠道 |

这与第八节的 S0–S4 是同一条路径：A 对应规格，B/C 对应真实切片和受控 Alpha，D/E 对应公开 Beta 和扩行业。工作可以在不相互抢占数据模型的前提下并行；来源权利、状态机和证据模型应先于大规模 UI 和 AI 功能。

### 15.2 人员、预算与持续维护

建议 4–5 个核心角色：产品与内容负责人、来源/数据质量工程师、后端兼 AI 工程师、小程序前端、测试兼运营；设计、版权/隐私、商务按阶段加入。预算用**人月 + 云与模型调用 + 文档解析/存储 + 来源授权 + 持续质检**五项测算，不用未经报价的固定总价。S0 先设预算上限和停止条件；若一个专题的来源频繁失效、人工纠错超过可承受成本，就缩小该专题或改为来源导航。上线后仍需要来源维护与纠错值班，资料库不会靠一次抓取永久更新。

### 15.3 首批验收案例（上线前逐条留证）

| ID | 输入/故障 | 期望结果 |
|---|---|---|
| AC-01 | 用户选到只有题录的企业报告 | 看得到目录与原站；AI 不引用未授权全文；不能下载原件 |
| AC-02 | 官方名单只有“拟通过”公示 | 企业记录与周报不得写“正式获批” |
| AC-03 | 公示后网站未找到正式公告 | 显示“待正式公布”，不推定落选 |
| AC-04 | 一个必看来源超时，其他来源无变化 | 本次“部分完成”；注明失败来源，不能写“全部无更新” |
| AC-05 | 同一文件多次点击导出或作业重试 | 一份逻辑订单/额度消耗，内容与报告版本一致 |
| AC-06 | 用户撤销团队成员或外部应用授权 | 受控文件和新投递立即不可用；留审计 |
| AC-07 | AI 被问到没有证据的金额、日期、企业获奖 | 明确无法确认并给可用来源，不能造数 |
| AC-08 | 两个行业指标年份或口径不同 | 在比较表中并列标示，不直接相加或给无依据的增长率 |
| AC-09 | iOS/Android 真机与电脑端打开文件 | 表格列、中文字体、来源脚注、链接和页数可读；失败可重新下载 |
| AC-10 | 官方网页改版或许可到期 | 连接器报错/权利动作停用；旧结论进入复核，不静默沿用 |

上线判定分别记录**规格完成、代码完成、测试通过、平台审核、真实数据运行、公开试用、收费能力**，不能用原型截图或一次成功导出代替全部完成。若将来收费，还需真实支付、退款、对账与重复回调检查；具体通道和小程序能力按届时申请主体的官方平台要求核验。

## 十六、没有客户时怎样启动并找到第一批使用者

**先建可公开展示的种子内容，不等签约。**建议挑选能由官方原站逐条核实的 2–3 个主题，覆盖至少一种政策、一种名单状态变化和一种统计指标；企业报告先做可检索题录与导流。每个主题发布一个带日期、来源、覆盖缺口的历史样本和一个可亲手完成的任务模板。所谓“全行业”从第一天提供分类与来源申请，但没有深度覆盖的行业不显示实时监测承诺。

**把营销入口直接连到功能：**公众号或行业社群文章展示一条真实变化→打开对应证据卡→用户试跑相似任务→保存周任务→收到实际完成提醒→下载报告。发布方合作页导回原站，优质资料被发现的次数可反馈给发布方。每一步记录必要的匿名或经授权行为指标：资料卡打开率、任务创建率、首次导出率、四周复访率、来源失败率、人工修改分钟数。不要以浏览量或 AI 对话次数代替真实工作成果。

**判断是否继续扩张：**先看来源是否可靠、证据是否可核、用户能否完成一次任务、是否自发复访；再看哪些行业/地区被搜索或申请覆盖、报告是否真正被导出与分享。没有付费也可继续完善有明显使用的基础资料服务；高成本的全文授权、专属连接和人工复核应在需求与成本明确时再投入。收费是第二阶段的商业实验，不是证明这个想法能不能启动的前置许可。
