# Claude 审查：全行业资料库 AI 小程序方案修订清单

**日期：**2026-09-24  
**审查对象：**[v5 产品、功能与开发规格](./全行业资料库AI小程序_完整产品功能与开发规格_v5.md)  
**后续整改：**[v5.1 完整产品与开发主规格](./全行业资料库AI小程序_完整产品与开发主规格_v5.1.md)已按本清单修订文档级问题；实际来源权利、平台能力和运行验收仍待 S0/S1 完成。  
**边界：**Claude 只读审阅了 v5、既有方案、青岛试点脚本与原型文字；没有运行脚本、改动文件或核对外部网页。Codex 另外核对了下面明确标记的本地事实，并查阅了文内链接的官方法规。此报告是方案审查，不代表小程序已开发或合规审批完成。

## 总判断

**方向可以继续，v5 适合做 S0 的输入，尚不能直接作为冻结的开发规格。**最有价值的设计是“全行业来源导航 + 已监测专题的深度交付”、三档覆盖、失败不等于无更新、公示不等于正式、结论可追到原站和同一份报告生成多个文件。主要缺口集中在首版范围、来源发现、状态转移、工作流数据、AI 问答验收以及平台手续的排期。

用户提出的“没有客户也可以先做”已经在 v5 里正确表达：不需要访谈或预订单作为开发门槛。建议由团队先用产品做公开的真实周报，再观察自然使用。

## P0：进入核心开发前必须修订

| 问题 | 已核对的依据 | v5.1 应如何改 |
|---|---|---|
| **首版范围不统一** | v5 §4、§8、§11、§15 对 AI 问答、样本馆、覆盖申请、统计卡、团队功能的阶段划分不一致 | 建立唯一发布矩阵：受控 Alpha、公开免费版、收费实验、后续扩张；其他章节只引用这个矩阵。受控 Alpha 可先有 AI 任务解析，公开版再开放经评测的单文档问答；统计卡等到有真实统计来源再开放 |
| **现有试点不能发现新公告** | `pilot-qingdao/source_registry.json` 只有 3 个固定文章 URL；`sync.py` 仅检查这些 URL 的页面变化，没有栏目列表发现、翻页或新文章接入。Codex 已只读复核 | 核心连接器必须从栏目列表发现新 URL，再取详情和附件；记录发现时间、发布时间、所属栏目与版本，覆盖所有必看栏目；固定 URL 脚本只保留为历史样本检查工具 |
| **试点失败后的“首次发现”可能误判** | `sync.py` 的 `latest.json` 在来源失败时保存失败记录，覆盖上次成功结果；下次恢复后缺少旧指纹，会产生 `first_seen`。Codex 已只读复核 | 分开保存“最近一次成功内容”与“本次检查结果”；恢复后和最近一次成功指纹比较；迟到发现单独标注发布日期和首次观测日；此轮只审查，不运行或修复脚本 |
| **首个专题更新太稀疏，周报可能长期为空** | 既有试点是少量企业认定文件；是否每周有新信号尚未统计 | 在 S0 核查栏目过去 12 个月的事件数；若低频，改为“青岛企业认定 + 申报通知”的组合，或提供事件触发/月报选项。历史基线按近 12 个月或最近 N 件事件设计，不固定四周 |
| **状态模型不足以处理真实公告** | v5 §12 把“复核”与“公示/正式”混成一个维度；任务“部分完成”和“待核”也混在同一状态栏 | 分开记录事项类型、发布阶段、资格有效性；任务运行另拆“来源完整度”和“工作流状态”。补充更正、撤回、未通过、到期、来源失败及恢复的转移规则。未监测正式公告来源时只能写“正式状态未知” |
| **报告工作流缺数据实体和接口** | v5 §13 的 `Digest` 只指向单个 `FetchRun`，但一个任务可检查多个来源；没有简报条目、报告版本、额度账本，也缺任务暂停/恢复和纠错接口 | 增加 `TaskRun`、`DigestItem`、`ReportRevision`、`ClaimEvidence`、`EntitlementLedger`、`CorrectionReport`、`CoverageRequest`。`Digest` 关联 `TaskRun`，导出键绑定报告版本、格式和模板版本；补全读写接口及权限矩阵 |
| **AI 问答没有可执行的答案契约** | v5 有“带出处”“无答案”等原则，但没有返回格式、引用位置校验、问答金标和上线阈值 | 名单、企业、日期先查结构化数据；政策解释再用模型。答案拆为事实/观点/推断，每段含证据 ID 和位置；无证据明确拒答。S0 建含拒答案例的金标，公开前冻结引用正确率与拒答指标；导出件增加适用的 AI 标识 |
| **资料使用权利与平台手续没有进入关键路径** | v5 只说“上线前核对”，S0–S3 没有来源权利审核、主体/类目/AI 功能核验的明确工作包 | S0 同步开“资料权利和平台能力”工作包：逐来源记录访问方式、许可依据、可存储/AI 阅读/下载/分享动作；确认小程序主体、服务类目、域名、AI 功能登记或备案适用性、隐私文本、支付路径。未获确认的功能按开关关闭，不以“日后补办”当成已通过 |
| **覆盖地图可能夸大行业深度** | v5 从“行业×地区×主题”推覆盖，但专精特新名单跨行业，现有模型没有企业行业字段 | 来源覆盖按地区、主题、栏目计算；行业只在有可靠标签时参与筛选。跨行业来源标“全行业来源，条目行业未标注”；不得对任意行业声称名单检索完整 |

### 权利与手续的证据边界

Claude 提议把政府公示及其附件一律按“可存档、解析、AI 阅读和导出”处理。**Codex 不采纳这个一揽子结论。**现行[《著作权法》第五条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)确实将具有立法、行政、司法性质的官方文件列为不适用著作权法的对象，但这不能自动判定每份附件、网站解读、图片或第三方汇编的权利，也不能代替站点访问条件与其他数据处理要求。S0 应逐类、逐来源记录依据并请专业人员确认。

公开生成式 AI 功能的适用要求也需要按产品主体和提供方式判断。[《生成式人工智能服务管理暂行办法》](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)规定了向境内公众提供相关服务的范围；[网信办已备案信息公告](https://www.cac.gov.cn/2024-04/02/c_1713729983803145.htm)涉及已上线应用对所用模型备案情况的公示；[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)涉及生成内容导出时的标识。不能据此推定本小程序必然适用某一种手续或固定周期，需在 S0 由申请主体按当期官方要求核对。

## P1：公开试用前补齐

1. **中文检索质量：**不要假定数据库默认全文检索就足够。用真实中文查询金标比较召回、排序与成本，再定具体索引方案。
2. **文件撤销文案：**已下载的文件无法远程收回。应承诺撤销后阻止新的下载和投递、使受控链接失效，并对已下载件标明生成者、时间和使用范围。
3. **手机到电脑的交付路径：**明确小程序里文件如何保存、分享给自己并在桌面打开；在目标手机及 Office/WPS 实测，不能只验证服务器生成成功。
4. **提醒可靠性：**不要假定微信可按周无条件主动推送。按当期订阅消息能力核对后设计授权与降级，首版仍应支持用户主动打开查看。
5. **权利判定先于全文持久化：**未完成许可判断前只保存必要题录和指纹；需要临时检查的内容走隔离区、限时删除，不能先批量存全文再补权利审核。
6. **人员与成本：**现有 4–5 人粗估中，一个后端/AI 角色承担连接器、解析、API、导出、运营台和 AI，排期偏紧。S0 应以具体人名和人月重估，并计算来源维护、搜索接口、企业行业数据与资料授权成本。
7. **一次性全行业搜索：**若要首版就“全行业可搜”，可评估有授权的外部网页搜索服务，只展示允许显示的题录和原站，并标“外部未核验结果”；其缓存、摘要和 AI 使用权需逐项核对。
8. **补充验收：**历史基线不能算本周新增；来源恢复后的迟到发现；企业同名/更名；更正公告；越权访问；删除账户；AI 标识；正文“等 N 家”与附件逐行计数不一致时进入待核。

## 可以保留的设计

- 全行业广目录、逐专题深监测、三档覆盖；没有客户也可以先做真实免费工具。
- 公示与正式分开；来源失败不写成“无更新”；报告结论逐条有证据。
- 资料权限按动作拆分；未经授权的企业报告先做题录和导流。
- 模块化单体、异步队列、同一报告对象生成多格式；先不建多智能体或复杂知识图谱。
- 手机负责发现和核对，导出到电脑继续编辑；增长围绕真实成果，不用强制分享。

## 建议的下一版交付顺序

1. **S0：**用 1–2 周冻结唯一发布矩阵、三类状态转移表、关键数据实体和 API、来源清单及权利记录、问答金标与预算上限；同步启动平台能力核验。无需先找到客户。
2. **S1：**先让栏目发现、附件证据、来源健康和非 AI 简报持续运行；团队自己每周人工对照并公开一份带出处的历史或当期样本。
3. **S2：**做小程序受控版：发现、任务、简报、证据、XLSX/DOCX、文件柜和纠错。找自愿试用者做可用性测试，但不把其人数当开工门槛。
4. **S3：**在权利、平台能力和金标评测通过后，开放引用问答、覆盖申请、分享与收费实验；跨行业整合、PPTX和更多外部连接按真实使用推进。

**审查结论：**现在可以继续做 S0 规格和来源验证；在上述 P0 事项修订前，不应把 v5 交给开发团队当作已经无歧义的实现合同。Claude 的审查没有代替用户、版权专业人员、微信平台或主管部门的确认。
