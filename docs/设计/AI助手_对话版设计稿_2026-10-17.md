## 一、这版要解决什么

创始人 10/17 试用 AI 内测（政策解读、条款对照，白名单只开给本人）后，觉得页面乱、逻辑不清：要先进「工具中心」，再选功能、等「任务」、去「任务中心」看结果。10/17 定的方向：

- AI 统一成一个入口「AI 助手」，进去是对话页：打字提问；可以上传图片（拍纸质通知、截图、营业执照）并识别；需要时联网检索；最后汇总成回答。
- 联网只查政府官网（gov.cn 等），不查全网。
- 「有据」原则：回答优先来自我们自己抓取的官方通知库；每句结论带出处（哪份通知、原文哪句，可点「看原文」）；找不到就说找不到。联网查到的内容标「来自政府网站、未经人工核对」并列出链接。
- 从通知详情点「AI 解读」，进入同一个对话页，自动带上这份通知，顶部给快捷按钮。
- 现有两项能力（政策解读、条款对照）变成对话里的结构化卡片；不再让用户理解「工具页」「任务」。

这改变了 [D-040](../决策记录.md) 里「点进去是整页，不做半屏和开放式聊天」的做法。D-040 不做开放式聊天的理由是：结果是长表格、生成慢要有进度、开放聊天容易答偏。对话版分别这样处理：长结果做成卡片（屏 3、7）；生成过程在卡片里显示进度（屏 9）；只回答申报通知相关的问题，范围外的直接说做不了、不扣次数（屏 9）。创始人确认后，在决策记录里补一条取代 D-040 这部分的决定。

## 二、入口和流程

| 从哪进 | 进来是什么 |
|---|---|
| 首页「AI 助手」入口 | 空白对话（屏 1）；下面是「最近问过」，按通知列出以前的对话 |
| 通知详情右下角「AI 解读」 | 带上这份通知的对话（屏 2）；这份通知以前问过的，接着原来的对话 |

- **每份通知一条对话。** 以前的划重点、对照结果都在这条对话里，不再有「任务」「任务中心」。换一份通知不丢原来的对话。不带通知的提问是一条通用对话。对话和整理结果保存 30 天（沿用现在的结果保存期），可以删除。
- **第一次用之前先同意使用须知。** 提问、点按钮、发图片，哪个先发生都先出须知（屏 9），同意后接着处理刚才的操作，不用重来。
- **对话里出现的卡片：** 划重点、要准备哪些材料、和我的企业对一下、自由提问的回答、识别图片、联网查政府网站。「要准备哪些材料」和划重点用同一份整理结果，共用 1 次。
- **「工具中心」只留数据工具**（批量名单比对、客户相关通知表），它们不是生成式 AI，不并进 AI 助手。
- 底层可以继续用现在的 `advisor_tasks` 队列和缓存，只是界面上不再出现「任务」。

## 三、每屏要点

所有画面宽 390，按小程序真实尺寸画；长画面是整条对话的长截图，输入框在最下面。图标只用小程序本地图标集里已有的（`tools/icons/icons.txt`），生成脚本里用了表外的图标会直接报错。

全稿统一的视觉约定：灰底块 = 通知原文原句；浅蓝底 = 用户填的企业情况；浅橙底 = 提醒（附件、未经人工核对、个人信息）；蓝色气泡 = 用户说的话；白卡片 = AI 的回答，开头标「AI 生成」，末尾写免责、模型和备案号、复制、投诉举报。

| 屏 | 画面 | 设计意图 |
|---|---|---|
| 1 | 首页 · 第一次打开 | 一句话说清能做什么（问申报通知里的事，每句回答都标出处），下面是三种问法（查通知、拍图片、联网查）和示例问题。顶部固定一行「AI 生成 · 第三方整理 · 非政府平台 · 以原文为准」，不能关闭；底部常驻模型、备案号、投诉举报。 |
| 1 | 首页 · 点开「说明」 | 第十条要公开的适用人群、场合、用途、不适用，加上次数、图片、保存期限、模型和备案号、投诉举报；默认收起。 |
| 1 | 首页 · 再次打开 | 「最近问过」按通知列出以前的对话（替代「最近任务」），整行可点，接着问。 |
| 2 | 从通知进入 | 顶部是通知卡片（标题、发文机关、日期、文号、附件数）和三个按钮：划重点、要准备哪些材料、和我的企业对一下。点了才开始，不自动扣次数；也可以直接问。 |
| 3 | 划重点 | 附件提醒放最前（附件内容没有读）；截止时间小表分清「企业填报截止」和「市（州）报送截止」，附原文、标「机器摘录 · 未经人工核对」（D-061 的规则：8–30 天内可显示机器摘录）；一排分类计数，点了只看这一类；每句原文只出现一次，标出属于哪几类；没摘到的类别合成一行（「没摘到：支持方式」）；每句可以「看原文」「这句摘错了」。 |

| 5 | 拍纸质通知 | 识别出的文字只用来找原文：标题和文号对上了，就给出收录里的官方通知，后面的回答都按政府网站上的原文来，不按照片。图片下面标「已通过内容安全检测」，识别完删除。 |
| 6 | 拍营业执照 | 拍之前先说清楚：执照上有法定代表人姓名、统一社会信用代码等信息；只识别成立日期和注册地；图片识别完就删；企业情况只用于这次对照，不发给 AI 模型，7 天后清除。按钮是「同意并拍营业执照」。读到的两项标「营业执照」请用户核对；写明是哪家企业（简称，可从「我的客户」选）；每项资质分别填有效期。 |
| 7 | 和我的企业对一下 | 左边是 AI 从原文摘的条件，右边是你填的情况（只在页面并排显示，没发给模型）；原句提到的每一项都列出填了什么或「你没有选」「没有对应的填写项」，只摆事实；每行标「请你自己判断」；表头写「正文 5 条，不含附件」，认定标准在附件里的单独提醒；可以修改、立即删除企业情况。 |
| 8 | 联网查政府网站 | 整块标「来自政府网站 · 未经人工核对」，写明只查了政府网站；先说「没找到专门规定」，相关的两条写明不是专门针对这件事；每个网页标「政策文件」或「新闻转载」，带网站名、域名、日期、摘录；小程序里打不开政府网站，给「复制网页链接」。 |
| 9 | 次数用完、出错、连不上 | 7 种情况放在一起看，实际一次只出现一种：第一次用之前的使用须知；正在整理（服务刚启动时写明大约还要 1 分钟、可以先离开）；范围外的问题；次数用完；没整理出来；连不上；图片没通过检测。每种都说原因、扣没扣次数、下一步。 |

## 五、技术前提

1. **对话要秒回。** api 冷启动约 67 秒（10/12 实测），对话等不了。对话接口要放在常驻的 admin 上，或者给 api 留常驻实例。现在的解读是排队任务加轮询（一般 10–30 秒），对话版要改成边生成边显示；服务刚启动时按屏 9 的写法提示。
2. **图片先过内容安全检测。** 微信的图片检测接口 `/wxa/media_check_async` 是异步的，结果推送回服务器，要实测等多久；等不了就改用同步的腾讯云图片内容安全（按次计费）。没通过的图片不识别、不扣次数。提问文字也要先过文本检测。
3. **看图要另配。** DeepSeek 官方 deepseek-v4-pro 不支持看图。两条路：用文字识别接口（通用文字识别、营业执照识别），只把识别出的文字交给 DeepSeek；或者换能看图的模型（要重新评测，页面公示和网信办登记的模型也跟着改）。
4. **联网只查政府官网，按次计费。** 需要能限定站点的搜索接口，只放行 gov.cn 等政府域名；网页摘录先过内容安全，再交给模型整理。每条结论都要对得上一个网页的原话，对不上的删掉。联网次数单独限额。
5. **每句都有出处。** 沿用现在的逐字核对：模型只给段号和原句，程序回原文核对，对不上的删掉；一条都对不上就回答「没找到」。自由提问的结论句也要挂到原句上，没有原句支撑的结论句不显示。
6. **对照右栏只摆事实。** 原句提到的资质，由程序按资质名称逐项列出「你选了」或「你没有选」；原句里没有对应填写项的要求（如独立法人资格），单列「没有对应的填写项」。不写「符合」「不符合」。
7. **范围控制。** 只回答申报通知相关的问题；代写申报书、判断能不能申报、和通知无关的问题，用固定话术回绝，不扣次数。

## 六、请创始人拍板（5 个）

1. **次数怎么算。** 建议：提问、划重点、对照、识别图片共用每人每天 5 次（要准备哪些材料和划重点共用 1 次）；联网单独算，每天 [3] 次。也可以沿用现在的「每类 5 次」。
2. **对话接口放哪台服务。** 建议先放在常驻的 admin 上（不加钱；抓取任务忙时对话可能变慢）。用的人多了再给 api 留常驻实例，要加钱（10/12 暂缓过）。
3. **图片怎么识别。** 建议用文字识别接口，模型继续用 DeepSeek，公示和登记都不用改。换能看图的模型要重新评测、改公示。
4. **联网检索用哪家、每天几次。** 建议团队先找两三家能限定政府网站的搜索接口，比价格和效果后你定；次数先从每人每天 [3] 次起。
5. **「AI 助手」放在哪。** 建议首页加「AI 助手」入口，通知详情右下角改叫「AI 解读」，不放进底栏；「工具中心」只留批量名单比对和客户相关通知表。
