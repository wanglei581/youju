# 原网页失效的通知 7 天后清理、我的保存：实现说明（D-123，2026-11-08）

> 决策：D-123（创始人 11/8，PR #459）；没定的几件 D-124（创始人 11/8"按推荐"，见第五节）。实现：分支 `claude/gone-cleanup-d123`（PR #461）、`claude/gone-cleanup-d124`（D-124，叠在 #461 上）。开关 `YOUJU_GONE_CLEANUP_ENABLED` 默认关，随 2.0 一起上线；关着时和现在完全一样（D-097：失效的正文、附件不给，不清理，没有保存、导出）。

## 一、规则

| 情况 | 列表卡片 | 详情页、阅读页 | 能不能保存、导出 | 本机清理任务 |
|---|---|---|---|---|
| 原网页能打开 | 照旧 | 照旧 | 没有按钮 | 不管 |
| 失效后第 1–7 天（失效那天算第 1 天，北京时间）、会清理 | 一行提示（写明哪天停止展示） | 标题下提示（写明哪天停止展示），正文、附件照常 | 保存（要登录、要同意新版隐私指引）、导出 Word（不用登录） | 每天再查一次原网页（排最前） |
| 第 8 天起、还没删 | 照 D-097"原文链接已失效" | 照 D-097（正文、附件不给） | 不能 | 当天原网页检查跑完以后删掉 |
| 到期也不清理的（见下） | 照 D-097 | 照 D-097 | 不能 | 不删 |
| 名单类（D-123 ④） | 一直标"原网页某月某日起已撤下"，不写清理日期 | 7 天里正文照常给；7 天过后不给，写"正文不再提供，名单请在“查名单”里按企业名称查询"（D-124 ③） | 7 天里能 | 不删（查名单照常能查到） |

**名单类怎么认**：用系统现有的分类——人工在核对台定过类型的按人工定的，没定过的按标题规则（`classify.effective_kind`；库里 `documents.kind_override`、入库时按标题算好的 `documents.rule_kind`），和列表筛选、查名单里的"名单"是同一个判断。到期清理的查询里直接排除（`coalesce(kind_override, rule_kind) = '名单'` 的不捞），保险起见删之前再按标题判断一次。

**名单类正文**：D-124 ③ 定了：失效后 7 天里照常给（和别的通知一样），7 天过后不给正文、只留查名单。就是原来的代码，没改。

**到期也不清理的**（`gone.KEEP_REASONS`）：名单类（上表最后一行）；另外五种页面照 D-097 显示，不写清理日期：
1. 有下架、恢复记录（下架记录对通知是 RESTRICT 外键，审计记录要留着，删不了）；
2. 别的通知的"截止已变更、见新通知"指向它（RESTRICT 外键）；
3. 原栏目列表 48 小时内还列着、而且是失效以后看到的（删了下一轮抓取会当新文件收回来，关注的人会收到"新文件"）；
4. 同一份通知（归并组）的其他网址还能打开；
5. 原栏目换了新地址：同一栏目、同一标题（去空白）、原网页没失效的另一份，发布日期一样，或者是原网页开始打不开以后才出现的（同名的往年通知不算）。

11/4 线上快照（2669 份，失效 83 份）实测：到期 80 份里，归并组别的网址还能打开 2 份、原栏目换了新地址 2 份，逐份核对都属实。

**恢复**：清理期里原网页又能打开，原网页检查清空 `link_gone_at`，清理取消，页面回到正常。

**附件文字**：D-123 改了 D-097 ③（政策附件文字留 2 年）：失效的文件到期清理时附件文字一起删。通知删掉以后它的附件网址不再在"要留的"范围里，当天的附件任务（每轮抓取的 attachment-texts、每天两次的 cache-attachments）按现有规则删掉附件文字和副本，别的通知还在用的同一网址除外；用户保存的副本是另存的，不受影响。

**删的时候**：一份一个事务，锁住这一行再核对一遍（这期间恢复、下架、换地址的不删），一份出错只记日志、接着删下一份。要求 30 小时内**确认过**原网页还打不开（新加的 `documents.link_gone_seen_at`：只有 404、410、撤稿页才算，网站出错、超时、robots 这些"判断不了"的不算——网站临时出故障时不删，D-123 ①），并且原栏目 48 小时内抓成功过（不然不知道它还列不列着）；不满足的推迟到下次。归并组（同一份通知的不同网址）先后打不开的，页面按各自的 7 天显示，整组等最后一个网址也到期了一起删（中间那几天主条目照 D-097 显示）。删通知用数据库外键规则：正文、截止、附件列表、名单、AI 判断等公开数据级联删除；用户的截止提醒授权、截止线索跟着删，纠错断开；引用这份通知的 AI 结果不再给看、写明原因（D-124 ②，见第五节）；附件副本和附件文字由附件任务按现有规则清掉。用户保存的副本不受影响（不建外键）。2.0 里本机删掉的行经同步通道带到服务器，服务器按外键级联删（#453 已测）。

## 二、我的保存

- 存什么：保存那一刻阅读页给的东西——正文和能读的附件文字（已脱敏、按页面说法换过，和阅读接口同样分段），加标题、发文机关、来源网站、地区、类型、发布日期、原网页打不开的日期、保存时间。不存附件原件。每份最多 4MB（约 130 万字，超过的后面附件不存、标"没存全"），每人最多 200 份（`YOUJU_SAVED_MAX_PER_USER`）。11/4 快照里最大的一份（7 个附件）约 4.8 万字、310KB。
- 表 `saved_documents`（迁移 0049）：`user_id` 随用户级联删除；`document_id` 不建外键（通知清理后副本还在）。不进公开快照、不同步到本机。
- 谁能看：只有本人（按 openid 对应的用户）。看列表、按页读、导出、删除都只认自己的。
- 再保存一次：换成现在的内容（期间附件可能读出来了）。
- 删除：本人在"我的保存"或"我的数据"里删；注销时随用户删；下架的（四种原因都算）删——单库时下架当场删，2.0 里下架在本机做、经同步过来，服务器每天 03:30 的 cleanup 任务删，删之前读的时候就不给（保存以后有过下架记录的也不给，下架后又恢复的同样删）。
- 开关后来关了：已经保存的照常能看、能导出、能删（自己的数据），"我的"页入口在保存过的人那里照常显示；不能再保存新的。
- 保存要同意过写进"您保存的通知"的隐私指引版本（`agreements.SAVED_AGREEMENT_VERSION`，现在占位 `2027-01`，2.0 指引定稿时改成真正的版本号）；只同意过旧版的点保存提示"保存通知要先同意新版隐私保护指引，请更新小程序后重新阅读并同意"。服务器配的协议版本（`YOUJU_AGREEMENT_VERSION`）还早于它时，开关开着也不给"保存"按钮、保存接口 404，只给"导出 Word"（`gone.saving_open`）。
- 通知已经清理、管理台下架不了，又收到要求删除的投诉：在服务器上 `youju saved-purge --doc <通知编号>` 删副本。

## 三、接口

| 接口 | 说明 |
|---|---|
| `GET /api/v1/documents/{id}`、列表 | 清理期里多一个 `gone`：`since`（打不开的日期）、`cleanup`（清理日期）、`notice`、`cleanupNotice` |
| `GET .../reading`、`.../attachments/{aid}/reading` | 清理期里照常给，多一个 `goneNote` |
| `POST /api/v1/documents/{id}/gone-export` | 清理期里导出 Word，不用登录（同导出题录的频率限制） |
| `POST /api/v1/me/saved` | 保存（`{"docId": "…"}`） |
| `GET /api/v1/me/saved` | 我的保存列表（不带正文） |
| `GET /api/v1/me/saved/{id}/reading?part=&cursor=&revision=` | 按页读副本，格式同阅读接口（`part` 空是正文，1、2… 是附件） |
| `POST /api/v1/me/saved/{id}/export` | 导出副本的 Word |
| `DELETE /api/v1/me/saved/{id}` | 删除（没同意过、协议版本过期也能删） |
| `GET /api/v1/me` | 多一个 `saved`：`{enabled, count, max}`；开关关着又没保存过时为 `null` |
| `GET /api/v1/me/data` | 多 `saved`（标题、日期、字数，不带正文）、`savedTotal` |

6. 上线前提醒：全国铺开以后原网页检查的量要跟着扩（D-123 ⑥），不然老文件查不出失效；清理期队列只占失效后 10 天以内的那些；D-124 ① 加的"超过 90 天的申报通知、政策每月查一次"排在最后，全国铺开后平均每天多几千份。

## 六、说法和导出格式（D-124 ④）

照 agy 合规审阅的原句"原网页已无法访问，本平台将于X月X日停止展示；内容变动以官方最新发布为准"：给用户看的地方不再说"清理"（可能被理解成政府废止）、不再说"内容可能已被发布机关撤回或更正"（有猜测之嫌）；哪天停止展示就是清理那天（失效那天 + 7 天）。下面以 10/21 打不开、10/28 停止展示、10/23 保存为例。

- 卡片：原网页已无法访问，本平台将于10月28日停止展示；内容变动以官方最新发布为准
- 详情页标题下：原网页已无法访问，本平台将于10月28日停止展示；内容变动以官方最新发布为准。可以先保存或导出。（第二句按这一页实际给的按钮写：只有导出时"可以先导出。"，都没有时不写）按钮"保存""导出 Word"；保存后"已保存"，提示"已保存，在“我的 → 我的保存”里看"
- 阅读页顶部、清理期里导出的 Word：原网页已无法访问，本平台将于10月28日停止展示；内容变动以官方最新发布为准。
- 名单类（不清理，D-123 ④，没改）：卡片、详情页"原网页10月21日起已撤下"，7 天过后详情页再加"正文不再提供，名单请在“查名单”里按企业名称查询"；阅读页"原网页10月21日起已撤下。"
- 我的保存里的副本（列表、阅读页顶部、导出的 Word 同一句）：原网页10月21日起无法访问；内容变动以官方最新发布为准。这是你10月23日保存的副本。（名单类"原网页10月21日起已撤下。这是你10月23日保存的副本。"）副本不写"本平台将于某日停止展示"：保存以后通知可能已经停止展示、也可能又能打开了，写打不开的那天起总是对的。**这句是照原句改的，请创始人过目。**
- 我的保存其他：状态"约 N 字 / 约 N 万字"或"本平台已停止展示原通知，这里是保存的副本"；删除确认"本平台已停止展示原通知，删除后就看不到了。确定删除？"；空列表、未登录时"原网页无法访问的通知，本平台会再展示 7 天，这期间可以在文件详情里点“保存”……"；页底"保存的是正文和附件文字，不含附件原件；最多 200 份。删除或注销时一起删除；通知因投诉等原因被下架的，保存的副本也一起删除。"（没改）
- 我的数据里保存的通知：原网页 2026-10-21 起无法访问 · 保存于 … · 原通知已停止展示
- 点保存、没同意过协议：保存通知前，请阅读并同意《用户协议》和《隐私保护指引》。……（没改）
- 找不到这份通知：从导出记录回到详情"这份通知原网页已无法访问，本平台已停止展示；保存过的在“我的 → 我的保存”里看"；从分享卡片、关注、旧列表点进来"没有找到这份文件，可能是原网页已无法访问、本平台已停止展示；保存过的在“我的 → 我的保存”里看"
- 保存、导出被拒：只有原网页无法访问 7 天以内的通知可以保存和导出；导出出错"没有找到这份通知，可能本平台已停止展示或已删除""这份通知本平台已停止展示，或者没有能导出的文字"
