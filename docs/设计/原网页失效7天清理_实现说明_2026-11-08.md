# 原网页失效的通知 7 天后清理、我的保存：实现说明（D-123，2026-11-08）

> 决策：D-123（创始人 11/8，PR #459）。实现：分支 `claude/gone-cleanup-d123`。开关 `YOUJU_GONE_CLEANUP_ENABLED` 默认关，随 2.0 一起上线；关着时和现在完全一样（D-097：失效的正文、附件不给，不清理，没有保存、导出）。

## 一、规则

| 情况 | 列表卡片 | 详情页、阅读页 | 能不能保存、导出 | 本机清理任务 |
|---|---|---|---|---|
| 原网页能打开 | 照旧 | 照旧 | 没有按钮 | 不管 |
| 失效后第 1–7 天（失效那天算第 1 天，北京时间）、会清理 | 一行提示 + 哪天清理 | 标题下提示 + 清理日期，正文、附件照常 | 保存（要登录、要同意新版隐私指引）、导出 Word（不用登录） | 每天再查一次原网页（排最前） |
| 第 8 天起、还没删 | 照 D-097"原文链接已失效" | 照 D-097（正文、附件不给） | 不能 | 当天原网页检查跑完以后删掉 |
| 到期也不清理的（见下） | 照 D-097 | 照 D-097 | 不能 | 不删 |

**到期也不清理的五种**（`gone.KEEP_REASONS`；页面照 D-097 显示，不写清理日期）：
1. 有下架、恢复记录（下架记录对通知是 RESTRICT 外键，审计记录要留着，删不了）；
2. 别的通知的"截止已变更、见新通知"指向它（RESTRICT 外键）；
3. 原栏目列表 48 小时内还列着、而且是失效以后看到的（删了下一轮抓取会当新文件收回来，关注的人会收到"新文件"）；
4. 同一份通知（归并组）的其他网址还能打开；
5. 原栏目换了新地址：同一栏目、同一标题（去空白）、原网页没失效的另一份，发布日期一样，或者是原网页开始打不开以后才出现的（同名的往年通知不算）。

11/4 线上快照（2669 份，失效 83 份）实测：到期 80 份里，归并组别的网址还能打开 2 份、原栏目换了新地址 2 份，逐份核对都属实。

**恢复**：清理期里原网页又能打开，原网页检查清空 `link_gone_at`，清理取消，页面回到正常。

**删的时候**：一份一个事务，锁住这一行再核对一遍（这期间恢复、下架、换地址的不删）；要求最近 36 小时查过原网页（没轮到就推迟一天）。删通知用数据库外键规则：正文、截止、附件列表、名单、AI 判断等公开数据级联删除；用户的截止提醒授权、截止线索跟着删，纠错断开；引用这份通知的 AI 结果以后打开显示"结果依据已不可用"（现有逻辑）；附件副本和附件文字由附件任务按现有规则清掉。用户保存的副本不受影响（不建外键）。2.0 里本机删掉的行经同步通道带到服务器，服务器按外键级联删（#453 已测）。

## 二、我的保存

- 存什么：保存那一刻阅读页给的东西——正文和能读的附件文字（已脱敏、按页面说法换过，和阅读接口同样分段），加标题、发文机关、来源网站、地区、类型、发布日期、原网页打不开的日期、保存时间。不存附件原件。每份最多 4MB（约 130 万字，超过的后面附件不存、标"没存全"），每人最多 200 份（`YOUJU_SAVED_MAX_PER_USER`）。11/4 快照里最大的一份（7 个附件）约 4.8 万字、310KB。
- 表 `saved_documents`（迁移 0049）：`user_id` 随用户级联删除；`document_id` 不建外键（通知清理后副本还在）。不进公开快照、不同步到本机。
- 谁能看：只有本人（按 openid 对应的用户）。看列表、按页读、导出、删除都只认自己的。
- 再保存一次：换成现在的内容（期间附件可能读出来了）。
- 删除：本人在"我的保存"或"我的数据"里删；注销时随用户删；下架的（四种原因都算）删——单库时下架当场删，2.0 里下架在本机做、经同步过来，服务器每天 03:30 的 cleanup 任务删，删之前读的时候就不给（保存以后有过下架记录的也不给，下架后又恢复的同样删）。
- 开关后来关了：已经保存的照常能看、能导出、能删（自己的数据），"我的"页入口在保存过的人那里照常显示；不能再保存新的。
- 保存要同意过写进"您保存的通知"的隐私指引版本（`agreements.SAVED_AGREEMENT_VERSION`，现在占位 `2027-01`，2.0 指引定稿时改成真正的版本号）；只同意过旧版的点保存提示"保存通知要先同意新版隐私保护指引，请更新小程序后重新阅读并同意"。

## 三、接口

| 接口 | 说明 |
|---|---|
| `GET /api/v1/documents/{id}`、列表 | 清理期里多一个 `gone`：`since`（打不开的日期）、`cleanup`（清理日期）、`notice`、`cleanupNotice` |
| `GET .../reading`、`.../attachments/{aid}/reading` | 清理期里照常给，多一个 `goneNote` |
| `POST /api/v1/documents/{id}/gone-export` | 清理期里导出 Word，不用登录（同导出题录的频率限制） |
| `POST /api/v1/me/saved` | 保存（`{"docId": "…"}`） |
| `GET /api/v1/me/saved` | 我的保存列表（不带正文） |
| `GET /api/v1/me/saved/{id}/reading?part=&cursor=&revision=` | 按页读副本，格式同阅读接口（`part` 空是正文，1、2… 是附件） |
| `POST /api/v1/me/saved/{id}/export` | 导出副本的 Word |
| `DELETE /api/v1/me/saved/{id}` | 删除（没同意过、协议版本过期也能删） |
| `GET /api/v1/me` | 多一个 `saved`：`{enabled, count, max}`；开关关着又没保存过时为 `null` |
| `GET /api/v1/me/data` | 多 `saved`（标题、日期、字数，不带正文）、`savedTotal` |

## 四、部署（随 2.0；生产部署、改协议和隐私指引版本都要创始人在聊天里点头）

1. 2.0 隐私指引定稿（含"您保存的通知"，见 `docs/合规/隐私保护指引_2.0_您保存的通知_补稿.md`），`SAVED_AGREEMENT_VERSION` 改成定稿的版本号；
2. 迁移 0049（只建表）随 admin 启动执行；之后执行 `deploy/mysql_accounts.sql` 里"我的保存权限"一行；
3. 本机（清理任务，跟着 `check-links` 跑）和服务器（接口；1.x 云托管时 admin、api 两个服务都要，详情、列表由 admin 回）都设 `YOUJU_GONE_CLEANUP_ENABLED=true`，两边要一样；
4. 不用改定时任务：本机清理挂在 `check-links` 后面（先查后删）；服务器删下架副本挂在每天的 `cleanup` 里。手动补跑：`youju gone-cleanup [--dry-run]`。
5. 上线前提醒：全国铺开以后原网页检查的量要跟着扩（D-123 ⑥），不然老文件查不出失效；清理期队列只占失效后 10 天以内的那些。

## 五、要创始人看的说法和导出格式（D-076）

- 卡片：原网页10月21日起打不开，内容可能已被发布机关撤回或更正，以官方为准；10月28日清理
- 详情页标题下：原网页10月21日起打不开，内容可能已被发布机关撤回或更正，以官方为准。这份通知将于10月28日清理，可以先保存或导出。按钮"保存""导出 Word"；保存后"已保存"，提示"已保存，在“我的 → 我的保存”里看"
- 点保存、没同意过协议：保存通知前，请阅读并同意《用户协议》和《隐私保护指引》。……
- 阅读页顶部：原网页10月21日起打不开，……以官方为准。这份通知将于10月28日清理。
- 我的保存：每份写"原网页X月X日起打不开，……以官方为准。这是你X月X日保存的副本。"、"约 N 字 / 约 N 万字"或"原通知已清理，这里是保存的副本"；按钮"阅读""导出 Word""删除"；页底"保存的是正文和附件文字，不含附件原件；最多 200 份。删除或注销时一起删除；通知因投诉等原因被下架的，保存的副本也一起删除。"
- 清理后从导出记录回到详情：这份通知原网页打不开，已经到期清理；保存过的在“我的 → 我的保存”里看
- 导出 Word：标题；"发文机关 · 发布日期"；"来源：××网站"；打不开的提示（我的保存里导出的写保存日期）；"正文"一节；每个附件一节"附件 N：名称"；末尾"以上文字是从原网页和附件自动提取的，未经人工逐字核对；图片、公章和版式不在内。""第三方按公开发布的信息整理，仅供参考，以发文机关原文为准。""导出时间（北京时间）：…"。不写网址，正文里的号码、联系人和页面一样隐去。
- agy 合规审阅的意见（不擅自改，请创始人定）：提示句"内容可能已被发布机关撤回或更正"有猜测之嫌，"清理"可能被理解成政府废止，建议改成"原网页已无法访问，本平台将于X月X日停止展示；内容变动以官方最新发布为准"。10/23 agy 也曾要求卡片只说"原文链接已失效"、不说"已撤下"。D-123 原文定的是前一种写法。
