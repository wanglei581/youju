AI 助手对话版

把政策解读、条款对照合进一个对话页：打字、拍图片都能问；回答先从有据收录的官方通知里找，每句结论带出处，找不到就说找不到。联网只查政府网站，并标明未经人工核对。

只做设计，给创始人定方向开发排在首发上线、网信办上线登记问清之后 原句和网页摘录均取自政府网站原文（10/17 核对）企业情况、对话时间是示例；[ ] 是待定项

入口和流程

只有一个对话页。从哪里进来，决定对话开头带不带一份通知；原来的两项 AI 能力变成对话里的卡片，用户不用再理解「工具页」「任务」。

首页搜索框下面的「AI 助手」不带通知，空白对话
通知详情里的「AI 解读」卡片在「要点」下面，带上这份通知；取代右下角浮动按钮
→
AI 助手对话页顶部固定「AI 生成」；每份通知一条对话，记录保存 30 天
→
在对话里出现的卡片
划重点要准备哪些材料和我的企业对一下自由提问拍图片联网查政府网站
「要准备哪些材料」用同一份划重点结果，不另扣次数

两个入口

两个入口进的是同一个对话页。通知详情里的入口改成嵌在页面里的卡片，不再用浮动按钮；卡片在每份通知的同一个位置，能不能用都写清楚。

为什么放首页、不放底栏

  • 多数时候是从通知进来的AI 解读卡片在每份通知的详情页里；首页这一条只管不带通知的提问和拍照，用得没那么频繁，还不值得占一个底栏位。
  • 底栏页面不能带参数打开详情页要带着通知进对话页。AI 助手做成底栏页，就得另做一个对话页、两个入口分开维护；放首页只要一个对话页，返回还能回到通知。
  • AI 有开关和额度总开关关掉或首发版不带 AI 时，首页这一条直接不显示；底栏少一格要改所有底栏页和提审包。
  • 底栏保持四个首页、关注、文件、我的和首发版一致，老用户不用重新找。

上线后看数据：如果不带通知的提问和拍照占到 AI 使用的一半以上，再把 AI 助手挪进底栏，对话页本身不用改。

技术前提

  • 对话要秒回api 冷启动约 67 秒（10/12 实测），对话等不了。对话接口要放在常驻的 admin 上，或者给 api 留常驻实例。现在的解读是排队任务加轮询（一般 10–30 秒），对话版要改成边生成边显示。
  • 图片先过内容安全微信图片检测接口（/wxa/media_check_async）是异步的，结果推送回服务器，要实测等多久；等不了就改用同步的腾讯云图片内容安全（按次计费）。没通过的图片不识别。
  • 看图要另配DeepSeek 官方 deepseek-v4-pro 不支持看图。两条路：用文字识别接口（通用文字识别、营业执照识别），只把识别出的文字交给 DeepSeek；或者换能看图的模型（要重新评测，公示和登记的模型也跟着改）。
  • 联网只查政府网站需要能限定站点的搜索接口，按次计费；只放行 gov.cn 等政府域名，网页摘录也过一遍内容安全，再交给模型整理。每条结论必须对得上一个网页的原话，对不上的删掉。
  • 每句都有出处沿用现在的逐字核对：模型只给段号和原句，程序回原文核对，对不上的删掉；一条都对不上就回答“没找到”。自由提问的结论句也要挂到原句上。
  • 登记材料和隐私指引要跟着改上线登记写的功能里要加上图片识别、联网检索（先问网信办能否后补）；隐私指引补上提问文字、图片、联网检索的处理和保存期限；协议八·2 补上复制带标识。

请你拍板（5 个）

  1. 次数怎么算建议：划重点、对照、提问共用每人每天 5 次；联网单独算，每天 [3] 次。也可以沿用现在的「每类 5 次」。
  2. 对话接口放哪台服务建议先放在常驻的 admin 上（不加钱，抓取忙时可能变慢）；用的人多了再给 api 留常驻实例（要加钱，10/12 没同意）。
  3. 图片怎么识别建议用文字识别接口，模型继续用 DeepSeek，公示和登记不用改；换能看图的模型要重新评测、改公示。
  4. 联网检索用哪家服务、每天几次建议先选一家能限定政府网站的搜索接口试用，团队给出两三家的价格和效果对比后你定；次数先从每人每天 [3] 次起。
  5. 「AI 助手」放在哪建议：首页加「AI 助手」入口，通知详情页右下角改叫「AI 解读」；不放进底栏。「工具中心」只留批量名单比对和客户相关通知表。
