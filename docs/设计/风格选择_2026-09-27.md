# 设计风格选择（2026-09-27）

- **状态：** 已定。创始人选定"风格 C 精修版"（[决策记录 D-014](../决策记录.md)），按下文"最终选定"一节的规范重做了原型 9 个页面。下面"四种风格和结论"到"各页面对标"是第一轮评审的记录，其中推荐的"A+B 融合"已被取代。
- **做法：** 同一个首页、同样的真实数据，做成四种风格（图在 [风格对比](./风格对比/)，也在[原型画布](https://claude.ai/artifact/46cN5cikNz91TLR5LmJof3)第三行）。Codex、agy、Grok 三名成员各自独立评审，Claude 汇总；方向一致，细节有分歧，由设计主审 Codex 看过实际效果图后定稿。各成员的原始意见见 [评审原文](./风格对比/评审原文/)。

## 四种风格和结论

| 风格 | 参考应用（uinotes.com） | 结论 |
|---|---|---|
| A 公文纸（原型 v1） | 微信读书、网易蜗牛读书 | 保留它的排版质感：细线分隔、克制的配色、紧凑的条目 |
| B 效率工具 | 飞书、ima、腾讯会议 | 采用它的信息结构和操作：搜索优先、状态一眼可见、勾选导出；不要大留白和满屏卡片 |
| C 企业查询蓝 | 企查查 | 不用：蓝色通栏和彩色宫格接近政务门户，也像企业查询换皮；运营位盖住截止和出处 |
| D 资讯媒体 | 36氪、虎嗅 | 不用：文章流有被当作新闻信息服务的审核风险（agy 判断，需要什么资质待核实）；还会把原文改写成标题，违背"以原文为准" |

**推荐：A 的排版质感 + B 的信息结构和操作。** 三名成员独立评审得出同一方向，Claude 也同意。

## 已定的分歧

| 问题 | 决定 | 理由 |
|---|---|---|
| 朱红方形"据"印章 | 去掉，改为黑体"有据"字标，旁边用靛蓝小字"每条都有出处" | 方印加纸色容易被当成公章、红头文件（agy、Codex） |
| 宋体用在哪里 | 只用于文件详情页 20px 以上的文件标题；首页和列表全部用黑体 | 列表要快速扫读，不少用户 35–55 岁 |
| 朱红用在哪里 | 只提示临近的截止时间，不做品牌色 | 避免"官方""警告"感 |
| 状态文字 | 写"公示"和"正式公布"，不写"公示中" | 无法确认公示期是否还没结束（Claude） |
| 日期 | 列表写完整日期 2026-09-24；截止写"10月18日截止 · 剩 N 天"，N 按北京时间每天零点更新（原型里的数字以 9 月 26 日为准） | 名单常跨年，年份不能省 |

## 各页面对标（暂定）

目标是先达到真实上线产品的完成度。只学完成度和交互惯例，不照搬对方的标志、图标和品牌色。**以下对标还没有对照截图核实，是暂定的**，核实后再定稿。

| 页面 | 对标 | 学什么 |
|---|---|---|
| 首页 | 企查查 | 搜索优先、常用任务直达、结果密度 |
| 搜索结果 | 网易有道词典 | 关键词突出、相关信息紧跟结果 |
| 筛选 | 猎聘 | 多条件选择、已选条件可见、一键清除 |
| 文件详情 | 微信读书 | 长文层级、舒适行距、定位和返回 |
| 申报日历 | 腾讯会议 | 日程扫描、日期切换、临近提醒 |
| 查名单 | 企查查 | 精确查询、字段对照、状态识别 |
| 关注 | 飞书 | 更新聚合、未读提示、批量处理 |
| 文件 | 夸克网盘 | 导出记录、格式识别、查找和管理 |
| 我的 | 微信读书 | 简洁的账户结构、设置和说明好找 |

uinotes.com 的应用截图要登录才能看，团队目前只能看到应用名单，对标依据是成员对这些应用的了解。创始人在 Claude 的内置浏览器里登录后，团队可以逐页对照截图核实。

## 最终选定：风格 C 精修版（2026-09-27）

**经过：** 创始人看了四种风格，认为 C 更好看、更像成熟软件。团队按创始人的偏好做了"C 精修版"，Codex、agy、Grok 重新评审：
- Grok：目标用户天天用企查查，"第一眼愿意用，C 精修高于 A+B"；愿不愿意付费，要看第一屏有没有截止、机关和原文。
- Codex：认可蓝色搜索区"更像他们熟悉的企业查询工具，也更有品牌辨识度"；建议外观用 C，列表按 A+B 的规则。
- agy：合规风险从"高"降到"中"，满足下面的合规底线即可采用。

**合规底线（agy）：** 品牌蓝用现代商业工具蓝，不用政务深蓝；"第三方整理"常驻首页顶部；入口和热词只用中性的检索用语；不出现印章、国徽式元素和"官方"字样。

**规范：**

| 项目 | 规范 |
|---|---|
| 颜色 | 品牌蓝 #2A5CE0（搜索、选中、链接、主按钮），顶部渐变 #2F66F0→#2553D6；页面 #F2F4F8；卡片 #FFFFFF；正文 #1D2129；次级 #4E5969；弱信息 #86909C（不用于来源和日期）；分隔线 #EEF0F3；灰色填充 #F2F3F5 |
| 语义色 | 申报：蓝（浅底 #EAF0FF）；名单：橙 #F57B21（文字 #D9640F，浅底 #FFF3E8）；政策：绿 #13A677（文字 #0E8A63，浅底 #E8F7F1）；截止提示：14 天内红字 #E5484D，7 天内再加浅红底 #FFECEC |
| 字体 | 思源黑体；页面标题 17/600；区块标题 16/600；列表标题 16/24、600；正文 14/22；辅助信息 12–12.5；数字用等宽 |
| 结构 | 首页：品牌蓝顶部（字标和"第三方整理 · 非政府平台"角标、搜索范围切换、带按钮的搜索框、热词）→ 一行 5 个入口 → 本周新增摘要 → 文件列表。其他页面：顶部常驻一行"第三方整理 · 非政府平台 · 每条附原文链接"（白色导航栏的页面放在导航栏下方；查名单、我的这类蓝色顶部页面放在蓝色区域里）。底栏：首页、关注、文件、我的 |
| 组件 | 卡片圆角 12，左右留白 12；列表行在同一张卡片里用 1px 分隔线；筛选项为胶囊形，选中为浅蓝底加蓝色描边；主按钮为蓝色胶囊，高 44 |
| 列表行 | 类型、状态、地区、截止 → 标题（最多三行）→ 发文机关和完整日期 + "复制原文链接"。发文机关不省略，超过 11 个字时单独一行。列表只显示一部分时，末尾写"已显示 x/y 份 · 查看全部 y 份" |
| 图标 | TDesign 图标库（腾讯，MIT，[决策记录 D-015](../决策记录.md)）；24px 基准，沿用原始 2px 线宽，不单独加粗；底栏未选中用线性、选中用面性；首页入口 42px 渐变方块里放 22px 白色线性图标；普通图标用次级灰，选中和链接用品牌蓝。对照表见 `原型v2/生成脚本/ds.py` 的 `LIB_ICONS` |
| 不用 | "NEW"角标、活动横幅、五颜六色的地区标签、营销文案 |

**小程序平台限制（agy 提出，Claude 于 2026-09-27 对照微信开放文档核实）：**

- **原文入口：** web-view 组件"可打开关联的公众号的文章，其它网页需登录小程序管理后台配置业务域名"（[web-view 文档](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html)）。政府网站没法配置成我们的业务域名（配置时要在对方网站放校验文件，这一步在管理后台，文档页没有写，提审前再确认）。所以列表和详情页的原文入口是"复制原文链接"，提示在浏览器打开；网页版可以直接打开。
- **提醒：** 文档列出一次性订阅消息和长期订阅消息两种（[订阅消息开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)、[wx.requestSubscribeMessage](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)）。agy 认为我们的类目只能用一次性订阅，这两页没有写长期订阅的开放范围，**待核实**。原型先按一次性订阅设计（每订阅一次，提醒一次），两种情况下都能用。
- **隐私：** 处理个人信息的小程序"需通过弹窗等明显方式提示用户阅读隐私政策"，用户点同意按钮后才能调用隐私接口（[隐私协议开发指南](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html)）。原型的做法：登录前主动勾选协议，未勾选不能登录。

原型 v2 的源文件在 [原型v2](./原型v2/)，由生成脚本统一输出，保证各页面规范一致。
