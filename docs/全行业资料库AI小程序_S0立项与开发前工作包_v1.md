# 全行业资料库 AI 小程序：S0 立项与开发前工作包 v1

**日期：**2026-09-24  
**适用：**开发前 10 个工作日的规格、来源和可行性核验；产品功能以[主规格 v5.1](./全行业资料库AI小程序_完整产品与开发主规格_v5.1.md)为准。  
**当前状态：**可启动 S0；S1 数据底座开发尚未获准。没有客户、持续连接器、已核准的自动采集/附件处理权利、已确定的人类负责人或预算上限。本工作包不代表站点许可、模型同意或商业可行性已获证实。旧 `pilot-qingdao/sync.py` 未运行。

## 1. S0 要做出什么决定

用真实来源回答四个问题：①能否稳定发现**新文章和后续更正**；②名单、申报节点和附件是否足够支撑可核验的答案与报告；③访问、保存、AI 阅读、下载和分享各自有什么依据；④在可承担的人力与预算内，用户提出问题或关注变化后能拿到什么直接可用的结果。全行业来源目录是后台能力，前台只展示用户关心的结论、关键字段、出处与覆盖缺口；首个深度切片暂定**青岛企业认定与申报节点**。如果更新不够密，改为月报或有事更新；不为周报编造变化。没有客户不是 S0 或 S1 的前置条件，未来付费与留存只能由真实使用验证。

**本轮的完成边界：**四方形成了规格评审意见；Codex 核对官方样本、两条同批次状态链，制作[内部回溯样张](./青岛企业认定与申报节点_回溯样张_内部核验版_v0.md)，并对两个市民营经济局栏目完成[当前列表的 52 周频率初核](./青岛试点_52周栏目频率初核_v1.md)。主规格已修订频率、申报节点、报告版本依赖、分享阶段及评测时间。**尚未**核科技局等其他栏目、过滤首专题有效变化、逐站权利审查、附件行核对、预算测算或正式团队签字；没有 app 开发或采集脚本执行。

### 来源台账每行要填的字段

`source_id / 发布方 / 列表 URL / 详情样本 / 附件样本 / 地区主题 / 是否必看 / 52个完整周的逐周有效事件数及类型 / 列表翻页与截止 / 同批跨栏目重复关系 / 发布频率 / 最后人工核验时间 / 网站访问条件及证据 URL / robots 及检查时间 / 题录展示 / 原站跳转 / 短摘 / 临时解析 / 持久存储 / 索引 / AI 阅读 / 原件下载 / 导出引用 / 再分发 / 每项依据与有效期 / 审核人 / 运营人 / 技术人 / 当前状态`。

初始状态统一为 `DIRECTORY_ONLY / RIGHTS_PENDING`；每个自动动作须有具体依据及审批。用户提供 URL 或其他平台开放访问都不产生自动采集、保存全文和再分发权。商业报告库先做获准题录与原站跳转；如腾讯等企业资料库需要全文问答/下载，则按发布方、内容类型和用途另谈授权。

## 3. 十个工作日的 S0 工作与产物

以下按“有完整人手且相关网站能核验”估算，日期为相对工作日，不是上线承诺。每一项留下输入来源、执行人、时间和检查记录。

| 日 | 工作 | 交付证据 | 谁验收 |
|---|---|---|---|
| D1 | 由发起人指定项目决策人及产品/资料、来源权利、工程、质检负责人；确定范围与决策日志 | 有姓名的 RACI、问题台账、≥6 个**栏目入口**（含扩展备选）与各自状态 | 发起人指定的决策人；尚未指定时只形成草案 |
| D2 | 人工低频核候选站点的列表、分页、访问条件和动作级权利，**先不锁定试点栏目** | 来源台账、页面截图/链接、访问失败类别及权利 `PENDING` 与调查依据；`ALLOW/DENY` 须署名审核 | 来源权利负责人；未指定时仅保留调查记录 |
| D3 | 对最近 52 个完整周（2025-09-22 至 2026-09-20）按发布日期逐周登记相关事项及类型，跨栏目去重；抽 2 份名单附件核页、末行序号/总数及各 30 行企业名称；抽 1 条申报通知核多截止节点 | 逐周信号表、两份附件核对及差异、申报节点链、不能解析/访问的样本 | 资料负责人和质检 |
| D4 | 用真实公告定义公示→正式、更名/撤销、迟到发现/失败恢复三张状态表；定义申报节点和必看来源的内部新鲜度窗口 | 3 张状态表、20 条起始名单/版本/申报节点金标、失败时文案 | 产品和工程 |
| D5 | **G0 检查**：来源、权利、频率和试点主题是否有可行路径；决定周报/月报/有事更新 | G0 决策记录、未通过项的替代专题 | 决策人和权利负责人 |
| D6 | 画/评 3 个关键页面的规格：找答案首屏、我的关注与变化、答案证据与所选导出；来源目录作为二级入口；列全空结果/失败/部分完成状态 | 页面状态图、答案卡字段与文案、真实样本引用 | 产品和质检 |
| D7 | 写 API 请求/响应样例：结构化找答案、覆盖、一次性任务、关注、运行、证据、报告修订、所选导出、403/429 与越权 | API 契约、权利和租户权限表、错误码 | 工程和质检 |
| D8 | 扩至 40 条名单/版本/申报节点金标；建立 60 条问答候选题（其中至少 20 条拒答/证据不足）；统计题有真实来源才算正式金标 | 金标、依据链接、预期状态与复核人；延期题单列 | 资料和质检 |
| D9 | 测算人月、云存储、模型、来源维护、质检、平台和授权；确定 S1 数字预算上限与止损指标 | 成本表、试价只是待测假设、S1 人员与运营排班 | 决策人和财务/产品 |
| D10 | 文档一致性审查与 **G1-A 规格签收 / G1-B 开工授权** | 签收版规格、未决问题、S1 任务拆分和验收卡 | 决策人，AI 只能提供审查意见 |

**D2–D3 的工程抽样记录：**在站点条件允许的访问方式内，记录列表/附件请求是否依赖登录、Cookie、Referer、脚本渲染、重定向和特定网络环境；遇 403/429/验证码立即停止，不探测拦截阈值或绕过防护。对明确可下载的样本核响应类型、实际文件签名、页数/工作表、哈希和下载失败页，避免把 HTML 错误页当 PDF/XLS。按“文本表格可规则提取、跨页/合并单元格需专项规则、扫描/印章遮挡需人工复核”标解析难度。未经许可不执行批量探针或自动采集。

**可并行做的事：**D2 的权利调查和 D3 的人工历史盘点可以分工，但把资料放进自动管道须等动作许可。S0 可建立手工样本与题目，不能把搜索引擎摘要当作完整数据库。若来源证据不足，先换青岛另一个官方专题或将频率改为事件，不把 G0 失败解释为全产品不能做。

**G0（主题可行，D5）：**已实名指定决策人；至少两个**具体栏目入口**有可复核的列表/详情和权利调查；至少一条公示→正式/更正链能用原始文件演示；至少一份名单附件可逐行定位，正文总数与末行序号/行数吻合或差异已记录原因，另记录 `.xls` 是否可处理；至少一条申报截止节点可回源且不同责任主体的日期不混写；20 条起始金标有出处；52 周信号表可支持频率决策；记录风险与备用来源。满足这些才进入 G1 规格收口，未满足则换主题/缩动作。G0 的权利调查不等于允许自动抓取或公开全文。

**预先登记的频率判定规则（只是产品假设）：**“有效变化”是首切片内去重后的公示、正式/更正/取消或对企业有行动意义的申报节点，以官方发布日期计入周；同一公告跨栏目出现只算一次。52 个完整周中，≥39 周有有效变化，才把**每周有内容的编辑报告**列为候选；13–38 周以每周检查、发生变化时出简报或按月汇总为候选；≤12 周以有事更新为候选。若逐周历史不完整，只给出区间和缺口，不用该阈值作确定结论。该规则可在 G0 结合维护成本和实际用户价值调整，但调整原因须在看结果前后的决策日志中公开，不把“每周检查”包装成“每周都有新资料”。

**目前频率判断：**[C01/C02 当前列表初核](./青岛试点_52周栏目频率初核_v1.md)合并最多 25/52 周有任意公告，低于 39 周门槛。因此只靠这两个栏目不能承诺“每周有新内容”；每周检查仍可进行，内容交付先按有事/按月设计。若扩大到科技局等栏目，须再完成相同口径的逐周、主题过滤和跨站去重，才能重定频率。

## 5. 首批验收卡与量化方式

| 卡 | 后续 S1/R1 需看到的证据 | 不合格示例 |
|---|---|---|
| 新公告发现 | 栏目列表或存档页回放能发现此前未登记的详情，跨栏目同文去重 | 只轮询固定 3 个 URL |
| 不漏报与完整度 | 必看栏目翻页到窗口起点，详情与必需附件无未解失败；任务与逐 URL 记录关联 | 一次 HTTP 200 就写“全周无更新” |
| 时间和状态 | 公示、正式、复核、取消、更名；本期发布/迟到发现/修订分栏并可回源 | 只按标题把公示写成获批 |
| 附件核对 | 可逐行定位；正文总数与末行序号/行数对照，并抽 30 行名称复核；跨页、合并单元格、扫描/印章遮挡分级 | OCR 错行直接进确定名单 |
| 申报节点 | 企业填报、区市初审和市级报送等按责任主体、渠道、起止日分别保存原文位置与版本 | 把市级报送日写作企业申报截止日 |
| 权利隔离 | `DIRECTORY_ONLY` 来源可跳原站，但全文 API、AI、原件下载、导出不能越权 | 前端按钮隐藏而接口仍返回全文 |
| 更正传播 | 文档版本→简报条目→报告版本有依赖；旧文件标过期，用户确认后新建文件 | 静默改写已下载报告 |
| 导出与成本 | XLSX/DOCX 在目标环境能打开；同一报告版本+格式+模板版本只扣一次；测每份人工修改分钟和边际成本 | 文件打不开、失败重试重复扣费 |
| 按需答案 | 同一问题只返回相关的少量结果和出处；无证据说明缺口；仅用户确认的关注进入周期任务，原文件不在首页堆积 | 某行业所有 PDF 推满首页，或题录命中被写成已读全文 |

**内部五项基线：**①来源检查成功率（成功检查数/应检查数，排除权利暂停但另列）；②漏报率（人工金标漏掉事件数/金标事件数）；③关键状态错误数；④单专题每周人工维护小时；⑤单份报告人工修改分钟与边际成本。S0 固定定义和记录方式，不伪造当前数值；S1 影子运行取得基线后冻结试点阈值。AI 引文与拒答阈值在 R2 开发前依据真实题库冻结，不能在测试后降低目标。

## 6. 无客户时怎样验证价值与收费

第一个“用户”是团队自己的资料运营：用原站资料人工做一份**非 AI 的、可回源的样本简报和 XLSX/DOCX**，记录完成分钟数、搜索站点数、差错数和人工改动处。当前已有[结构样张](./青岛企业认定与申报节点_回溯样张_内部核验版_v0.md)，但尚无附件校对、投入时间实测或可编辑文件，不能算这项验证完成。S1 工具出来后对同一历史窗口回放，比对漏报、时间与成本。样本只说真实变化，若一周无变化则发布“本期检查完成，无新增/有缺口”，或者改月报。公开分享等到权利、质量和对应阶段的分享能力具备。

**已有服务必须纳入对照：**[青岛政策通](https://zccx.qingdao.gov.cn/)官方页面列有政策文件、政策匹配、政策订阅、项目公示/公告及“一周一策”；[青岛政务网介绍](https://www.qingdao.gov.cn/zwgk/xxgk/fzj/gkml/gzxx/202211/t20221108_6487546.shtml)还描述政策计算器、在线申报和资金兑现。因而“政策搜索/匹配/订阅”不能作为本产品独有卖点。S0 应用同一个真实研究任务，对照这些现有入口及常规网页搜索，记录能否得到**跨来源的名单状态链、逐行出处、更新缺口和可编辑报告**，以及完成时间与错误数。现阶段尚未核对青岛政策通是否已有同类导出或 AI 功能，不能声称它缺少这些能力，也不能把差异化写成已证实。

价格见主规格的试验区间，目前只是**假设**。先计算 `每份贡献 = 实收 - 模型 - 存储/导出 - 来源授权分摊 - 人工质检/支持 - 支付成本`；再选择按份或团队的一种模式做 R3 试价。前期不能拿行业总体报告市场规模代替本产品的付费证据。获客指标从“来源卡→原站/证据→试跑→保存→首次导出→连续四期按期完成→付费”，每一步保留失败/无覆盖原因；自然用户数据出现后再判断是否扩行业、扩地区或做 PPTX/跨行业报告。
