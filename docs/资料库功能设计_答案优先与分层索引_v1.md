# 资料库功能设计：答案优先、分层索引、按需取证

**日期：**2026-09-25  
**定位：**[产品与开发主规格 v5.1](./全行业资料库AI小程序_完整产品与开发主规格_v5.1.md)的资料库专题细化；阶段和发布门槛仍以主规格为准。本文件是设计方案，尚未开发或完成来源授权。

## 1. 资料库到底是什么

资料库不是把 PDF、Word 和网页批量塞进小程序的“文件仓库”，而是由**来源目录、资料题录、可核事实、证据位置、版本关系、用户保存成果**组成的检索与回答系统。用户先提出任务，系统只展示与任务有关的答案和少量资料；研究人员需要时再浏览目录、核验出处。

**两种入口共享一套数据：**

| 入口 | 适用问题 | 首屏结果 | 后续动作 |
|---|---|---|---|
| 找答案（默认） | “某企业是否入选？”“本月有什么新政策？”“某指标是多少？” | 一句话结论或无法确认、关键字段、覆盖程度和出处 | 看证据、关注变化、导出所选 |
| 浏览资料（次级） | “有哪些机构发布过工业互联网报告？”“青岛有哪些申报栏目？” | 按行业/地区/类型筛选的来源与资料卡 | 打开原站、筛选、收藏来源、提出接入申请 |

首页底部仍采用主规格的`找答案 / 关注 / 文件 / 我的`；在“找答案”页设置明确的“浏览资料”入口。它既不能深藏到找不到，也不占用答案首页成为无限文件流。

## 2. 让用户按问题分类，不要求先懂资料分类

搜索框下先放职场高频任务模板：**查政策条件、查申报节点、查企业名单、查行业指标、找研究报告、看近期变化、对比两个地区或行业**。选择模板后，只问完成任务必需的字段，例如地区、行业、企业、统计期或截止时间。模糊问题先询问最关键的一个缺失条件；未补齐时展示探索结果，不输出假精确结论。

资料同时拥有多个筛选维度，不用一个排他的“行业→子行业→文件夹”树来存放：

| 维度 | 用途 | 显示要求 |
|---|---|---|
| 行业/主题 | 医疗、制造、工业互联网等，可一条资料多标签 | 区分人工核验标签与 AI 建议标签；“工业互联网”作为跨行业主题 |
| 地区/适用范围 | 全国、省、市、区县及政策适用对象 | 发布地不自动等于适用地；跨地区资料可多选 |
| 资料类型 | 政策、申报通知、公示/正式名单、统计指标、研究报告、新闻线索 | 新闻线索不能替代政策或原始统计证据 |
| 时间 | 发布日、生效日、统计期、申报窗口、首次发现、最后核查 | 不混用“本周发布”和“本周才找到” |
| 发布方与阶段 | 机关、企业、协会、智库；草案、公示、正式、更正等 | 同一事项的阶段形成时间线，不能相互覆盖 |
| 可用程度 | 仅题录、可读证据、可引用、可导出、持续监测 | 按逐来源权利和实际检查状态显示，不能因网页公开就默认可全文再分发 |

行业标签建议维护同义词和上下位关系，例如“医疗器械”关联“医疗健康”，但原标签、归一标签及确认人分开保存。先覆盖用户真实搜索词，分类版本可迁移；不要在 S0 为所有行业手工建立庞大空目录。

## 3. 五类资料用五种结构，不能只存“标题＋文件”

| 类型 | 必要的结构化字段 | 关键核验点 |
|---|---|---|
| 政策法规 | 发文机关、文号、公布/施行/失效时间、地区、适用对象、条款、修订关系 | 现行效力未核实就显示“待核”；解读与正文分开 |
| 申报通知 | 项目、对象、条件、材料、渠道、企业截止日、其他层级截止日、批次 | 企业截止日不能拿主管部门报送日替代 |
| 企业认定/获奖名单 | 事项、批次、阶段、企业名称与识别信息、名单行、发布日、更正关系 | 公示与正式不同；同名、附件解析错行进入待核 |
| 统计数据 | 指标定义、单位、地区、统计期、频率、来源表、初值/修订值 | 口径不同不可直接求和、对比或自动算增长率 |
| 研究报告 | 题名、发布方、日期、主题、原站、授权动作、可获取方式 | 仅有目录时只答“找到报告入口”，AI 不概括未读全文 |

国家统计局对指标使用**名称、专业分组、时间类型、频率、单位、来源、统计范围**等元数据来确定指标，且按发布日程更新；统计卡应借鉴这种“数值＋口径＋时间”的设计，而不是只摘一个数字。[国家统计局说明](https://www.stats.gov.cn/zs/tjws/jbtjzswd/tjzn/202412/t20241216_1957774.html)

## 4. 四层存储和四个可见状态

1. **来源登记：**官网栏目、数据接口或报告库入口、发布方、访问规则、权利审核、运营负责人、最后成功检查时间。广覆盖从这一层开始。
2. **轻量题录：**标题、链接、发布日期/统计期、地区、类型、标签、版本指纹、权限。用于发现和检索，不声称已读正文。
3. **事实与证据：**仅在允许处理且任务相关时提取条款、企业名单行或统计单元；每个事实指回原文位置、源版本和核验状态。
4. **用户成果：**用户明确保存的答案、关注任务、报告版本与导出记录；每个成果记录依赖哪些证据版本，以便后续更正时标记影响。

小程序包只放界面代码、必要配置和少量静态资源；原始大附件不放进去。服务端是否缓存全文、保存多久，由具体许可、追溯和恢复需求确定。无法获得全文处理权时只保留被允许的题录和原站入口。[《著作权法》第五条](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)对某些官方文件有规定，但不能据此推断所有政务附件、企业报告和图片都可以商业复制、AI 阅读或再分发。

对用户必须明确显示四种资料状态：`来源入口已发现`、`题录已收录`、`证据已核验`、`持续监测中`。另显示“监测暂停/来源失败”。只有后两种状态才能支持相应的确定性回答或更新承诺。状态按**具体来源×地区×主题**计算，不给整个行业贴笼统的“已覆盖”标签。

## 5. 查询后的答案页

**首屏只放：**结论或无法确认、最多几个与问题直接相关的字段、资料截止时间、覆盖状态、发布方与原站、证据和版本入口。结果多时先合并重复资料，并只显示最相关的少量条目；“查看更多”由用户主动点开。负面证据、更正、冲突与来源失败不因精简界面而隐藏。

**示意（仅为界面文案示例，并非真实企业判断）：**

> 问：某企业是否进入某市 2026 年正式认定名单？  
> 答：目前无法确认。已找到该批次公示，但正式名单的企业行尚未核验。  
> 证据：公示原站、发布日期、待核附件；资料截至本次成功检查时间。  
> 可做：打开原站｜关注正式结果｜报告资料错误。

“未找到”只能代表**已成功检查的来源和时间范围内未检出**，不代表企业没有入选。结构化数字、金额、资格与日期优先由已核验字段计算或查询；AI 用于解释和编排，逐项引用获权证据。只有题录、来源失败或证据冲突时返回缺口，不补编答案。

## 6. 资料怎样进来、怎样更新

```text
来源推荐/发现 → 人工验真与权利审核 → 来源登记
    → 按允许的方式检查栏目列表/API/RSS → 新题录/版本识别
    → 按用户任务和专题价值选择相关资料 → 获权解析与证据定位
    → 规则校验/人工待核 → 上线答案与来源卡
    → 监测更正、撤回、许可到期和来源故障 → 标记受影响答案/文件
```

一个公共来源只同步一次，服务多个用户。记录每次检查尝试和最近一次成功快照；检查失败不能显示“暂无新内容”。用户推荐的“冷门干货库”先成为候选来源，经发布方、真伪、访问条件和维护价值审核后，再逐步开放题录、问答或全文能力。作者/机构可以提交官方入口或申请认领，但不得自行修改已核验事实或购买更高的证据排序。

资料目录应给运营人员提供来源健康、待核队列、失效链接、重复合并、权利到期、用户纠错和受影响报告清单。持续运营责任和预算与功能一起设计，不能将其当成一次性“数据导入”。

## 7. 分阶段开发，先把一条答案链做真

| 阶段 | 资料库能力 | 可验收结果 |
|---|---|---|
| S0 设计核验 | 选定一个专题、2–3 个真实栏目，核对权利和历史更新；列出 20 个真实用户任务和金标答案/拒答样本 | 每个样本的原站、证据需求、缺口与人工维护成本清楚 |
| S1 数据底座 | 来源登记、列表发现、题录去重、版本、名单/政策结构化、证据定位、故障与待核队列 | 历史回放与连续检查都能识别新增、迟到、更正和失败 |
| S2 受控小程序 | 找答案、浏览资料、关注、证据展开、纠错、保存和所选 XLSX/DOCX | 用户不靠开发人员帮助完成“问题→可信答案→可编辑成果” |
| S3 公开 AI | 获权证据上的引用问答、覆盖申请、分享；经平台核验的消息能力 | 引用确实支持结论，资料不足会拒答，权利和平台门槛通过 |
| 后续扩展 | PDF/PPTX、跨行业口径对照、团队应用连接与合作来源 | 逐类验证格式可用性、对比口径和付费意愿 |

“全行业”适合先做**可探索的来源地图**；“资料完整、持续更新、可问答”只能逐地区和专题宣布。国务院政策文件库本身已有政策检索及持续更新，[官方说明](https://sousuo.www.gov.cn/zcwjk/)；我们的价值假设要通过跨来源整理、证据定位、变化追踪和可编辑成果的实际省时表现来检验，不能把“能搜索资料”当成独有卖点。

## 8. 判断资料库有没有做好

优先看：用户问题的**有依据答案率、证据定位成功率、需要拒答时的拒答率、资料更新漏报与误报、用户完成任务所需时间、导出后修改时间、来源故障可见率、每个完成任务的总成本**。目录总文件数、AI 对话数和下载次数只是辅助指标。用户提出但未覆盖的问题要进入“需求队列”，结合重复次数、可获得来源、许可和维护成本，决定下一个深做的行业专题。
