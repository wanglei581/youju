## 一、协议与指引待定段落审阅

### 1. 账号注销与数据处理
* **所在位置**：用户协议｜三、账号登录与数据使用｜第3段
* **要确认事项**：线上注销承诺“立即删除”关注与纠错记录，是否与网络安全法要求的日志留存义务产生冲突？是否需要设置冷静期？
* **目前倾向**：线上点击立即执行删除/解除授权，邮件申请核实后处理。
* **可选方案**：
  * **方案 A**：保留“立即删除”，但补充“法律法规另有规定除外（如日志依法留存）”。
  * **方案 B**：将“删除”明确表述为“删除或匿名化处理”。
  * **方案 C**：增设注销核验或提供即时注销与缓冲期提示。

### 2. 免费政策与未来商业化调整
* **所在位置**：用户协议｜六、服务的变更、中断与终止｜第3段
* **要确认事项**：首版免费转未来增值收费的表述，如何避免被认定为不合理的单方变更格式条款？
* **目前倾向**：保留调价权利，承诺提前公告并在取得用户明确同意后上线增值收费功能。
* **可选方案**：
  * **方案 A**：明确基础公开查询功能永久免费，仅新增增值模块实行独立收费协议。
  * **方案 B**：保留全局调整权，仅写明“提前 30 天公示并征得同意；不同意可终止使用”。

### 3. 管辖法院约定
* **所在位置**：用户协议｜七、法律适用与管辖｜第2段
* **要确认事项**：格式条款中约定“运营主体住所地法院”的有效性，以及具体区级法院名称的显着提示（加粗）要求。
* **目前倾向**：约定公司注册地所在基层人民法院管辖。
* **可选方案**：
  * **方案 A**：直接写明具体的基层人民法院全称，并做粗体下划线显著提示。
  * **方案 B**：表述为“运营主体住所地有管辖权的人民法院”，不绑定具体区名。

### 4. 访问日志属性与微信云托管 IP 获取
* **所在位置**：隐私指引｜一、我们收集的信息及使用目的｜第12段
* **要确认事项**：日志留存 190 天作为“履行法定义务（网安法第21条）”免征得同意的处理是否充分？单向哈希 OpenID 与 IP 是否需要单独提示？若技术上无法获取独立客户端公网 IP 应如何修正？
* **目前倾向**：作为法定安全义务处理；仅记接口不记查询词；OpenID 哈希脱敏。
* **可选方案**：
  * **方案 A**：维持现状，若云托管无法获取独立 IP 则将字段修正为“网络代理/出口 IP”。
  * **方案 B**：在敏感信息与授权范畴中明确排除“去标识化后的日志数据”。

### 5. 云托管服务商的法律属性定性
* **所在位置**：隐私指引｜四、向第三方提供信息与合作方说明｜第5段
* **要确认事项**：底层微信云托管（腾讯云）应界定为“委托处理方”还是“向第三方提供（共享）”？是否需要征得个人单独同意？
* **目前倾向**：界定为基础设施技术支持提供方（委托处理），不属于对外共享。
* **可选方案**：
  * **方案 A**：作为“委托处理”列出，披露受托方主体名称、处理目的并说明有数据安全协议保护，无需单独同意。
  * **方案 B**：仅在“技术安全防护”章节笼统说明使用主流云服务商，不列入第三方合作清单。

### 6. 数据查阅、复制范围及响应时限
* **所在位置**：隐私指引｜五、您的权利与行使途径｜第1段、第5段
* **要确认事项**：排除访问日志的在线直接查阅复制是否合规？“15 个工作日”响应时限是否符合监管标准？
* **目前倾向**：在线仅开放核心业务数据复制；日志走邮件申请；时限设为 15 个工作日。
* **可选方案**：
  * **方案 A**：维持现状，明确系统安全日志不属于法定应供复制的个人信息客体。
  * **方案 B**：将“15 个工作日”调整为“15 个自然日”或律师建议的时限。

### 7. 未成年人保护及官方联系渠道
* **所在位置**：用户协议｜八｜第1段，隐私指引｜六｜第2段、八｜第4段
* **要确认事项**：政企公开信息工具面向职场成年人，是否需制定专门的儿童隐私条款？仅留官方邮箱是否满足个人信息保护专人/渠道要求？
* **目前倾向**：声明面向 14 岁以上用户；不设专岗电话，仅提供官方邮箱。
* **可选方案**：
  * **方案 A**：维持纯邮箱受理，前置提示“本小程序仅面向具备完全民事行为能力的成年人使用”。
  * **方案 B**：增补个人信息保护专职人员称号及工作日在线客服通道。

## 二、R1.5 拟增功能（机构名单比对与跟进表）专项问答

* **问题 1（法律角色定位）**：机构用户上传客户企业名称或统一社会信用代码进行比对及生成导出表，平台在该流程中应界定为“受托处理方”还是“独立/共同个人信息处理者”？
  * **方案 A**：认定为“受托方”，平台仅提供自动化比对工具，不承担直接向被比对主体告知同意的义务。
  * **方案 B**：认定为“独立处理者”，需要求机构出具完整授权证明。
* **问题 2（机构合法性承诺机制）**：为防范合规责任传导，隐私指引与协议中对机构上传行为的免责条款应如何拟定？
  * **方案 A**：在用户协议中增设“机构承诺已获得合法依据（法定授权/同意）”，并约定因数据来源违法导致的一切赔偿责任由机构承担。
  * **方案 B**：在功能使用前增加独立弹窗，要求机构用户每次上传前单独勾选《数据来源合规承诺书》。
* **问题 3（个体工商户名称）**：客户名单里的个体工商户名称可能就是个人姓名（如"张三便利店"），算不算个人信息、要不要在指引里单独说明？目前引擎会拒绝"像个人姓名"的输入，但个体户字号拦不全。
  * **方案 A**：指引写明可能包含个体工商户名称，按个人信息同等保护、同样的保存期限。
  * **方案 B**：比对只接受统一社会信用代码或含"公司/中心/研究院"等组织形式的名称。
* **问题 4（生命周期与存储期限说明）**：
  * **待确认事项**：“客户上传名单保留 7 天，比对结果文件保留 30 天后自动删除”，应如何表述方能兼顾保障合规最小必要原则与业务追溯需求？

## 三、创始人需前置准备的核实材料

1. **主体资质与工商信息**：
   * 营业执照扫描件（核实公司全称、法定代表人、注册住所地及对应管辖基层法院名称、经营范围是否含数据/信息服务）。
2. **云服务与基础设施凭证**：
   * 微信云托管（腾讯云）服务协议及数据安全处理协议（DPA）条款。
   * 技术团队核验结果：微信云托管网关是否能获取并沉淀真实的客户端公网 IP。
3. **通信与渠道准备**：
   * 正式对外公开的合规/官方联系邮箱（企业域名或实名专用邮箱）。
   * 小程序已选服务类目备案凭证及是否开通微信通知相关能力授权。
