# 政策周报第 0 步：自动生成、人工发布

## 使用

- 管理台 `/admin` 左侧进入“周报”，选择方案并生成草稿；统计周留空取上一个完整自然周，指定日期必须是周一。
- 查看预览，复制标题和带格式正文（或公众号版纯文本），粘贴到公众号后台后人工发布，再点“标为已发布”。邮件或企业微信群使用“复制带链接版”：每条固定五列、单独一行。浏览器拒绝剪贴板权限或不支持格式复制时，页面选中正文并提示手动复制。
- 已发布期刊不能被重新生成覆盖。要修改，先撤回标记，再重新生成。撤回只改内部状态，不会撤销公众号文章。
- 方案可新增、编辑名称、省份、关键词、栏目、生成星期和启用状态。空省份表示全国；选择地区后仍包含国家部委；关键词按标题包含任意一个词筛选，不把 `%` 和 `_` 当通配符。
- CLI：`youju weekly-digest [--profile 全国版] [--week 2026-09-28]`。未指定方案时处理全部启用方案；显式指定方案可手工生成停用方案。`--scheduled` 再按当天星期筛选。
- 默认全国版在周一 07:30 生成。为支持方案修改星期，周二至周日也安排 07:30 调度，未到生成星期的方案不生成。所有定时调用走 `job.sh`，记入 `job_runs`。

## 固定口径与边界

- 新发布按详情发布日期优先、题录发布日期兜底计算，日期范围含周一及周日，不按首次发现时间算。北京时间周一 00:00 切换到新的完整统计周。
- 未来截止栏目仅列申报通知，基准是本次生成的北京时间日期，含当天至第 30 天；核定时刻已过的不列。历史周重生成仍使用本次生成日期，正文写明截止统计基准；同一通知有多个有效截止时，该栏目列近期最早一条。
- 公开范围沿用 `Source.rights_level == 1`；使用现有归并映射和 `available_condition` 排除整组下架。每个栏目内同一归并组只展示一次；新发布和未来截止栏目可以各收录一次。
- 发布日期或文号未提取到时写“见原文”，不声称原文没有提供。
- 截止仅使用 `approved` 核定日期、时刻，同组标记变更的相同截止不再显示。无核定截止写“截止时间见原文”。支持方式仅使用已通过、属于现有支持方式枚举、且当前正文指纹仍匹配的字段。
- 公众号版每条两行：加粗标题、机关与日期等小字信息；HTML 和对应纯文本均不放网址，HTML 不含 `a` 标签。文末固定引导微信搜索「有据」和免责声明。带链接版存入 `body_text_with_links`，详情接口返回，列表接口不返回正文；每条为“标题｜发文机关｜发布日期｜截止｜原文链接”。
- 每个栏目和省份小标题显示筛选后总条数（包括超出展示上限的部分）。各栏目国家部委最前，其余按 `youju.sources.onboard.PROVINCES` 顺序；省内新发布按日期倒序，未来截止按核定日期正序。
- 名单条数为公开归并组中已收录名称的去重条数；未解析时不显示条数。名称、信用代码、序号等明细不进入周报；小字只在标题含“公示/公布”时照录该词，不推断名单状态。
- 禁用文字只约束自写模板与方案名称；政府原标题即使含“人工智能”“智能制造”等字样也照录。公众号版展示时去除题录字段夹带的网址并将换行压成空格，带链接版保留原题录内容并压成单行。
- 各栏目总数保留，正文正文展示上限 30 条；空栏目不显示；全空不创建期刊并记录原因，重新生成全空时删除原草稿。
- 周报快照保存实际展示的文件编号。预览、复制和标已发布时再次检查实时下架与来源公开范围；失效返回 409，撤回后重生成才能继续。已发布快照不会自动改写。
- HTML 使用白名单标签、内联样式及转义数据；只接受无凭据的 HTTP(S) 原文网址。正文不调用模型，不发送到公众号或客户。

## 验证与审阅

只在指定 `youju_test_codex3` 测试库执行测试，没有操作 MySQL 服务或开发库。

在 `backend/` 目录执行：

```sh
YOUJU_TEST_DATABASE_URL="mysql+pymysql://root@127.0.0.1:33306/youju_test_codex3?charset=utf8mb4" YOUJU_REQUIRE_DB=1 UV_CACHE_DIR=/private/tmp/youju-codex-digest-uv uv run pytest -q
UV_CACHE_DIR=/private/tmp/youju-codex-digest-uv uv run ruff format .
UV_CACHE_DIR=/private/tmp/youju-codex-digest-uv uv run ruff check .
```

最终全量结果：**940 passed，1 warning，234.64 秒**；没有跳过数据库测试。周报新增 31 个测试用例，包括四栏目、公开与下架筛选、归并、字段核验、北京时间边界、方案筛选、截断、空期刊、草稿覆盖、已发布保护、并发、口令与审计、迁移往返、页面脚本复制与回退行为。Ruff 格式和静态检查通过，`git diff --check` 通过。

最终警告为既有 Starlette TestClient 的 httpx 弃用提示。之前复验中还曾观察到既有 `test_fetcher.py` 的 DNS 后台线程信号量释放警告；未改动这些模块。


根据 AGENTS.md 尝试启动独立只读审阅，工具返回 `failed to load model context / invalid thread-store request`，未产生审阅意见。尚需 Claude 独立审阅和 CI；所有改动留在工作区，不提交、不合并、不部署。

## 2026-10-04 临期提醒（每周四）

- 和周报共用方案的地区、关键词；不受栏目开关和"生成星期"影响。期刊表新增 `kind`（`weekly`/`reminder`，迁移 0016），同一方案每周每种各一份；临期提醒归入生成当天所在的自然周。
- 口径与小程序截止雷达相同：候选、公开范围、归并组、"已变更"抑制、主截止（优先企业申报截止）、当天时刻都复用 `youju.api.v1`（新抽出的 `upcoming_deadline` 由截止雷达和临期提醒共用），只收今天起 7 天内、截止日期已核对的申报通知；另外与周报一样要求主文件来自一级来源。按截止日期升序，每条写标题、发文单位、截止类型和日期（已核对）；正文展示上限 30 条。没有符合条件的项目时生成一句"本周未来 7 天没有已核对截止的申报项目"。
- 公众号版（不带网址）和带链接版（每条一行四列：标题｜发文单位｜截止｜原文链接），落款和声明与周报相同。
- CLI：`youju weekly-digest --kind reminder [--profile 名称] [--week 本周周一]`。截止按生成当天计算，只能生成本周。`--scheduled` 只在周四至周日生成，本周已有临期提醒（含已发布）的方案跳过。
- 定时：周四至周日 07:30 与周报的定时调用写在同一行，先周报后提醒（两者共用 `job.sh` 的 `weekly-digest` 任务锁，同时启动会有一个被当作重叠跳过）。
- 管理台"周报"页：选择稿件类型后生成；列表和预览标明"周报"或"临期提醒"，复制按钮相同。列表接口新增可选 `kind` 筛选，返回字段新增 `kind`；周报原有接口行为不变。
